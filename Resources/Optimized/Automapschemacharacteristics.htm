Mapping schema characteristics

Automap

From the Optimized Decision editor, once the schema has been selected, the user must map the schema characteristics to the logical characteristics in the Logical Data Source, either automatically as described here, or manually. Automap will try to match the set of schema characteristics to characteristics from the Logical Data Source. See the discussion for a more detailed description of automapping.

  The filters are a useful way to identify the characteristics that should be mapped.

To map characteristics automatically

  1. In the Optimized Decision editor, with the Optimization Inputs tab selected, click on the button to map the characteristics.
  2. The Automap Characteristics dialog is displayed, allowing you to select which of the suggested mappings to add and which to discard.
  3. Click on the Accept button. The mapped characteristics will be removed from the Schema Characteristics table, and listed in the Mapped Characteristics table.

The software checks for mapping validation errors, and displays them in the Mapped Characteristics table. See Mapping validation for a description of how mapping validation errors can be identified.

The user can unmap mapped characteristics individually, using the button, or all together using the button.

Automap characteristics: discussion

Fuzzy matching

Automap performs exact matching as well as some degree of "fuzzy" matching. For example, the following matches will be offered to the user in the Automap Characteristics dialog to either accept or decline:

Logical Name Schema Characteristic

Decision Input Data.Applicant Existing Credit Commitments

Applicant_existing_credit_commitments

Decision Input Data.Applicant Monthly Income

Applicant_monthly_income

Decision Input Data.Applicant Risk Score

Applicant_risk_score

Decision Input Data.Insurance TakeUp Rate

Insurance_TakeUp_rate

Decision Input Data.Loan Amount

LOAN_AMOUNT

Decision Input Data.PD Lifetime

PD_Lifetime

Matching arrays

Static arrays are included in the search for matches.

Alternative matches not included

The search will only return the best match for each schema characteristic, not offer alternative matches for the same schema characteristic. To find multiple matches, the user will have to map the first suggestion and then automap again. Schema characteristics will be removed from scope once mapped as they can only be mapped once.

Order in which mapping occurs

The matching algorithm will work through the Logical Data Sources in the order they are defined in the system composition manager, and through the characteristics in the order they are listed in the Logical Data Sources/Logical Data Models. Therefore the user may see better results from the fuzzy matching depending on how they define their data sources.

For example, a schema characteristic called AGE would match equally well to App Data Gen.Main.Age as to App Data Gen.Joint.Age. Therefore, if the match is equal, it will return the first match it finds. Thus, if the primary match you want to map is to the Main applicant details, then placing the Main Logical Data Model above the Joint Logical Data Model in the logical data source will produce the desired result.

Mapped characteristics selection

Mapped Characteristics - a table that shows the mapped characteristics. You can use the following buttons to map the schema characteristics to logical data characteristics:

– automatically tries to map characteristics from the set of schema characteristics to Logical Data Sources.

– allows you to map the schema characteristics to Logical Data Sources manually.

– unmaps the mapped characteristics individually.

– unmaps all mapped characteristics.

  If there are unmapped characteristics, an error icon will be displayed in the Schema Characteristics table.

The software checks for mapping validation errors, and displays them in the Mapped Characteristics table. See Mapping validation for a description of how to identify mapping validation errors.

Map schema characteristics manually

Once the Optimization Schema has been selected, the user must map the schema characteristics to the logical characteristics in the Logical Data Source, either manually as described here, or automatically. This can be done in the Optimized Decision editor, Optimization Inputs tab.

  The filters are a useful way to identify the characteristics that should be mapped.

To map characteristics manually

  1. In the Optimized Decision editor, with the Optimization Inputs tab using the Filters functionality, if necessary, identify and click on a schema characteristic, and then identify and click on the logical characteristic with which to map it. The schema characteristics are loaded automatically when the schema is selected.
  2. Click on the button to map the characteristic(s).

    3.   The mapped characteristics must be of the same type (Numeric or String). Within Numeric, you can map Integer to Integer, Float or Decimal.
     
  3. If an array element appears anywhere within the hierarchy of the selected logical characteristic, the Select Characteristic Array Element(s) dialog is displayed, enabling you to map the schema characteristic to an array element.
  4. The mapped characteristics are removed from the Schema Characteristics table and listed in the Mapped Characteristics table:

  5. You can map a group of schema characteristics to a logical characteristic.

    The software checks for mapping validation errors, and displays them in the Mapped Characteristics table. See Mapping validation for a description of how mapping validation errors can be identified.

  6. Click on Save to save the mapping.

The user can unmap the mapped characteristics individually, using the button, or all together using the button.

Mapping validation - Schema Characteristics

The validation service checks for invalid mappings and shows them in the Mapped Characteristics table. Invalid mappings will occur in the following cases:

  • When the Optimization Schema associated with the mapped schema characteristics has been removed.
  • When the associated Optimization Schema has been replaced and a previously mapped schema characteristic is no longer present in the new schema or its type has changed.
  • When a logical characteristic is deleted. In this case, the missing characteristic is shown in curly brackets.
    •   If the missing logical characteristic is re-created, you have to re-map the schema characteristic to it.
     
  • When the logical characteristic type is modified to an incompatible type.

  If the Optimization Schema is changed and the new schema contains the same schema characteristic names and types, the mapping will be preserved in the Mapped Characteristics table.
Mapping validation - Mapped Metrics

The validation service checks for invalid mappings and shows them in the Mapped Metrics table. Invalid mappings will occur in the following cases:

  • When the Optimization Schema component is cleared or changed and the new Optimization Schema does not contain the same Decision Metrics.
  • When the name of the embedded Logical Data Model is not unique within the Logical Data Source
  If the Optimization Schema is changed and the new schema contains the same decision metric names, the mapping will be preserved in the Mapped Metrics table.
