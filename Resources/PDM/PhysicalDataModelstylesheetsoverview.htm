Physical Data Model style sheets

Overview

Physical Data Models represent physical specifications of Logical Data Models/Sources for a particular interface type. When either a Byte Array or Java Object Physical Data Model is created, the data format and lengths must be defined for every characteristic held in the Logical Data Model/Source. For ease and accuracy, the user can define the default settings (the styles) for each particular interface type using style sheets. Then, when a Physical Data mModel for a particular interface type is created, the system will automatically select the data formats and lengths that have been defined in these style sheets. The user can modify the specific detail of a Physical Data Model and, if required, apply a new style sheet to an existing Physical Data Model to reset/modify the settings within it.

Two types of style sheet can be defined:

  • Byte array style sheet
  • External Object Style Sheet

Byte array style sheet

Within the byte array style sheet the user can define the default physical type settings for the:

  • Integer byte format
  • Decimal byte format
  • Float byte format
  • String byte format
  • Date byte format

For more information on the individual numeric types (integer, float, decimal) and individual string types, see Physical Data Types.

Date physical data types use both the numeric and string physical data types, see the relevant topics to obtain the required information.

Within the byte array style sheet, the user can set the default format for date. The user can choose from DDDYYYY, DDMMYY, MMDDYYYY, YYYY-MM-DD, YYYDDD, YYYYDDMM and YYYYMMDD.

In preparation for using the Cobol Copybook generator, the user can also determine how the data size for PC Floating point numbers should be calculated. If the "S390" check box is selected, the PC floating point will not be allowed and the binary formats PCBS, PCBU, MFBS and MFBU will be limited to 2, 4 or 8 bytes in length. If the "S390" check box is not selected the binary formats can be any size and the PC floating point's length will be limited to 4 or 8 bytes.

To automatically generate External Names when new characteristics are added to the Logical Data Source/Models, the "Generate external names for newly added characteristics" checkbox needs to be selected.

The radio buttons "Optimal byte size" and "8 byte size" will set the byte array size for floating point length to 4 bytes and 8 bytes respectively. Data types PCF, LEF and BEF should always be set to the "8 byte size" option. Note that the "Assume S390 Cobol for data size calculations" checkbox may also have an effect on the floating point.

The Reset to Default button enables the user to reset the settings in the style sheet to the system default.

External Object Style Sheet

Within the External Object Style Sheet, the user can define how the case of the letters used in the names of the Logical Data Source/Models should be converted.
The user can choose from:

  • None - No conversion will be made, for example, App Data Gen_Existing Customer Indicator.
  • Uppercase - All letters will be set to uppercase, for example, APP DATA GEN_EXISTING CUSTOMER INDICATOR.
  • Lowercase - All letters will be set to lowercase, for example, app data gen_existing customer indicator.
  • Swapcase - The case of each letter will be swapped, for example, aPP dATA gEN_eXISTING cUSTOMER iNDICATOR.
  • Capitalize - All words that begin with a lowercase letter will be set to uppercase, for example, App Data Gen_Existing Customer Indicator.
  • Camelcase - All words begin in uppercase and the spaces between words are removed, for example, AppDataGen_ExistingCustomerIndicator.
  • Uncapitalize - All words that begin in uppercase will be set to lowercase, for example, appdatagen_existingcustomerindicator.

In the Configure delimiters section, the user can specify how spaces and delimiters should be changed within the External Name. For full information on this, see the External Object Style Sheet editor topic.

Some Java external Logical Data Source/Model names may need to be XML tag name compliant and/or Java bean compliant.

Names need to comply with the following rules:

Java

  • Java bean compliant names may only contain alphanumeric characters plus the underscore ("_") and/or dollar sign ("$") characters.
  • Java bean compliant names may not contain spaces.

XML

  • XML compliant names contain alphanumeric characters plus the period (".") character.
  • XML compliant names may not contain spaces.
  • If XML tag name compliance is required, then check the "Ensure new external data source external names are XML tag name compliant" checkbox.

Validation checks will run to ensure that names are Java and XML compliant and a warning message is displayed if these checks fail regardless of any preference settings. If this option is left unselected, the external data source names will match the Logical Data Source/Model names exactly and may contain any characters apart from those shown below:

+ * / : % = " ' [ ] < > , \ # ? -

Edit a Byte Array style sheet

When a physical data model for a byte array is created, the user can apply this style sheet to set the data formats and lengths for the Physical Data Models. The user can edit the byte array style sheet if required.

Create a Byte Array style sheet

A byte array style sheet can be created from the Explorer window.

  You will only be able to add a component type that has been allowed for the selected folder. If it is not allowed it will not be listed and therefore cannot be selected.

To create a byte array style sheet

  1. From the Explorer window, right click at the required folder level and select Add component.
  2. Select Byte Array Style Sheet.
  3. In the Create component dialog enter the name of the Byte Array Style Sheet.
  4. Select the Open new components in component editor check box.
  5. Click on the OK button.
    The Byte Array Style sheet editor will open allowing you to amend the style sheet as required.
    The byte array style sheet name will be listed in the Explorer window under the selected folder level. The component is identified by the icon.

If you do not wish the editor to open, keep the check box de-selected. From the Explorer window right click on the byte array style sheet and select Open.

To edit a byte array style sheet

  1. With the byte array style sheet open, from the "Integer byte format" drop down box select the format that is required.
  2. From the "Decimal byte format" drop down box select the format that is required.
  3. From the "Float byte format" drop down box select the format that is required.
  4. From the "String byte format" drop down box select the format that is required.
  5. From the "Date byte format" drop down box select the format that is required.
  6. From the "Default Date Format" drop down box select the format that is required.
  7. Depending on your requirements select the "Assume S390 Cobol for data size calculations" check box.
  8. To generate the external names for newly added characteristics, ensure that the "Generate external names for newly added characteristics" check box is selected.
  9. Depending on your requirements select either the "Optimal byte size" (4 byte) or "8 byte size" radio button as the setting to be used when calculating floating point representation.

The byte array style sheet can now be applied to any byte array physical data models.

Assign a new style sheet to the Physical Data Model

When either a Byte Array or Java Object Physical Data Model is created, the data format and lengths must be defined for every characteristic held in the Logical Data Model/Source. For ease and accuracy, the default settings (the styles) for each particular interface type are set using style sheets. Then, when a Physical Data Model for a particular interface type is created, the system automatically selects the data formats and lengths that have been defined in these style sheets. The user can apply a new style sheet to an existing Physical Data Model to reset/modify the settings within it.

To assign a new style sheet to a Physical Data Model

  1. With the Physical Data Model editor open, ensure that the Physical Data Model is in sync with the Logical Data Source from which it was made by using the sync icon on the tool bar.
    All the icons on the tool bar should now be activated.
  2. Click on the Resources window and the Style Sheet list to display all the available style sheets.
    3.   The system will list the correct type of style sheets for the Physical Data Model you have open.
     
  3. Drag and drop the required style sheet onto the Physical Data Model.
    The system will display the following warning message.

    4.  
  4. Click Yes.
    The new style sheet will be assigned to the Physical Data Model and the relevant data types and lengths will be updated.

The default style sheet can be reapplied to the Physical Data Model using the default style sheet icon.

Apply the default style sheet to the Physical Data Model

When a Physical Data Model is created, the system automatically selects the data formats and default lengths that have been defined in the style sheet. If the style sheet changes or the Physical Data Model is amended and is no longer valid, the user may wish to reapply the default style sheet to the Physical Data Model.

To apply the default style sheet to the Physical Data Model

  • Within the Physical Data Model editor open, click on the default stylesheet icon to apply the style sheet to the Physical Data Model.

You can now validate the Physical Data Model.
