Working with Java Object Physical Data Models

Toolbar

The Physical Data Model editor - Java Object's Toolbar is used to alter the contents of the Physical Data Model.

Apply default style sheet - the default style of External Names will be applied to this interface, overwriting/amending previous settings.

Synchronize Physical Data Model - when the Physical Data Model no longer matches the Logical Data Source or Logical Data Model from which it was created, selecting the Synchronize Physical Data Model on the toolbar will bring the model back into line.

Create

A Java Object Physical Data Model can be created from the Explorer window from either a Logical Data Model or Logical Data Source

  You will only be able to add a component type that has been allowed for the selected folder. If it is not allowed, it will not be listed and therefore cannot be selected.

To create a Java Object Physical Data Model

  1. From the Explorer window, right click on the name of the Logical Data Model or Logical Data Source and select Add PDM followed by Java Object.
  2. In the Create component dialog, enter the name of the Java Object Physical Data Model.
  3. Select the Open new components in the component editor checkbox.
  4. Click OK.
    The Physical Data Model editor - Java Object will open allowing you to amend the model as required.
    The Java Object Physical Data Model name will be listed in the Explorer under the selected folder level. The component is identified by the icon.

If you do not wish the editor to open, keep the checkbox de-selected. From the Explorer window, right click on the Java Object Physical Data Model and select Open.

Edit

When a Physical Data Model for a Java Object is created, the system automatically generates the External Names for each characteristic using the logical name for the characteristic. The user can modify the specific detail of a Physical Data Model if required.

To edit a Java Object Physical Data Model

  1. With the Physical Data Model for a Java Object is open, you can alter the specific detail for the data model.

    2. To change the order of a characteristic in a Java Object Physical Data Model

  2. Select the row number of the characteristic you wish to move.
    A green arrow will be displayed . Drag and drop this to the position you require in the model.

    3. To change the external name of a characteristic in a Java Object Physical Data Model

  3. Select the characteristic you wish to change and update its External Name.

External Names are Optional

The External Names are Optional checkbox allows the External Names in the Java Object Physical Data Model to be blank. This option is only applicable for Call Interface related Java Object Physical Data Model intended for the Input/Output Data Definition field in a Business Process Composition. By default, this checkbox is not selected and External Names are mandatory.

  This property will only be displayed when the Hierarchical Data Model (HDM) Mode is turned on. Refer to the Best Practices Guide for more information.

To set External Names are Optional

  1. Open the required Java Object Physical Data Model.
  2. Select the External Names are Optional checkbox if you wish to leave some of the External Names to be blank.
  3. (Optional) Update the expected External Name of each characteristic.
  Ensure that there is at least one External Name specified.
  When the External Names are Optional checkbox is selected, applying an External Object Style Sheet will only format the non-empty External Names.

The Physical Data Model can now be validated.

Validate

Validate checks the Java Object Physical Data Model to ensure that it matches the Logical Data Model or Logical Data Source that it references. Valid means the component is complete, that each logical characteristic in the Logical Data Model is mapped appropriately to a physical characteristic.

To validate a Java Object Physical Data Model

  1. With the Java Object Physical Data Model editor open, click on the Validate icon .
  2. The system will check the validity of the Physical Data Model and display information on areas of the Physical Data Model that are invalid in the Validation Results window.
  3. The Description column contains details of the validation.

To fix the model, the user could reapply the default settings, select Synchronise or continue editing the Physical Data Model as required.
