External Object Style Sheet editor

The External Object Style Sheet editor enables the user to alter the default settings used by the system to automatically create Java object physical data models.

The External Object Style Sheet consists of:

  • A drop down box that enables the user to define how the names of the logical data source/models should be converted in order to be compliant with Java and whether empty spaces will be removed from the Java object names and if special characters will be allowed
  • Options to remove or replace empty spaces and delimiters
Create an External Object Style Sheet

An External Object Style Sheet can be created from the Explorer window.

  You will only be able to add a component type that has been allowed for the selected folder. If it is not allowed it will not be listed and therefore cannot be selected.

To create an External Object Style Sheet

  1. From the Explorer window, right click at the required folder level and select Add component.
  2. Select External Object Style Sheet.
  3. In the Create component dialog, enter the name of the External Object Style Sheet.
  4. Select the Open new components in component editor check box.
  5. Click on the OK button.
  • The External Object Style Sheet editor will open allowing you to amend the style sheet as required.
  • The External Object Style Sheet name will be listed in the Explorer under the selected folder level.
  • The component is identified by the icon.

If you do not wish the editor to open, leave the check box de-selected. From the Explorer window, right click on the External Object Style Sheet and select Open.

Edit an External Object Style Sheet

When a physical data model for a Java object is created, the user can apply an External Object Style Sheet to set the data formats and lengths for the physical data model. The user can edit the External Object Style Sheet if required.

To edit an External Object Style Sheet

  1. With the External Object Style Sheet open, from the Case Conversion drop down box, select the required format.
  2. Depending on your requirements, make a selection from the Remove or Replace section.
  1. Do Nothing - leaves the name as it was entered.
  2. Remove empty spaces - removes empty spaces.
  3. Remove empty spaces and the following delimiters - removes empty spaces and allows you to enter specific delimiters to be removed.
  4. Replace empty spaces with the following delimiter - allows you to enter a delimiter to replace spaces.
  5. Replace empty spaces with the following delimiter and remove the following delimiters - allows you to enter a delimiter to replace spaces and enter delimiters to be removed.
  Hover over the ? icon next to any of the above fields to see a list of the acceptable delimiters
  1. Depending on your requirements, select the "Ensure new external data source external names are XML tag name compliant" check box.
    2.  

    Java Object Physical Data Model validation rules are based on Java bean compliance naming rules. Any external name characteristic that does not follow these Java variable naming rules will prompt a warning message that is similar to the following:

    "External name is invalid. The characteristic does not follow Java variable naming rules. Name cannot start with a number."

    When the "Ensure new data source external names are xml tag name compliant" checkbox is not selected the following will be true:

    • It will allow the external name characteristic to start with a number, space and permitted special characters.
    • It will allow the external name characteristic to contain underscores _
    • The Validation error message will change to a Warning message, allowing non-Java variable names to proceed but with a caution.

The External Object Style Sheet can now be applied to any Java object physical data models.
