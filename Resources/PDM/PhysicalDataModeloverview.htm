Physical Data Models

  Although available for selection in all PowerCurve products, the Semi Structured Data Definition component is only supported in PowerCurve Strategy Management and PowerCurve Originations.
Overview

The Physical Data Models represent physical specifications of the Logical Data Models for a particular interface type. The Decision Agent interfaces currently can use two types; these are Java Byte and Java Object. The type of interface which a Physical Data Model is intended to represent determines the precise set of physical properties of the data for that environment of that model.

Logical Data Sources represent single instances of a Logical Data Model. Each Logical Data Model may be represented by many Physical Data Models and many Logical Data Sources. The user cannot select which characteristics within a Logical Data Model should be used for the Physical Data Model because the Physical Data Models represent the entire Logical Data Model.

Physical Data Models cannot be created without specifying the type of physical interface they are going to represent. As the software currently supports Java Byte and Java Object, altering the Physical Data Model editor will depend on the type the user creates.

  Dynamic data is supported, but only in the Java Object Physical Data Model where additional technical configuration will be required.

For ease and accuracy, the user can define the default settings (the styles) for each particular interface type using style sheets. Then, when a Physical Data Model for a particular interface type is created, the system will automatically select the data formats that have been defined in these style sheets. The user can modify the specific detail of a Physical Data Model if required, and, if required, apply a style sheet to an existing Physical Data Model to reset/modify the settings within it.

Physical Data Models are used by the Call Interface and are required in a deployment.

Edit a Byte Array Physical Data Model
Create

A Byte Array Physical Data Model can be created from the Explorer window from either a Logical Data Model or Logical Data Source.

  You will only be able to add a component type that has been allowed for the selected folder. If it is not allowed it will not be listed and therefore cannot be selected.
  Byte Array Physical Data Models do not support dynamic data - so all arrays in the Logical Data Source must be defined with fixed lengths.

To create a byte array physical data model

  1. From the Explorer window, right click on the name of the Logical Data Model or Logical Data Source and select Add PDM followed by Byte Array.
  2. In the Create component dialog, enter the name of the Byte Array Physical Data Model.
  3. Select the Open new components in component editor checkbox.
  4. Click OK.
    The Physical Data Model editor - Byte Array will open allowing you to amend the model as required.
    The Byte Array Physical Data Model name will be listed in the Explorer under the selected folder level. The component is identified by the icon.

If you do not wish the editor to open, keep the checkbox de-selected. From the Explorer Window, right click on the Byte Array Physical Data Model and select Open.

Edit

When a Physical Data Model for a Byte Array is created, the system automatically selects the data formats that have been defined in the Byte Array Style Sheet and automatically generates the physical names for each characteristic using the logical name for the characteristic. The user can modify the specific detail of a Physical Data Model if required.

To edit a Byte Array Physical Data Model

  1. With the Physical Data Model for a Byte Array open you can alter the specific detail for the data model.

    To change the Physical Data type for the characteristic

  2. Select the characteristic you require, then in the Physical Type column, from the drop down list select the type you require.

    For more information on the individual numeric types (integer, float, decimal) see the topic Numeric Physical Data Types for more information on the individual string types see the topic String Physical Data Types .

    To recalculate the offsets for all the characteristics

  3. Click on the following icon

    To recalculate the length of all the characteristics

  4. Click on the following icon

    To recalculate the length and offset for all characteristics

  5. Click on the following icon

    To change the order of a characteristic

  6. Select the row number of the characteristic you wish to move.
    A green arrow will be displayed . Drag and drop this to the position you require in the model.

The Physical Data Model can now be validated.

Validate

Validate checks the Byte Array Physical Data Model to ensure that it matches the Logical Data Model or Logical Data Source that it references. Valid means the component is complete, that each logical characteristic in the Logical Data Model is mapped appropriately to a physical characteristic.

To validate a Byte Array Physical Data Model

  1. With the Byte Array Physical Data Model editor open, click on the Validate icon
  2. The system will check the validity of the Physical Data Model and display information on areas of the Physical Data Model that are invalid in the Validation Results window.
  3. The Description column contains details of the validation.

To fix the model, the user could reapply the default settings, select Synchronise or continue editing the Physical Data Model.

Edit a Java Object Physical Data Model
Create

A Java Object Physical Data Model can be created from the Explorer window from either a Logical Data Model or Logical Data Source

  You will only be able to add a component type that has been allowed for the selected folder. If it is not allowed, it will not be listed and therefore cannot be selected.

To create a Java Object Physical Data Model

  1. From the Explorer window, right click on the name of the Logical Data Model or Logical Data Source and select Add PDM followed by Java Object.
  2. In the Create component dialog, enter the name of the Java Object Physical Data Model.
  3. Select the Open new components in the component editor checkbox.
  4. Click OK.
    The Physical Data Model editor - Java Object will open allowing you to amend the model as required.
    The Java Object Physical Data Model name will be listed in the Explorer under the selected folder level. The component is identified by the icon.

If you do not wish the editor to open, keep the checkbox de-selected. From the Explorer window, right click on the Java Object Physical Data Model and select Open.

Edit

When a Physical Data Model for a Java Object is created, the system automatically generates the External Names for each characteristic using the logical name for the characteristic. The user can modify the specific detail of a Physical Data Model if required.

  If a Semi Structured Data Definition data type exists in the Logical Data Model or Logical Data Source, because the physical representation of a Semi Structured Data Definition is a single JSON string, only a single entry will be automatically generated in the Physical Data Model rather than the nested characteristics.
The length of the Semi Structured Data Definition is not displayed in the editor (-) however, it will be considered as an integer.max value (2,147,483,647).

To edit a Java Object Physical Data Model

  1. With the Physical Data Model for a Java Object is open, you can alter the specific detail for the data model.

    2. To change the order of a characteristic in a Java Object Physical Data Model

  2. Select the row number of the characteristic you wish to move.
    A green arrow will be displayed . Drag and drop this to the position you require in the model.

    3. To change the external name of a characteristic in a Java Object Physical Data Model

  3. Select the characteristic you wish to change and update its External Name.

External Names are Optional

The External Names are Optional checkbox allows the External Names in the Java Object Physical Data Model to be blank. This option is only applicable for Call Interface related Java Object Physical Data Model intended for the Input/Output Data Definition field in a Business Process Composition. By default, this checkbox is not selected and External Names are mandatory.

  This property will only be displayed when the Hierarchical Data Model (HDM) Mode is turned on. Refer to the Best Practices Guide for more information.

To set External Names are Optional

  1. Open the required Java Object Physical Data Model.
  2. Select the External Names are Optional checkbox if you wish to leave some of the External Names to be blank.
  3. (Optional) Update the expected External Name of each characteristic.
  Ensure that there is at least one External Name specified.
  When the External Names are Optional checkbox is selected, applying an External Object Style Sheet will only format the non-empty External Names.

The Physical Data Model can now be validated.

Validate

Validate checks the Java Object Physical Data Model to ensure that it matches the Logical Data Model or Logical Data Source that it references. Valid means the component is complete, that each logical characteristic in the Logical Data Model is mapped appropriately to a physical characteristic.

To validate a Java Object Physical Data Model

  1. With the Java Object Physical Data Model editor open, click on the Validate icon .
  2. The system will check the validity of the Physical Data Model and display information on areas of the Physical Data Model that are invalid in the Validation Results window.
  3. The Description column contains details of the validation.

To fix the model, the user could reapply the default settings, select Synchronise or continue editing the Physical Data Model as required.

Edit an embedded or referenced Physical Data Model

Physical Data Models are created from either a Logical Data Model or a Logical Data Source. When a Physical Data Model is created from a Logical Data Source/Model that contains embedded or referenced Logical Data Models (subordinate Logical Data Models), the Physical Data Model for these subordinate Logical Data Models will be created when the original physical data source is created. These subordinate Physical Data Models can be accessed from within the source Physical Data Model.

To edit an embedded or referenced Physical Data Model

  1. With the Physical Data Model open, right click on the name of the referenced or embedded Logical Data Model and select Open Subordinate PDM.

    The standard editor for an embedded component will open for the Logical Data Model.
  2. Edit the subordinate Physical Data Model as required.
  3. Once you have finished amending the Physical Data Model, select the Close Internal Editor button.
    The embedded/referenced Physical Data Model will close.

Continue amending the Physical Data Model as required.

Synchronise a Physical Data Model

A Physical Data Model is created from either a Logical Data Model or Logical Data Source. If the Logical Data Model or Logical Data Source changes, the Physical Data Model will no longer match the Logical Data Model. When an out of synch Physical Data Model is opened, the system will provide details in the Physical Data Model editor of the problem and identify with an icon the characteristic(s) that have been changed. Moving the cursor over the icon will provide the user with a tooltip describing the changes as displayed in the example below.



 

The Physical Data Model will be automatically updated if the name, size, scale or array size is updated when the Logical Data Model or Logical Data Source is saved.
 

The Synchronize icon will become activated if a characteristic is added or deleted and the affected characteristics will be marked with icons in the Physical Data Model editor.
