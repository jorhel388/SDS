Acquisition Cross Tabulation Report (ACT)

The Acquisition Cross Tabulation (ACT) report is a generic report that provides an overview of customer acquisition by two segmentation characteristics allowing the user to choose measures relating to the acquisition decision.

The report allows the user to choose a single characteristic to produce row segmentation for the portfolio based on the analysis period. A single characteristic can then be chosen to produce column segmentation at the same period in time.

A number of measures can then be reported on for these segments either at the same or by defining an outcome length a later point in time.

The standard acquisition filters (inclusion, exclusion) and slicing functionality is also available.

To create an Acquisition Cross Tabulation (ACT) report, the user needs to configure the following tabs in the report editor

Analysis Period tab

The Analysis Period tab determines the time span the report covers. This report style will show results for the whole analysis period (e.g., a 6 month period).

The user can configure the analysis period by specifying a reference date and an analysis time length. This sets the analysis period as the specified analysis time length before the analysis reference date.

Within the Analysis Reference Data, the user can choose to set one of the following to be the reference date:

  • a user defined date
  • the current server date
  • a date that is offset from the current server date.
    •   When you select the offset server date, you can handle any data latency issues that arise from delays in data being generated and being loaded to the reporting's data mart.

Within the Analysis Time Period Length, the user can:

  • select the time interval using the drop down (day, month, quarter)
  • the number of intervals using the slider

This specifies the length of the analysis period.

Configure the Analysis Period tab

The Analysis Period tab determines the time span the report covers. The user can configure the analysis period by specifying a reference date and an analysis time length. This sets the analysis period as the specified analysis time length before the analysis reference date.

To configure the analysis period tab

  1. With the Report Definition editor open and the Analysis Period tab selected in the Analysis Reference Date section, select the required radio button from the available date controls.
  2. Use the calendar date picker to specify a reference date.
  3. Use the Server Date radio button to select the current server date as a reference date.
  4. Use the Offset Server Date radio button to select a reference date offset from the current server date.
  5. To configure the offset date, select the required time unit from the drop down menu and the value slider. These controls specify the number of days, weeks, months or quarters before the current server date.
    6.   When you select the Offset Server Date, you can handle any data latency issues that arise from delays in data being generated and being loaded to the reporting's data mart.
  1. In the Analysis Time Period Length section, select the analysis time period length.
  2. Select the required time unit from the drop down menu and the value slider. These controls specify the number of days, months or quarters and the duration of the analysis time period.
    3.   If month or quarter is selected, the analysis time period spans to the end of the last matching time period before the reference date. For example, if you select the analysis time length as 3 months and January 4th, 2009 as the analysis reference date - the actual analysis time period is from October 1st, 2008 to December 31st 2008 inclusive.
Population Definition tab

The Population Definition tab determines the database records that the report covers. The available controls include:

  • Inclusion and/or exclusion filters – controls which records to include or exclude from the population of interest.
  • Scorecard – allows the user to only report on records which went through a specific scorecard.
Report Description tab

The Report Description tab is an optional entry the user can use to enter extra information for the report. The report description appears in the report output header and serves as reference on the report's purpose and scope.

A maximum of 200 characters can be entered into the Report Description area.

Add a Report description

Within the Report Definition editor you can define an optional description for the Report using the Report Description Tab. The report description appears in the report output header and serves as reference on the report's purpose and scope.

To add a report description

  1. With the Report Definition editor open and the Report Description tab selected enter your description in the Report Description field.

You can enter up to 200 characters.

Population Segmentation tab

The Population Segmentation tab allows the user to define the rows and columns and slicing on the output report.

The available controls include:

  • Row segmentation - controls the rows on the reports (how the population is segmented).
  • Column segmentation - controls the columns on the reports (how the population is segmented).
  • Slicing segmentation - controls whether sub-reports should be created for each value of the slicing characteristic/class set.

The user is presented with a preview of the report output in the editor. The information is displayed below the report’s tab and above the Output window. When a class set is chosen for segmentation the class-set interval names are shown.

Configure Population Segmentation

In the Population Segmentation tab, there are two ways to configure the segmentation or slicing section. They are:

  • Referenced class set
  • Referenced logical data source.

As the steps to configure a segmentation or slicing characteristics are similar, the following example is for segmentation.

To configure segmentation characteristics using a referenced class set

  1. In the Segmentation Characteristic section, select the Class Set radio button.
  2. Drag the desired class set from the Resources window and drop it in the Class Set field.
    3.   You can view the details of the referenced class set you select when you double-click on the Class Set field. The Class set editor is then displayed. You can also edit the referenced class set. For more information on editing the class set, please refer to Edit Reference or Embedded Filters.

To configure segmentation characteristic using a referenced Logical Data Source characteristic

  1. In the Segmentation Characteristic section, select the LDS Characteristic radio button .
  2. Drag the desired logical data source from the Resources window and drop it in the LDS Characteristic field.
  3. The characteristic chooser is displayed, allowing you to choose the characteristic from the selected logical data source.
  4. Click on the OK button after you have selected the logical data source.
Measure Selection tab

The Measures Selection tab allows the user to specify and configure the formatting for the measures they would like to be included on the report. A measure is a piece of information that the user wants to see on the output report (split by the time periods within the analysis period they have selected). The Measures Selection tab contains a table which has one row for each measure the user wishes to be included. Each measure specified will add either an extra row or an extra column to the output report (depending on the report template) and an extra graph.

Add a Measure to a report

In the Measure Selection tab, the user can add a minimum of 1 measure and a maximum of 10 measures.

  Your report must contain at least one measure.

To add a measure to a report

  1. With the Measure Selection tab open, in the Measure Selection table, drag the desired measure from the Resources window and drop it in the first column of a row of the Measure Selection table.
  2. Configure the customisable columns of the corresponding Measure Selection table row.
  3. To add another measure, right click on the Measure Selection table and select Add Row.
  4. Repeat step 1 to add another measure to the row of the report.
    5.   You can also use the Insert Row function to add another measure. When you use Add Row, a measure is added at the last position of a measure record where as when you use Insert Row, a measure is added between two existing measure records.

The Measures that you have added will be used in the report.

Remove a Measure from a report

The Measures Selection tab allows the user to specify and configure the formatting for the Measures they would like to be included on a report.

To remove a measure from a report

  1. With the Measure Selection tab open, select the Measure, right click and select Delete Row.

The Measure will be removed.

  Your report must contain at least one Measure.

For more information on measures see the Create Measures help topic.

The Measures table has the following columns:

  • Measure - This column shows the name of the corresponding measure component.
  • Type - This column shows the type of the corresponding measure component (Average, Count, Max, Min, etc.)
  • Calculation - This column allows the user to select the calculation type of the corresponding measure. The measure type determines which calculation types are available.
    •   Derived Measure use the treat as type to control the calculation types available. Thus Derived Sum is treated as a Sum type measure.

  • Calculate Over - This drop-down menu allows the user to select the dimension over which the measures are calculated. The user will only need to specify this field for cross-tabulation, advanced management and summary trend type reports.
  • Scaling - This field allows the user to enter a scaling parameters for the calculated report measure results (for example, thousands if the values are too large).
  • Units - This field allows the user to customise the report by entering a defined unit. The user can use this field to define currency symbols (for example, EUR'). The calculation type and scaling will auto-populate this field, but the user can edit the value. The value entered will impact the starting display name
  • Graph - This column allows the user to select the style of the report chart. One chart is produced for each measure the user select. For Index Odds measures, the user's selection for the graph type will be ignored (as no graph will be produced at all).
    •   Currently, only two types of chart are produced. This consists of the simple bar and line charts.
  • Precision - This field allows the user to enter the desired precision for the calculated report measure results.
  • Display Name - This option allows the user to enter a custom name that is displayed in the report output for the corresponding measure. The starting value will be based on the measure component type and the other selections in the table. The display name should be unique for each measure in the table. So even if the same measure is referenced multiple times, the display name should be edited to make each one unique. The display name will be shown as this heading and graph title in the output report.

The following example illustrates how the Accumulation Up calculation is applied in the Acquisition Trend report.

 

Your report spans from January to December and measures the number of applications over time. The total number of applications from January to December is 50 000

In 'accumulation up' mode - the value of the December column is equal to the total number of applications (50 000). The value of the January column is the actual number of applications for that month. The value of the February column is the number of applications submitted in January plus the number of applications submitted for February.

The accumulation up finishes in December where the value of the column is the sum of the number of applications submitted from January to December (50 000).

The following example illustrates how the Accumulation Down calculation is applied in the Acquisition Trend report.

 

Your report spans from January to December and measures the number of applications over time. The total number of applications from January to December is 50 000

In 'accumulation down' mode - the value of the January column is equal to the total number of applications (50 000). The value of the February column is 50 000 minus the number of applications submitted in January. The value of the March column is 50 000 minus the number of applications submitted in January and February.

The accumulation down finishes in December where the value of the column is the number of applications submitted in December.
Configuration tab

The Configuration tab is used to reference a Report Configuration component.

Report Configuration: References the Report Configuration component from the Resources window.

Report Output Folder: The default output folder for all reports using this report configuration can be changed on the Mart tab of the Report Configuration component. On this screen, the user can choose to follow the default output folder as specified in the Report Configuration, or click Browse to display the Reporting Repository Browser dialog, and select an output folder for this specific report.

Configure Configuration tab

Within the Report Definition editor you can reference a Report Configuration component using the Configuration tab.

To reference a Report Configuration

  1. With the Report Definition editor open and the Configuration tab selected, from the Resources window drag and drop the report configuration onto the Report Configuration field.

You can double click on the Report Configuration to open the selected Report Configuration component editor.
