Customer Management Report Templates

Reports are created by the user selecting a Report Template from those available in the solution and then configuring the template using a set of parameters to create a report definition. Additional templates may be developed in later software releases, and hence the range of available templates will grow over time.

Select a Report Template

When the user creates a report definition, they have to select the report template type to determine the report that needs to be produced.

The user will then need to set up the relevant configuration for the report definition.

To select a report template

  1. From the Report Template chooser, select the required template type from the Available Reports section.
  2. Click on the Expand (+) button to display the list of available report templates.
  3. Select the report template you want to configure.
  4. Click the Load button to load the report.

You can now configure the report definition.

Customer Management Advanced Management report (CMAM)

The Customer Management Advanced Management (CMAM) report is a generic report that allows the account portfolio to be assessed at a point in time.

The report allows the user to choose a primary and secondary characteristic to segment the portfolio by at a period in time (analysis period).

Multiple measures can then be reported on for these segments either at the same or a different point in time by specifying an outcome length.

The standard account management filters (inclusion, exclusion) and slicing functionality are also available. These parameters are calculated at the population reference date.

 

The following business example illustrates how the Customer Management Advanced Management report could be used:

In the Asia Pacific region, ABank Ltd is a credit card issuer with branches in Indonesia, Malaysia, Singapore and Thailand. ABank uses the Customer Management Advanced Management report to monitor the following:

1. Average outstanding balance, broken down by country and card type (e.g. Master/Visa/Amex etc).

2. After implementing a strategy of selectively increasing credit limits using a champion-challenger approach, ABank might use this report to see the limits, outstanding balance and utilisation rates for those accounts, broken down by strategy (i.e. champion/challenger) as well as card type.

To create a Customer Management Advanced Management (CMAM) report, the user needs to configure the following tabs in the report editor

Analysis Period tab

The Analysis Period tab determines the time span the report covers. This report style will show results for the whole analysis period (e.g., a 6 month period).

The user can configure the analysis period by specifying a reference date and an analysis time length. This sets the analysis period as the specified analysis time length before the analysis reference date.

Within the Analysis Reference Data, the user can choose to set one of the following to be the reference date:

  • a user defined date
  • the current server date
  • a date that is offset from the current server date.
    •   When you select the offset server date, you can handle any data latency issues that arise from delays in data being generated and being loaded to the reporting's data mart.

Within the Analysis Time Period Length, the user can:

  • select the time interval using the drop down (day, month, quarter)
  • the number of intervals using the slider

This specifies the length of the analysis period.

Configure the Analysis Period tab

The Analysis Period tab determines the time span the report covers. The user can configure the analysis period by specifying a reference date and an analysis time length. This sets the analysis period as the specified analysis time length before the analysis reference date.

To configure the analysis period tab

  1. With the Report Definition editor open and the Analysis Period tab selected in the Analysis Reference Date section, select the required radio button from the available date controls.
  2. Use the calendar date picker to specify a reference date.
  3. Use the Server Date radio button to select the current server date as a reference date.
  4. Use the Offset Server Date radio button to select a reference date offset from the current server date.
  5. To configure the offset date, select the required time unit from the drop down menu and the value slider. These controls specify the number of days, weeks, months or quarters before the current server date.
    6.   When you select the offset server date, you can handle any data latency issues that arise from delays in data being generated and being loaded to the reporting's data mart.
  1. In the Analysis Time Period Length section, select the analysis time period length.
  2. Select the required time unit from the drop down menu and the value slider. These controls specify the number of days, months or quarters and the duration of the analysis time period.
     If month or quarter is selected, the analysis time period spans to the end of the last matching time period before the reference date. For example, if you select the analysis time length as 3 months and January 4th, 2009 as the analysis reference date - the actual analysis time period is from October 1st, 2008 to December 31st 2008 inclusive.
Population Definition tab

The Population Definition tab determines the database records that the report covers. The available controls include:

  • Inclusion and/or exclusion filters – controls which records to include or exclude from the population of interest.
  • Scorecard mapping – allows the user to map observation characteristics on the benchmark sample with the equivalent field from the operational data held in the reporting data mart.
Report Description tab

The Report Description tab is an optional entry the user can use to enter extra information for the report. The report description appears in the report output header and serves as reference on the report's purpose and scope.

The user can remove a parameter such as a filter or scorecard from the report definition.

Measures Selection tab

The measures selection tab allows the user to specify and configure the formatting for the measures they would like to be included on the report. A measure is a piece of information that the user wants to see on the output report (split by the time periods within the analysis period they have selected). The measures tab contains a table which has one row for each measure the user wishes to be included. Each measure specified will add either an extra row or an extra column to the output report (depending on the report template) and an extra graph.

Add a Measure to a report

In the Measure Selection tab, the user can add a minimum of 1 measure; the maximum number of measures depends on the report template.

  Your report must contain at least one measure.

To add a measure to a report

  1. With the Measure Selection tab open, in the Measure Selection table, drag the desired measure from the Resources window and drop it in the first column of a row of the Measure Selection table.
  2. Configure the customisable columns of the corresponding Measure Selection table row.
  3. To add another measure, right click on the Measure Selection table and select Add Row.
  4. Repeat step 1 to add another measure to the row of the report.
    5.   You can also use the Insert Row function to add another measure. When you use Add Row, a measure is added at the last position of a measure record where as when you use Insert Row, a measure is added between two existing measure records.

The measures that you have added will be used in the report.

Remove a measure from a report

The measures tab allows the user to specify and configure the formatting for the measures they would like to be included on a report.

To remove a measure from a report

  1. With the Measure Selection tab open, select the measure, right click and select Delete Row.

The measure will be removed.

  Your report must contain at least one measure.

For more information on measures see the Create a measure help topic.

Customer Management Cross Tabulation report (CMCT)

The Customer Management Cross Tabulation (CMCT) report is a generic report that allows the account portfolio to be assessed at a point in time.

The report allows the user to choose a single characteristic to produce row segmentation for the portfolio, and a single characteristic to produce column segmentation, at a period in time. A number of measures can then be reported on for these segments. Each measure is shown as a separate table on the output.

 

The following business example illustrates how the Customer Management Cross Tabulation report could be used:

In the Asia Pacific region, ABank Ltd has branches in Indonesia, Malaysia, Singapore and Thailand. ABank uses the Customer Management Cross Tabulation (CMCT) reports for ad-hoc analysis to monitor the following:

1. Number of accounts by delinquency status and balance bands

2. Number of accounts by score band and test group

To create a Customer Management Cross Tabulation (CMCT) report, the user needs to configure the following tabs in the report editor

Analysis Period tab

The Analysis Period tab determines the time span the report covers. This report style will show results split by time interval (e.g.; showing results for each month in the analysis period).

For customer management reports multiple updates per customer/account may be included in each time interval population when the analysis period interval is greater than the update frequency. So if my analysis period is the 3 months from 1st Jan 2010 to 31st March 2010 and my data is updated on a monthly basis, three time period intervals will be reported on (Jan 2010, February 20101 and March 20101). Each account/customer may therefore appear in each time period (each time the last dated performance update in the time period interval will be used). It is advisable to select the analysis period interval to match the frequency of updates.

  Any account/customer with a closed or write-off date before the start of the analysis period will be excluded from the population. This test will apply for each period in the trend report, so an account that was closed in the first month would be in the population for the first month, but missing from the remaining months in the analysis period

The report allows the user to choose a characteristic to segment the portfolio by at a period in time (analysis/population reference date).

Multiple population measures (based on the population reference date) can then be reported on over the time periods.

The standard account management filters (inclusion, exclusion) and slicing functionality are also available. These parameters are calculated at the population reference date.

 

The following business example illustrates how the CM Management (CMM) report could be used:

In the Asia Pacific region, ABank Ltd has branches in Indonesia, Malaysia, Singapore and Thailand. ABank uses the CM Management (CMM) reports for ad-hoc analysis to monitor the following:

1. Average balance, average credit limit by score-band

2. Number of accounts, average balance and total exposure by delinquency status

Customer Management Movement Matrix report (CMMM)

The Customer Management Movement Matrix (CMMM) report is a generic report that allows movements in the account portfolio to be assessed between two points in time.

Typically the report might be used to produce a roll rate report where the exact movement of customers/accounts by delinquency status (or risk grade) is shown by comparing one time period with the following.

The report allows the user to choose a characteristic to produce row segmentation for the portfolio at a specific period in time (analysis time period). The same characteristic is then used to produce column segmentation at a later period in time (outcome time period).

Up to 10 measures can then be reported on for these segments using values from the analysis time period. The row and column percentages for the measure are also calculated and displayed. All the measures use the same outcome length to derive the outcome time period which is used to assign the column segmentation.

The standard account management filters (inclusion, exclusion) and slicing functionality is also available, these are also applied using the analysis time period.

The report is similar to the Customer Management Cross-tabulation report but enables a dynamic delinquency (roll-rate) type of report to be produced more easily.

 

The following business example illustrates how the Customer Management Movement Matrix report could be used:

In the Asia Pacific region, ABank Ltd is a credit card issuer with branches in Indonesia, Malaysia, Singapore and Thailand. ABank uses the Customer Management Movement Matrix report to monitor the following:

1. Number of accounts and total outstanding balance, broken down by risk score band.

2. Number of accounts, total credit limit and total outstanding balance, broken down by delinquency bucket.

Customer Management Population Stability Trend report (CMPST)

The Customer Management Population Stability Trend (CMPST) report provides the user with a high level assessment of whether the customer/account population is stable. In this report, the score distributions (or other segmentation characteristics) of the population are compared over a period of time. This analysis will then allow the user to observe the score distribution's trend which could indicate whether the population is becoming lower or higher risk.

For example, there may be small differences between consecutive months when the proportion in the lowest score band increases from 10% to 11%. But, if this trend occurs each month, a clear trend over time can be observed. This trend will then imply that the population is shifting in a clear direction (for example, becoming higher risk) and appropriate strategies can be taken (for example, plan to rebuild or reweight the behavioural scorecard).

This report also allows the user to observe the change in distribution of any classed variable (or an unclassed variable with up to 100 discrete values).

 

The following business example illustrates how the Customer Management Population Stability Trend (CMPST) report is used:

In the Asia Pacific region, ABank Ltd has branches in Indonesia, Malaysia, Singapore and Thailand. For their credit card line management decision making, they have been using their "SC_CC_Account" scorecard, purchased from a third party vendor in 2006. This scorecard consists only two class sets, "CS_AgeAccount" and "CS_WorstStatus".

The Customer Management Population Stability Trend (CMPST) report displays whether the distribution of accounts running through a given scorecard is changing over time. This can be assessed through the scorecard’s inputs (for example, the age and worst status of the accounts) or through the scorecard’s output (that is, the score).

ABank scheduled the Customer Management Population Stability Trend (CMPST) reports for its scorecard, showing the trend over the last twelve months. In fact, this report showed that scores for their "SC_CC_Account" scorecard were gradually improving. This prompted ABank to run an ad-hoc Customer Management Population Stability Trend (CMPST) report on both class sets in that scorecard. They found the account ages were quite stable but the worst status trend was moving upwards (generally better worst statuses). This triggered the development of the new "SC_CC_Account_New" scorecard.

Gini Statistic

  • The Gini coefficient is a measure of the power of a scorecard
  • The higher the Gini the stronger the discrimination of the scorecard
  • A scorecard with no discrimination would have a Gini of zero; a perfect scorecard would have a Gini of 100
  • A Gini is calculated by comparing the cumulative descending proportion of Goods and Bads by score
  • Missing score values are not included (however this means that the proportions being used should be calculated excluding null/missing values – i.e. the remaining proportions sum to 100%)
  • Gini is based on a graphical representation of the distribution of bads and good accounts by showing the proportion of bad accounts above a score cut-off versus the proportion of good accounts above the same score cut-off
  • If no difference in distribution (Gini =0) then curve lies along the diagonal, if perfect discrimination (Gini =100) then curve is in bottom corner
  • The larger the area between the curve and the diagonal, the better the discrimination.
  • Gini is defined as:
    • = (area between curve and diagonal)/area of lower triangle

    • = 2 * (area beneath diagonal – area beneath curve)

Analysis Period tab

The Analysis Period tab determines the time span the report covers. This report style will show results split by time interval (e.g.; showing results for each month in the analysis period).

For customer management reports multiple updates per customer/account may be included in each time interval population when the analysis period interval is greater than the update frequency. So if my analysis period is the 3 months from 1st Jan 2010 to 31st March 2010 and my data is updated on a monthly basis, three time period intervals will be reported on (Jan 2010, February 20101 and March 20101). Each account/customer may therefore appear in each time period (each time the last dated performance update in the time period interval will be used). It is advisable to select the analysis period interval to match the frequency of updates.

  Any account/customer with a closed or write-off date before the start of the analysis period will be excluded from the population. This test will apply for each period in the trend report, so an account that was closed in the first month would be in the population for the first month, but missing from the remaining months in the analysis period
