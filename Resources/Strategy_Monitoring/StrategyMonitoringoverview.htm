Strategy Monitoring overview

Strategy Monitoring allows the user to report on their operational strategies using report definitions configured from templates. The set of templates will expand over time and should cover the best practice requirements for Strategy Monitoring across different geographies and vertical markets (industry sectors). By using best practice templates, users can quickly define reports that will assist them in checking the quality of their strategy decisions and ensuring that their business expectations are met. The business user can then ensure that their analytical resource is targeted at the appropriate area of concern.

Strategy Monitoring Data

Strategy monitoring requires a reporting data mart (analytical data mart) to be created and updated on a regular basis with relevant data from the user's operational environment. The data mart can be stored on one of the supported SQL database platforms. The reporting data mart will be configured to support the reports required and the data available in the user's environment. Typically this data will include:

  • Observation data from when decisions are made (e.g., application form, bureau)
  • Monitoring data captured from processes within the decision agent
  • Results from the decisions (e.g., account set up information)
  • Ongoing account performance data (e.g., summary monthly updates of account transactions)
Strategy Monitoring components

Strategy monitoring will re-use common components stored in the common repository. In addition it will also require some reporting specific components including:

  • Reports
  • Report Configuration
  • Report Scorecard Mapping
  • Report Sets
  • Report Output

These are described more fully under the relevant topics.

Report parameter controls

Reports are defined by a set of parameter controls which vary depending on the report template selected. The parameters are set within the appropriate tabs in the Report Definition editor. The following is a list of the possible report parameter controls:

  • Inclusion and Exclusion filters
  • Scorecards
  • Test Groups
  • Segmentation Characteristic
  • Slicing Characteristic
  • Remove a parameter from a Report Definition
  • Report Scorecard Mapping
Submit a Report

After a report definition is configured and validated, the user can submit the report for execution by the Job Submission Console.

  Only users with the report submission permission can submit a report.

There are three ways to submit a report definition:

  • Submit the report definition from the Report Definition editor.
  • Submit the report definition from the Explorer window.
  • Submit a batch of reports after creating a report set.
Report Output

When a report definition is submitted it is sent to the Job Submission framework for execution. Assuming no errors are encountered, each report submission will create a Report Output component which will be stored in the reporting repository.

The Report Output is a read-only component which shows the report (tables and graphs) based on the data in the reporting data mart when the report was executed. The Report Output also holds log information, the parameters used and details of the SQL executed to create the report.

  The folder containing the report output is specified in the report set/report definition or report configuration (depending on what the user has specified).
Report Templates

Reports are created by the user selecting a Report Template from those available in the solution and then configuring the template using a set of parameters to create a report definition. Additional templates may be developed in later software releases, and hence the range of available templates will grow over time.
