Acquisition Scorecard Discrimination report (ASD)

The Acquisition Scorecard Discrimination report allows the user to monitor the predictive power of a segmentation characteristic. The segmentation characteristic is usually a scorecard score-band. A fixed group of measures are required for the report including a good and bad outcome measures. The predictive power of the segmentation characteristic is then calculated using a KS test and Gini statistic on the cumulative distributions.

 

The following business example illustrates how the Acquisition Scorecard Discrimination (ASD) report is used:

ABank Ltd uses the Acquisition Scorecard Discrimination (ASD) report to see how effective the acquisition scorecard is at predicting delinquency over a 12 month outcome. This allows both the score cut-off to be assessed and terms of business to be determined or opened for accounts.

To create an Acquisition Scorecard Discrimination (ASD) report, the user needs to configure the following tabs in the report editor:

Analysis Period tab

The Analysis Period tab determines the time span the report covers. This report style shows results for the whole analysis period (e.g., a 6 month period).

The user can configure the analysis period by specifying a reference date and an analysis time length. This sets the analysis period as the specified analysis time length before the analysis reference date.

Within the Analysis Reference Data, the user can choose to set one of the following to be the reference date:

  • a user defined date
  • the current server date
  • a date that is offset from the current server date
    •   When the user selects the offset server date, the user can handle any data latency issues that arise from delays in data being generated and being loaded to the reporting's data mart.
    This report style also requires performance outcome to be available on opened accounts, so typically the analysis reference date will be historic (e.g. to assess an outcome length of 9 months, the analysis period must be from at least 9 months previously).

Within the Analysis Time Period Length, the user can:

  • select the time interval using the drop down (day, month, quarter)
  • the number of intervals using the slider

This specifies the length of the analysis period.

Population Definition tab

The Population Definition tab determines the database records that the report covers. The available controls include:

  • Inclusion and/or exclusion filters – controls which records to include or exclude from the population of interest.
  • Scorecard – allows the user to only report on records which went through a specific scorecard.
Report Description tab

The Report Description tab is an optional entry the user can use to enter extra information for the report. The report description appears in the report output header and serves as reference on the report's purpose and scope.

A maximum of 200 characters can be entered into the Report Description area.

Add a report description

Within the Report Definition editor you can define an optional description for the Report using the Report Description Tab. The report description appears in the report output header and serves as reference on the report's purpose and scope.

To add a report description

  1. With the Report Definition editor open and the Report Description tab selected enter your description in the Report Description field.

You can enter up to 200 characters.

Population Segmentation tab

The population segmentation tab allows the user to define the row and slicing on the output report. 

The available controls include:

  • Segmentation  - controls the rows on the reports (how the population is segmented).
  • Slicing segmentation – controls whether sub-reports should be created for each value of the slicing characteristic/class-set.

The user is presented with a preview of the report output in the editor. The information is displayed below the report’s tab and above the Output window. When a class set is chosen for segmentation the class-set interval names are shown.

  The segmentation characteristic is assessed for predictive power using a KS test and Gini statistic – these use cumulative distributions which would only be valid if the segmentation values have a ordered nature (like consecutive increasing/decreasing score-bands). The table of results can still be used to assess bad rate by segmentation interval for any characteristic (e.g. residential status).

Gini Statistic

  • The Gini coefficient is a measure of the power of a scorecard
  • The higher the Gini the stronger the discrimination of the scorecard
  • A scorecard with no discrimination would have a Gini of zero; a perfect scorecard would have a Gini of 100
  • A Gini is calculated by comparing the cumulative descending proportion of Goods and Bads by score
  • Missing score values are not included (however this means that the proportions being used should be calculated excluding null/missing values – i.e. the remaining proportions sum to 100%)
  • Gini is based on a graphical representation of the distribution of bads and good accounts by showing the proportion of bad accounts above a score cut-off versus the proportion of good accounts above the same score cut-off
  • If no difference in distribution (Gini =0) then curve lies along the diagonal, if perfect discrimination (Gini =100) then curve is in bottom corner
  • The larger the area between the curve and the diagonal, the better the discrimination.
  • Gini is defined as:
    • = (area between curve and diagonal)/area of lower triangle
    • = 2 * (area between curve and diagonal)
    • = 2 * (area beneath diagonal – area beneath curve)
    • = 2 * (0.5 - area beneath curve)
    • = 1 – 2 * area beneath curve

Measures Selection tab

The measures selection tab allows the user to specify and configure the formatting for the measures they would like to be included on the report. A measure is a piece of information that the user wants to see on the output report (split by the time periods within the analysis period they have selected). The measures tab contains a table which has one row for each measure the user wishes to be included.

Add a Measure to a report

In the Measure Selection tab, the user can specify the require measures.

  Your report must contain at least one measure.

To add a measure to a report

  1. With the Measure Selection tab open in the Measure Selection table, drag the desired measure from the Resources window and drop it in the second column of a row of the Measure Selection table.
  2. Configure the customisable columns of the corresponding Measure Selection table row.
  3. Repeat step 1 to add another measure to the row of the report.

The measures that you have added will be used in the report.

Remove a measure from a report

The measures tab allows the user to specify and configure the formatting for the measures they would like to be included on a report.

To remove a measure from a report

  1. With the Measure Selection tab open, select the measure, right click and select Delete Row.

The measure will be removed.

For more information on measures see the Create a measure help topic.

The measures table has the following columns:

  • Measure Business Type - this is the business concept required for the measure - the calculations in the report assume a specific set of measures are included
  • Measure - This column shows the name of the corresponding measure component.
  • Type - This column shows the type of the corresponding measure component (Average, Count, Max, Min, etc.)
  • Calculation - This column is fixed as the user has no choice over calculation type on this report.
  • Precision - This field allows the user to enter the desired precision for the calculated report measure results.
  • Scaling - This field allows the user to enter a scaling parameter for the calculated report measure results (for example, thousands if the values are too large).
  • Units - This field allows the user to customise the report by entering a defined unit. The user can use this field to define currency symbols (for example, EUR'). The calculation type and scaling will auto-populate this field, but the user can edit the value. The value entered will impact the starting display name.
  • Display Name - This option allows the user to enter a custom name that is displayed in the report output for the corresponding measure. The starting value will be based on the measure component type and the other selections in the table. The display name should be unique for each measure in the table. So even if the same measure is referenced multiple times, the display name should be edited to make each one unique. The display name will be shown as this heading and graph title in the output report.

The Measure Business Type including validation restrictions are defined below (all are mandatory except for 'Indeterminate') -

Accounts Opened – typically the original number of accounts opened for a set of applications. This measure must be a Normal (non outcome) Count or Sum measure.

Bads – typically the number of bad accounts after an outcome length. This measure must be a Count or Sum measure. (Usually it will be derived measure or single measure of type(s) outcome open, outcome written-off).

Goods - typically the number of good accounts after an outcome length. This measure must be a Count or Sum measure. (Usually it will be derived measure or single measure of type(s) outcome open, outcome closed).

Indeterminate - typically the number of indeterminate (neither good or bad) accounts after an outcome length. This measure must be a Count or Sum measure. (Usually it will be derived measure or single measure of type outcome open). This measure is optional (and not required if Goods and Bads includes all potential account outcomes).

Total – typically the sum of Bads + Goods + Indeterminate. This measure must be a Count or Sum measure. (Usually it will be a derived measure).

Bad Rate – typically Bads over Accounts Opened. This measure must be a ratio measure. (Usually it will be a derived measure).

Good Bad Odds – Typically Goods over Bads. This measure must be a ratio measure. (Usually it will be a derived measure).

  For a logical report, the outcome lengths should be the same for each measure type.
