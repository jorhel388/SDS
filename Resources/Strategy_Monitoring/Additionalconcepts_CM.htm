Trends: Additional concepts

Walkthrough:

The Analysis Reference Date is 15th August 2010. The Analysis Period was set to TWO QUARTERS. (This means that the CMRP is ONE quarter.) So the two last complete quarters prior to 15th August are used as the Analysis Period (Jan - June 2010 i.e. 2010 Q2). This being a trend report, each trend period is processed independently.

The Outcome Length was defined as "3" - so, granted that the CMRP is one quarter, this translates to three quarters. So the "strict" Outcome Period is three quarters after the Analysis Period.

Consider two Accounts ("A" and "B") that have updates as per the table above.

For the first trend period, the Analysis Period is effectively just 2010 Q1. So, for Account "A", the most recent update in that period (March 2010) would be used for the Analysis Period information for the first trend period.

For the second trend period, the Analysis Period is effectively just 2010 Q2. Account A's June 2010 update would be used to provide the Analysis Period information for the second trend period. Similarly, the Outcome Period information will be captured twice (three quarters later) for each of the two trend periods. For Customer Management trend reports, an account can be counted (summed etc) separately for each trend period in which it appears.

Account B would only appear in the first trend period, as it has no update in the second trend period.

For the "All" column, each account will only be counted once. The most recent update in the Analysis Period (and the corresponding update in the Outcome Period) would be used. So, in this example, both Account A (using June 2010 (Analysis Period) and March 2011 (Outcome Period) information) and Account B (using March 2010 (Analysis Period) and October 2010 (Outcome Period) information) would appear.

For Acquisition trend reports, the only conceptual difference (from a trend perspective) is that each application will only appear in one trend period (since the application event is unique).
