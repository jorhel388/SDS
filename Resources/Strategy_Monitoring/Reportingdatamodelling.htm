Reporting data modelling

The user needs to ensure that the required logical data sources and physical data models are properly defined for reporting.

Only one logical data source should be created for each database table the user wants to use in reporting. The logical data source should not contain any arrays or referenced logical data models, since each characteristic in the logical data source will refer to a specific database column for the table being modelled. Each logical data source must have an associated java object physical data model. See Table Joins tab for information on mapping logical data sources to physical data models.

For more information on creating a logical data source, please refer to Create a Logical Data Source.

For more information on creating a physical data model, please refer to Create a Physical Data Model.

  For reporting, only Java Object physical data models should be used.

Within the Java Object physical data model the External Name field is used to hold the physical table name and column for the data items.

This should be entered without the use of quotes; e.g., APPLICANT.AGE.  

Naming requirements in reporting

There are certain requirements relating to naming conventions in Reporting. In order to protect against a malicious user corrupting the database the software prevents the use of high risk SQL keywords when a user constructs queries. SQL injection will be detected during execution by a simple text search for high risk SQL keywords. ("DROP" and "UPDATE" are examples of these SQL keywords.)

The search is a simple text search (as opposed to a word search), so "AccountUpdates" will be considered to contain a keyword, and the report will fail.

Also, it does not matter where in the query the keyword occurs; the search is not sensitive to whether the query appears as:

  • an SQL keyword (a true positive)

    ("SELECT * from table where '1';DROP TABLE x")

  • as part of a string (a false positive)

    ("SELECT * from table where Channel = "Maildropped")

  • in a column or table name (a false positive)

    ("SELECT * from AccountUpdates")

The reporting database cannot have tables or columns that contain keywords.

The database columns used in the report cannot (in many circumstances) contain VALUES that contain the SQL keywords.

Studio components referenced by the report (e.g. Scorecards, Test Group Set, Measure) cannot have names that contain SQL keywords.

Studio components whose contents are used by the report cannot (in many circumstances) contain keywords. Examples include:

  • Class set interval names
  • Class set range values
  • Test Group Set Test Group names

A generic error is returned to the Job Submission Console, so the user is not given guidance to where the high risk SQL keyword has been found.
