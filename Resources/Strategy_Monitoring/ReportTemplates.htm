Acquisition Report Templates

Reports are created by the user selecting a Report Template from those available in the solution and then configuring the template using a set of parameters to create a report definition. Additional templates may be developed in later software releases, and hence the range of available templates will grow over time.

Select a Report Template

When the user creates a report definition, they have to select the report template type to determine the report that needs to be produced.

The user will then need to set up the relevant configuration for the report definition.

To select a report template

  1. From the Report Template chooser, select the required template type from the Available Reports section.
  2. Click on the Expand (+) button to display the list of available report templates.
  3. Select the report template you want to configure.
  4. Click the Load button to load the report.

You can now configure the report definition.

Acquisition Automated Decision Trend report (AADT)

The Acquisition Automated Decision Trend (AADT) report allows the user to monitor the trend in the number of applications made from period to period.The volume and rate of the system's automated accept, refers and decline is also displayed in this report. Changes in the reports' trend will help the user to identify the strategy changes that needs investigation or a change in applying population.

 

The following business example illustrates how the Automated Decision Trend (AADT) report is used:

ABank Ltd schedules the Automated Decision Trend (AADT) reports over twelve months and eight quarters. They monitor these reports for any unexpected changes in the system decision rates. Due to the seasonality of the number of applications through the year, ABank pays close attention to the line chart (which, being percentage-based, remove this factor).

To create an Acquisition Automated Decision Trend (AADT) report, the user needs to configure the following tabs in the report editor:

Analysis Period tab

The Analysis Period tab determines the time span the report covers. This report style will show results for the whole analysis period (e.g., a 6 month period).

The user can configure the analysis period by specifying a reference date and an analysis time length. This sets the analysis period as the specified analysis time length before the analysis reference date.

Within the Analysis Reference Data, the user can choose to set one of the following to be the reference date:

  • a user defined date
  • the current server date
  • a date that is offset from the current server date.
    •   When you select the offset server date, you can handle any data latency issues that arise from delays in data being generated and being loaded to the reporting's data mart.

Within the Analysis Time Period Length, the user can:

  • select the time interval using the drop down (day, month, quarter)
  • the number of intervals using the slider

This specifies the length of the analysis period.

  4. Use the Offset Server Date radio button to select a reference date offset from the current server date.
  5. To configure the offset date, select the required time unit from the drop down menu and the value slider. These controls specify the number of days, weeks, months or quarters before the current server date.
    6.   When you select the offset server date, you can handle any data latency issues that arise from delays in data being generated and being loaded to the reporting's data mart.

The user can remove a parameter such as a filter or scorecard from the report definition.

The report parameter will be removed from the report definition.

Measure Selection tab

The measures selection tab allows the user to specify and configure the formatting for the measures they would like to be included on the report. A measure is a piece of information that the user wants to see on the output report (split by the time periods within the analysis period they have selected). The measures tab contains a table which has one row for each measure the user wishes to be included. Each measure specified will add either an extra row or an extra column to the output report (depending on the report template) and an extra graph.

Add a Measure to a report

In the Measure Selection tab, the user can add a minimum of 1 measure and a maximum of 10 measures.

  Your report must contain at least one measure.

To add a measure to a report

  1. With the Measure Selection tab open, in the Measure Selection table, drag the desired measure from the Resources window and drop it in the first column of a row of the Measure Selection table.
  2. Configure the customisable columns of the corresponding Measure Selection table row.
  3. To add another measure, right click on the Measure Selection table and select Add Row.
  4. Repeat step 1 to add another measure to the row of the report.
    5.   You can also use the Insert Row function to add another measure. When you use Add Row, a measure is added at the last position of a measure record where as when you use Insert Row, a measure is added between two existing measure records.

The measures that you have added will be used in the report.

The following example illustrates how the Accumulation Up calculation is applied in the Acquisition Trend report.

 

Your report spans from January to December and measures the number of applications over time. The total number of applications from January to December is 50 000

In 'accumulation up' mode - the value of the December column is equal to the total number of applications (50 000). The value of the January column is the actual number of applications for that month. The value of the February column is the number of applications submitted in January plus the number of applications submitted for February.

The accumulation up finishes in December where the value of the column is the sum of the number of applications submitted from January to December (50 000).

The following example illustrates how the Accumulation Down calculation is applied in the Acquisition Trend report.

 

Your report spans from January to December and measures the number of applications over time. The total number of applications from January to December is 50 000

In 'accumulation down' mode - the value of the January column is equal to the total number of applications (50 000). The value of the February column is 50 000 minus the number of applications submitted in January. The value of the March column is 50 000 minus the number of applications submitted in January and February.

The accumulation down finishes in December where the value of the column is the number of applications submitted in December.

The report results showed that scores for the “SC_CC_Apps” scorecard were generally higher than those expected from the benchmark distribution.

This prompted ABank to run the Acquisition Population Stability (APS) report on ad-hoc basis for both class sets in that scorecard. The applicants' ages were found to be slightly lower than those from the benchmark distribution. Incomes in the production data were also higher than those from the benchmark distribution. The Acquisition Population Stability Trend (APST) report provides the user with a high level assessment of whether the applied population is stable. In this report, the score distributions (or other segmentation characteristics) of the applications are compared over a period of time.   • The higher the Gini the stronger the discrimination of the scorecard
  • A scorecard with no discrimination would have a Gini of zero; a perfect scorecard would have a Gini of 100
  • A Gini is calculated by comparing the cumulative descending proportion of Goods and Bads by score

Acquisition Summary Trend report (AST)

The Acquisition Summary Trend (AST) report is a generic report that provides an overview of customer acquisition by a segmentation characteristic over time allowing the user to choose measures relating to the acquisition decision.

Each measure is shown by the row segmentation allowing easy comparison for a measure across the row segments.

The report user can then choose for which measures to report on, all the measures must relate to the acquisition decision as no subsequent account performance data is used. The measures are then shown by the segmentation characteristic (LDS characteristic or class set) as rows and the analysis time period (columns).

The standard acquisition filters (inclusion, exclusion) and slicing functionality is also available.

 

The following business example illustrates how the Acquisition Summary Trend (AST) report could be used:

In the Asia Pacific region, ABank Ltd has branches in Indonesia, Malaysia, Singapore and Thailand. ABank uses the Acquisition Summary Trend (AST) reports for ad-hoc analysis to monitor the following:

1. System accept rate, refer accept rate and take up rates by score-band over the last 12 months

2. Credit limits granted (to new applicants) by score-band over the last 3 quarters

3. Credit limits granted (to new applicants) by applicant income over the last 3 quarters
