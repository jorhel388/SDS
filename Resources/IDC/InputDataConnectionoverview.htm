Input Data Connections

The Input Data Connection provides an interface between Logical Data Sources and external Physical Data Sources. Users can:

  • Select an external database table or .csv file
  • Map logical characteristics from the published Logical Data Sources to an equivalent on the physical data repository
  • use the Input Data Connection's Automap, that performs exact matching as well as some degree of "fuzzy" matching that the user can accept or not as required
Overview

The Input Data Connection component will be used as input to other components that require access to a Physical Data Source. In the case of Test Project, for example, an Input Data Connection configured for use with a database table can be used as the source of test case data.

  All data configuration and characteristic mappings are maintained when exporting and importing Input Data Connection components and when creating and applying templates that include Input Data Connections. Summary and detailed reports will include information about the data connection and configured mappings.
  Dynamic arrays are not supported by the Input Data Connection component as it is not possible to represent these hierarchical data structures in an external database table or .csv file.
Define an input data connection

The Input Data Connection provides an interface between logical data sources and external physical data sources. The Input Data Connection component is used as input to other components that require access to a physical data source.

Create an input data connection

An input data connection can be created from the Explorer window.

  You will only be able to add a component type that has been allowed for the selected folder. If it is not allowed it will not be listed and therefore cannot be selected.

To create an input data connection

  1. From the Explorer window right click at the required folder level and select Add component.
  2. Select Input Data Connection.
  3. In the Create component dialog enter the name of the input data connection.
  4. If you wish to have the new component display in the Main editor on creation, ensure that the Open new components in component editor tick box is selected.
  5. Click on the OK button.

    The Input Data Connection editor will open allowing you to define the input data connection required.
    The input data connection name will be listed in the Explorer window under the selected folder level. The component is identified by the icon.

If you do not wish the editor to open, de-select the tick box. From the Explorer window select the input data connection and select Open.

Select a data source

The data source is a CSV file or a database table which stores the physical characteristics of the data set.

To select a CSV file as the data source

  1. From the Input Data Connection editor, click on the Select button in the Data Location section of the editor. The Data Source Selection dialog is displayed.
  2. Check that the data source type is identified as CSV, and click on the button to locate and select the file to use as the data source.
  3. Click the Preview button to display a sample of the data set.
  4. Click on the OK button to close the dialog and return to the editor.

The physical characteristics must now be mapped to the logical characteristics, either manually or automatically.

To select a database table as the data source

  1. From the Input Data Connection editor, click on the Select button in the Data Location section of the editor. The Data Source Selection dialog is displayed.
  2. Select Database as the data source type. The dialog reconfigures to prompt for database information.
  3. From the drop down menu, select the Job Server associated with the database, then select the Database to use.
  4. Finally, select the database Table to use as the data source. Note that the Preview button is disabled in this configuration of the dialog.
  5. Click on the OK button to close the dialog and return to the editor.

The physical characteristics must now be mapped to the logical characteristics, either manually or automatically.

Map characteristics manually

Once the data source has been selected the user must map the logical characteristics in the Logical Data Sources to the physical characteristics in the data file, either manually as described here, or automatically. This can be carried out in the Input Data Connector editor.

  The filters are a useful way to identify those characteristics that should be mapped.

The user can limit the number of Logical Data Sources displayed by clicking on the Select Logical Data Sources button to display the Logical Data Sources Selector dialog. The Select Logical Data Sources button can be found in the Input Data Connector editor.

To map characteristics manually

  1. In the Input Data Connector editor, using the filters if necessary, identify and click on a logical characteristic, then identify and click on the physical characteristic with which to map it. The physical characteristics are loaded automatically when the data set is selected.
  2. Click on the Map button to map the characteristics.
  3. If a static or dynamic array element appears anywhere within the hierarchy of the selected logical characteristic, the Select Characteristic Array Element(s) dialog is displayed, enabling you to map static and dynamic arrays.
  4. The mapped characteristics are listed in the Mapped Characteristics table, and the characteristic name disappears from the Logical Characteristics display.
  5. You can specify a group of characteristics all at once by selecting a referenced or embedded logical data model from the characteristics chooser; when you click the Map button, the warning appears: "Selected logical characteristic will result in multiple mappings. Do you want to continue?" Click OK to map all the characteristics in the Logical Data Model to the selected physical characteristic.
  6. The system checks for mapping validation errors, and displays them in the Mapping table. See the topic Mapping validation for a description of how mapping validation errors can be identified.
  7. Click on Save to save the mapping.

Mapped characteristics can be unmapped individually, using the Unmap button, or all together using the Unmap All button.

Automap characteristics

From the Input Data Connection editor, once the data set has been selected the user must map the logical characteristics in the logical data source to the physical characteristics in the data file, either automatically as described here, or manually. Automap will try to match characteristics from the logical data source to the set of physical characteristics. See the discussion for a more detailed description of automapping.

  The filters are a useful way to identify those characteristics that should be mapped.

To map characteristics automatically

  1. In the Input Data Connection editor, click on the Automap button to map the characteristics.
  2. The Automap Characteristic dialog is displayed, allowing the user to select which of the suggested mappings to add and which to discard.
  3. Click Accept. The mapped characteristics are listed in the Mapped Characteristics table, and the characteristic names disappear from the Logical Characteristics display.
  4. The system checks for mapping validation errors, and displays them in the Mapping table. See the topic Mapping validation for a description of how mapping validation errors can be identified.

Mapped characteristics can be unmapped individually, using the Unmap button , or all together using the Unmap All button .

The Input Data Connection you have created can now be used in other components as required.
