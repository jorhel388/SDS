Semi Structured Data Definition

The Semi Structured Data Definition component uses a loaded JSON schema to generate Logical Data Models of all or a subset of the contents of the selected JSON file. These Logical Data Models can then be used within other Design Studio components as normal depending on publishing rules. The Semi Structure Data Definition enables a user to use a central definition of their data model (JSON file) that could span the entire PowerCurve platform, if required.

  Although available for selection in all PowerCurve products, the Semi Structured Data Definition component is only supported in PowerCurve Strategy Management and PowerCurve Originations.
Overview

Using the functionality within the Semi Structured Data Definition component, the user can:

  • load a JSON schema that will be used to generate a root Logical Data Model and all the required child Logical Data Models defined in the JSON file

  • determine whether all or a subset of the data model that is defined in this JSON file is required and processed at runtime

  • manipulate the data model prior to the generation of the required Logical Data Models (only data type, length, scale and array size can currently be modified)

  • choose which Parser to use at runtime to load the file

    •  

    The DOM parser is not yet supported.
  The name of the Semi Structured Data Definition component and names of all the nested elements in the JSON schema file must adhere to the rules defined within the Characteristic Properties section of the Logical Data Model overview.

Edit a Semi Structured Data Definition
Create

A Semi Structured Data Definition is created from the Explorer Window.

  You will only be able to add a component type that has been allowed for the selected folder. If it is not allowed it will not be listed and therefore cannot be created.

To create a Semi Structured Data Definition

  1. From the Explorer window, right click at the required folder level and select Add component.

  2. Select Semi Structure Data Definition.

  3. In the Create component dialog, enter the name of the Semi Structured Data Definition.

  4. Select the Open new components in the component editor check box.

  5. Click on the OK button.

  6. The Semi Structured Data Definition editor will open allowing you to define a Semi Structured Data Definition.

  7. The Semi Structured Data Definition name will be listed in the Explorer window, under the selected folder level. The component is identified by the icon.

If you do not wish the editor to open, keep the check box de-selected. From the Explorer window select the Semi Structured Data Definition and select Open.

To define a Semi Structured Data Definition

  1. With the Semi Structured Data Definition editor open, from the Protocol drop down box, select the required Protocol of the file.

  2. From the Parser drop down box, select the required Parser.

    3.   Only the SAX parser is currently supported.

  1. Leave the Read Only checkbox as it has been rendered.

    2.   The Read Only feature is currently not supported.

  1. Click Browse and Load.
    The Open dialog will be displayed.

  2. Locate and select the JSON Schema file and click Open.
    The Data Source Selection dialog will Open. The Data Source Selection dialog provides a preview of the Logical Data Models that will be generated when the Semi Structured Data Definition component is saved.

  3. Select the characteristics that you want to be included.

  4. Click OK
    The Data Source Selection dialog will close.
    The details of the selected characteristics from the Data Source Selection dialog will be added to the Semi Structured Data Definition. The Schema field will be populated with the name of the selected file.

  5. Click Save.

The Logical Data Models will be generated in the folder where the Semi Structured Data Definition is located and be available for selection within the Explorer.

The route Logical Data Model will be assigned the same name as the Semi Structured Data Definition, but with the suffix LDM.

Test a Semi Structured Data Definition using Interactive Tester

In order to test a Semi Structured Data Definition using Interactive Tester, the value from the Semi Structured Data Definition characteristic needs to be assigned to the Logical Data Source characteristic.

  The Semi Structured Data Definition payload is Read Only in Interactive Tester. However, the payload can be modified externally and then imported into Interactive Tester.
  The Semi Structured Data Definition payload is constructed dynamically when entering values into the leaf characteristics.
  Export will contain both the Semi Structured Data Definition payload and the Semi Structured Data Definition leaf characteristics.

To test a Semi Structured Data Definition using Interactive Tester

  1. Select the Test icon to activate Interactive Tester.

  2. Select the Tree View tab.
