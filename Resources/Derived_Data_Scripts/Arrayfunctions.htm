Array functions

These functions manipulate the contents of an array (table) characteristic.

Note the following:

  • Array is a single row table containing all text values or all numeric values.
  • Dest is an array characteristic where the result of the function is to be placed.
  • Dynamic array is an array for which characteristics can be added or removed.
    •  

    The size of the dynamic array used to hold the results <dest> will be automatically sized to hold the number of elements returned.

    Any existing values in the <dest> array will be ignored, they will be cleared and will be replaced by the elements returned.
  • The ADDELEMENT, CLEAR and SETSIZE functions are only applicable for use with dynamic arrays. Dynamic arrays can be used with all other array functions.
  • Dynamic Logical Data Model (LDM) arrays are valid input and output in the Interactive Tester for the following array functions: SIZE, ADDELEMENT, SETSIZE and CLEAR. Therefore, the user is allowed to build the dynamic LDM array characteristics by adding elements. Further information on this can be found in Add elements.
    •  

    When dynamic array elements are added in the Interactive Tester and the test does not use any primitive characteristics from the array, the added elements will appear with an asterisk (*) next to them in the Table View. In the Tree View, they will appear, but not with an asterisk.

    Table View Tree View
  • Bound is a limitation on the number of entries in the array on which the function will be based. For example a bound value of 10 will return the result based on the first 10 values. In the case of an optional bound, if no bound is entered then the function will be performed on all values in the array.

The below series of drop downs provide detailed information on each array function.

For information on the Palette availability tables, see Palette availability.

Add Element (Increases the size of a dynamic array)
w

Add Element

The ADDELEMENT function increases the size of a
dynamic array by adding one element to the end of the
array. It initialises the
new element values to NULL.

Syntax

ADDELEMENT( <dynamic array> )

 

 

 

 

Parameter or Return Data Type Description

<dynamic array>

Date, Numeric or String array

A reference to a dynamic array, or a dynamic array of an LDM (group-level) characteristic.
Return

Void

This function does not return a value.

Remarks

Currently dynamic arrays are only supported by scripts directly processed by the Enrichment Agent and the Decision Agent. For further details about the use and restrictions of dynamic arrays, see the Arrays topic in the Experian Domain Scripting Language (EDSL) user guide.

The element that is added to the dynamic array is initialised to a NULL value.

The function cannot be used with a fixed size array. An error is produced if the function is used with a fixed size array.

As an alternative to the ADDELEMENT function, the SETSIZE function can be used to set a pre-determined size of a dynamic array at runtime, instead of increasing the size one element at a time. For further information see Set size below.

Example

The following example adds an element to a dynamic array called 'Example.Stringarray'.

ADDELEMENT('Example.Stringarray')

The Clear elements function removes all elements from a dynamic array so that its size is 0. Any data previously held by the array is removed from memory.

Palette availability

Find (Returns the number representing the array element)

Find

Palette availability

The FIND function returns the number representing the array element for a characteristic array or a number
representing (index) the location of the
first matching value, for a characteristic field in an LDM array.

Syntax

FIND( <array>, <value>, <condition(optional)>, <bound(optional)>)

or

FIND( <ldm array>, <characteristic>, <value>,<condition (optional)>, <bound(optional)>)

For usage of FIND( <array>, <value>, <condition(optional)>, <bound(optional)>)

Parameter or Return Data Type Description

<array>

Numeric or String array

A reference to a fixed-size or dynamic array.

<value>

Numeric or String

A reference to a characteristic; a literal; or an expression that equates to a numeric or string value. It represents the value used to search the <array>.

<condition(optional)>

String

A string representing a condition to be applied to the <value>. The following conditions can be used >, >=, =, <>, <, <= and ~.

The value of this parameter must be enclosed in double quotes, for example "<=".

<bound(optional)>

Numeric (Integer)

A reference to a characteristic; a literal; or an expression that equates to an integer value. It must have a value of between 1 and the size of the array. It may be used to limit the number of elements in the array that are tested for the value. For example, if the array has a size of 12 and <bound> is set to 10, then the FIND function will only test the first 10 elements.

Return

Numeric (Integer)

A number representing the index of the first matching element which contains the <value>.

A value of 0 is returned if the <value> is not found in the array.

 

For usage of FIND( <ldm array>, <characteristic>, <value>,<condition (optional)>, <bound(optional)>)

 

This usage requires access to hierarchical group characteristics, which are only supported by scripts directly processed by the Enrichment Agent and the Decision Agent. Usage in an unsupported context will result in a deployment failure.
Parameter or Return Data Type Description

<ldm array>

Array of an LDM

A reference to a fixed-size or dynamic array of an LDM.
<characteristic> Numeric or String A reference to a <characteristic> which must be held within the <ldm array>, not in a subordinate LDM. This is the<characteristic> that the Find will be executed against.

<value>

Numeric or String

A reference to a characteristic; a literal; or an expression that equates to a numeric or string value. It represents the value used to search the <characteristic> in the <ldm array>.

<condition (optional)>

String

A string representing a condition to be applied to the <value>. The following conditions can be used >, >=, =, <>, <, <= and ~.

The value of this parameter must be enclosed in double quotes, for example "<=".

<bound (optional)>

Numeric (Integer)

A reference to a characteristic; a literal; or an expression that equates to an integer value. It must have a value of between 1 and the size of the <ldm array>. It may be used to limit the number of elements in the <ldm array> that is tested for the value.

For example, if the <ldm array> has a size of 12 and <bound> is set to 10, then the FIND function will only test the first 10 elements.

Return

Numeric (Integer)

A number representing the index of the first matching <ldm array> element which contains the <value> within the characteristic.

A value of 0 is returned if the <value> is not found in the <ldm array>.

Remarks

The FIND function that is available from the Functions – Array palette can be used with all studios and the script components shown in the Palette Availability table above. There is also a FIND function in the Functions palette and this is available in CMDS only with the Behavioural Script, Behavioural History Update Script and User Defined Behavioural Function script components only; and does not support regular expressions.

Currently dynamic arrays are only supported by scripts directly processed by the Enrichment Agent and the Decision Agent. For further details about the use and restrictions of dynamic arrays, see Using dynamic arrays in a script. Dynamic arrays are not supported by the Scoring Function and Transformation Function components.

The result can be stored in an Integer characteristic, passed as an argument into another function or used as part of an expression.

The <condition (optional)> parameter must be specified if the <bound (optional)> parameter is used. It is not possible to use <bound (optional)> on its own.

The <bound (optional)> parameter specifies the upper element limit in an array. This is useful for arrays that contain sequential information such as the balance information for each month of a year, where it may be required to only find the maximum value for a shorter period than a year.

The data type of <value> must match the data type of <array>. When using an <ldm array> , the data type of the value must match the data type of the <characteristic>.

If the regular expression tilde operator (~) can be used for the <condition (optional)> parameter, then <value>,and <array> or <value> and <characteristic> must be of type string. The <value> parameter must be a string literal or a string characteristic that contains the regular expression pattern.

 

Zero Sized Arrays and null value handling

The FIND function has differing behaviour for fixed-sized and dynamic arrays with respect to null value handling.

Fixed-sized array (<array>) or fixed-size array of an LDM (<ldm array>):

  • For fixed-sized arrays within a LDS hierarchy which includes a parent zero sized dynamic array of an LDM, the FIND function will return 0 (and no runtime error will be produced).

  • Other operations of the FIND function will produce an error:

    • if the <array> (or <characteristic>) contain uninitialised values

    • if the <value> is a characteristic which has an uninitialised value

Dynamic array <array> or dynamic array of an LDM (<ldm array>)

  • For dynamic-sized arrays within a LDS hierarchy which includes a parent zero sized dynamic array of an LDM, the FIND function will return 0 (and no runtime error will be produced).

  • If the <array> or <ldm array> is zero sized, the FIND function will return 0 (and no runtime error will be produced).

  • Other operations of the FIND function will NOT produce an error

    • if the <array> (or <characteristic>) contain only uninitialised values the FIND will return 0

    • if the <array> (or <characteristic>) contain some uninitialised values the FIND will ignore (but not remove) the uninitialised values and operate on the remaining values (returning 0 if no match is found, or the element which matches)

    • if the <value> is a characteristic which has an uninitialised value the FIND will return 0

For more details (and examples) refer to the EDSL User Guide. Refer to the ISNULL function for how to detect uninitialised values

The function cannot be used with Date arrays.

For examples on how the RegEx operator is used see the Regular Expression topic.

Examples for FIND( <array>, <value>, <condition(optional)>, <bound(optional)>)

 

The following example uses an array called Example.Integerarray which has 3 elements containing the values 12, 36 and 36 respectively. The FIND function is used to search the array for the first value of 36. The result is 2 (the index of the first element containing 36) and is stored in the Integer characteristic called Example.Result.

'Example.Result' = FIND('Example.Integerarray', 36)

 

The following example uses an array called Example.Integerarray which has 5 elements containing the values 2, 8, 10, 16 and 10 respectively. The FIND function is used to search the array for the first value greater than 10. The result is 4 (the index of the first element containing a value greater than 10) and is stored in the Integer characteristic called Example.Result.

'Example.Result' = FIND('Example.Integerarray', 10, ">")

 

The following example uses an array called Example.Integerarray which has 12 elements containing the values 1, 2, 21, 16, 34, 16, 94, 89, 21, 37, 18 and 9 respectively. The FIND function is used to search the first 10 elements of the array for the first value greater than 70. The result is 7 (the index of the first element containing a value greater than 70) and is stored in the Integer characteristic called Example.Result.

'Example.Result' = FIND('Example.Integerarray', 70, ">", 10)

 

The following example uses a string array called Example.Addressarray which contains a postal address in USA. The FIND function uses a regular expression pattern to search the array for a US ZIP code. The result is stored in the Integer characteristic called Example.Result.

'Example.Result' = FIND('Example.Addressarray', "^\d{5}$|^\d{5}-\d{4}$","~")

Examples for FIND( <ldm array>, <value>, <condition(optional)>, <bound(optional)>)

 

The following example uses an LDM array called Applicant which contains an applicant's employment information. The FIND function searches the array for any applicants in full time employment over all applicants using a fixed bound. The result is stored in Application LDS.FT Employed.

IF FIND('Application LDS.Applicant', 'Application LDS.Applicant'[1].'Employment Status', "F", "=", 6) = 0 THEN 'Application LDS.FT Employed' = "N"

ELSE 'Application LDS.FT Employed' = "Y"

ENDIF

  The characteristic being assessed, 'Application LDS.Applicant'[1]., refers to the first element in the LDM array. However, any of the elements in the LDM array can be used.

 

The following is an invalid example in which the employment status characteristics are not a direct child of the Applicant LDM.

'Application LDS with Two Level LDM.FT Employed' = FIND ('Application LDS with Two Level LDM.Applicant','Application LDS with Two Level LDM.Applicant'[1].'Applicant Information.Employment Status', "F", = "6")
Max (Returns the maximum value in a numeric array)

Max

The MAX function returns the maximum value contained in a numeric array.

Palette availability

Syntax

MAX( <array>, <bound> )

or

MAX( <ldm array>, <characteristic>, <bound> )

 

 

 

 

For usage of MAX( <array>, <bound> )

Parameter or Return Data Type Description

<array>

Numeric array

A reference to a fixed-size or dynamic array.

<bound>

Numeric (Integer)

A reference to a characteristic; a literal; or an expression that equates to an integer value. It must have a value of between 1 and the size of the array. It may be used to limit the number of elements in the array that are tested for the maximum value. For example, if the array has a size of 12 and <bound> is set to 10, then the MAX function will only test the first 10 elements.

Return

Numeric

The maximum value stored by one or more elements in the array.

For usage of MAX( <ldm array>, <characteristic>, <bound> )

 

This usage requires access to hierarchical group characteristics, which are only supported by scripts directly processed by the Enrichment Agent and the Decision Agent. Usage in an unsupported context will result in a deployment failure.
Parameter or Return Data Type Description

<ldm array>

Array of an LDM

A reference to a fixed-size or dynamic array of an LDM.
<characteristic> Numeric or String A reference to a <characteristic> which must be held within the <ldm array>, not in a subordinate LDM. This is the <characteristic> that will be assessed for the maximum value.

<bound>

Numeric (Integer)

A reference to a characteristic; a literal; or an expression that equates to an integer value. It must have a value of between 1 and the size of the array. It may be used to limit the number of elements in the array that are tested for the maximum value. For example, if the array has a size of 12 and <bound> is set to 10, then the MAX function will only test the first 10 elements.

Return

Numeric

The maximum value of the <characteristic> stored by one or more elements in the LDM array.

Remarks

The result can be stored in a numeric characteristic; passed as an argument into another function; or used as part of an expression.

Currently dynamic arrays are only supported by scripts directly processed by the Enrichment Agent and the Decision Agent. For further details about the use and restrictions of dynamic arrays, see Using dynamic arrays in a script. Dynamic arrays are not supported by the Scoring Function and Transformation Function components.

The <bound> parameter specifies the upper element limit in an array. This is useful for arrays that contain sequential information such as the balance information for each month of a year, where it may be required to only find the maximum value for a shorter period than a year.

The maximum value for the whole array can be obtained by using the SIZE function to set the <bound> to the size of the array. For further information, see Size.

The function should not be used on uninitialised arrays otherwise an error will be produced.

The function cannot be used with Date or String arrays.

Examples for MAX( <array>, <value>, <condition(optional)>, <bound(optional)>)

 

The following example uses an array called Example.Integerarray which has 3 elements containing the values 2, 40 and 15 respectively. The Max function is used to return the maximum value for all elements by using the Size function to set the <bound> parameter. The result is 40 and is stored in the Integer characteristic called Example.Maxvalue.

'Example.Maxvalue' = MAX('Example.Integerarray', SIZE('Example.Integerarray'))

Examples for MAX( <ldm array>, <characteristic>, <bound> )

 

The following example uses an LDM array called Applicant which contains an applicant's income information. The MAX function searches the array for the maximum income over all applicants using a <bound> calculated from the size of the LDM array. The result is stored in Application LDS.Max Income.

  The characteristic being assessed, 'Application LDS.Applicant'[1].'Income', refers to the first element in the LDM array. However, any of the elements in the LDM array can be used.

 

The following is an invalid example in which the income characteristics are not a direct child of the Applicant LDM.

'Application LDS with Two Level LDM.Max Income' = MAX ('Application LDS with Two Level LDM.Applicant','Application LDS with Two Level LDM.Applicant'[1].'Applicant Information.Income', 6)
Merge (Combines and sorts the contents of two source arrays)

Merge

The MERGE function combines and sorts the contents of two source arrays in a destination array, and optionally removes any duplicate entries.

Palette availability

Syntax

MERGE( <array1>, <array2>, <order>, <
dest> )

 

 

 

 

 

Parameter or Return Data Type Description

<array1>

Numeric or String array

A reference to a fixed-size or dynamic array to use as the first source.

<array2>

Numeric or String array

A reference to a fixed-size or dynamic array to use as the second source.

<order>

String

The order used to sort the <dest> array and whether duplicates should be removed. This parameter can have any one of 4 values:

  • "A" - Ascending order, retain duplicates.
  • "D" - Descending order, retain duplicates.
  • "AR" - Ascending order, remove duplicates.
  • "DR" - Descending order, remove duplicates.

<dest>

Numeric or String array

A reference to a fixed-size or dynamic array to use as the destination.

 

The size of the dynamic array used to hold the results <dest> will be automatically sized to hold the number of elements returned.

Any existing values in the <dest>array will be ignored, they will be cleared and will be replaced by the elements returned.
Return

Void

This function does not return a value.
  When Merge is used any entry that contains only multiple spaces, that is there are no other characters, for example " ", the multiple spaces will be converted to a single space " " and duplicates removed when specified.

Remarks

Currently dynamic arrays are only supported by scripts directly processed by the Enrichment Agent and the Decision Agent. For further details about the use and restrictions of dynamic arrays, see Using dynamic arrays in a script. Dynamic arrays are not supported by the Scoring Function and Transformation Function components.

The data type of the <array1>, <array2> and <dest> arrays must be the same.

The size of the <dest> array must be at least the combined size of <array1> and <array2>.

The function cannot be used with Date arrays.

Example

 

The following example combines the contents of two arrays called Example.SrcStringarr1 and Example.SrcStringarr2 in a destination array called Example.DestStringarr. The contents of the destination array are sorted in ascending order and any duplicate values are removed.

MERGE('Example.SrcStringarr1', 'Example.SrcStringarr1', "AR", 'Example.DestStringarr')

Set Size (Used to define the number of elements in a dynamic array)

Setsize

The SETSIZE function is used to define the number of elements in a dynamic array.

Palette availability

Syntax

SETSIZE( <array>, <size> )

 

 

 

 

 

 

Parameter or Return Data Type Description

<array>

Date, Numeric or String array

A reference to a dynamic array, or a dynamic array of an LDM (group-level) characteristic.

<size>

Numeric (Integer)

A reference to a characteristic, a literal, or an expression that equates to an integer value. It is used to define the size of the dynamic array.

Return

Void

This function does not return a value.

Remarks

Currently dynamic arrays are only supported by scripts directly processed by the Enrichment Agent and the Decision Agent. For further details about the use and restrictions of dynamic arrays, see Using dynamic arrays in a script.

The elements that are created in the dynamic array are initialised to a NULL value.

The SETSIZE function should be used when the size of the dynamic array can be pre-determined. For example, when performing normalisation and going from a source Logical Data Source to a destination Logical Data Source, when only the format of the data needs to be changed and occurrences of the data are not being added or removed (i.e. the size of the source and destination dynamic arrays will be the same).

The function cannot be used with a fixed size array. An error is produced if the function is used with a fixed size array.

As an alternative to the SETSIZE function, the ADDELEMENT function can be used to add a single element to a dynamic array at runtime. For further information see Add element.

SETSIZEshould be used when the destination dynamic array's magnitude can be pre-determined.

 

For example, when performing normalisation, going from a source Logical Data Source to a destination Logical Data Source, when only the format of the data needs to be changed, when occurrences of the data are not being added or removed:  e.g. the size of the destination dynamic array will be the same as the size of the one from which the function is reading so the size of the destination dynamic array can be specified by using SETSIZEwith the parameter being the SIZEof the source array.

The <array> can be an atomic dynamic array or a dynamic array of an LDM (group-level) characteristic.  The number can be a constant, a numeric characteristic or the numeric result of another valid expression.

Example

 

The following example sets the size of a dynamic array called Example.DestIntegerarray to the same size as the array called Example.SrcIntegerarray.

SETSIZE('Example.DestIntegerarray', SIZE('Example.SrcIntegerarray'))

Sort (Sorts the contents of a source array)

Sort

Palette availability

The SORT function sorts the contents of a source array into a destination array, and optionally removes any duplicate entries.

Syntax

SORT( <array>, <order>, <dest> )

 

 

 

Parameter or Return Data Type Description

<array>

Numeric or String array

A reference to a fixed-size or dynamic array to use as the source.

String

The order used to sort the <dest> array and whether duplicates should be removed. This parameter can have any one of 4 values:

  • "A" - Ascending order, retain duplicates.
  • "D" - Descending order, retain duplicates.
  • "AR" - Ascending order, remove duplicates.
  • "DR" - Descending order, remove duplicates.

<dest>

Numeric or String array

A reference to a fixed-size or dynamic array to use as the destination.

 

The size of the dynamic array used to hold the results <dest> will be automatically sized to hold the number of elements returned.

<array>

Numeric array

A reference to a fixed-size or dynamic array.

<bound>

Numeric (Integer)

A reference to a characteristic; a literal; or an expression that equates to an integer value. It must have a value of between 1 and the size of the array. It may be used to limit the number of elements in the array that are used in the calculation of the sum. For example, if the array has a size of 12 and the <bound> is set to 10, then the Sum function will only add the values of the first 10 elements.

Return

Numeric

The sum of the elements in the array.

For usage of SUM( < ldm array >, < characteristic >, < bound > )

  This usage is not supported in the Behavioural History Update Script, Behavioural Script or User Defined Behavioural Script components
 

This usage requires access to hierarchical group characteristics, which are only supported by scripts directly processed by the Enrichment Agent and the Decision Agent. Usage in an unsupported context will result in a deployment failure.
Parameter or Return Data Type Description

<ldm array>

Array of an LDM

A reference to a fixed-size or dynamic array of an LDM.
<characteristic> Number or String A reference to a <characteristic> which must be held within the <ldm array>, not in a subordinate LDM. This is the <characteristic> that the Sum will be executed against.

<bound>

Numeric (Integer)

A reference to a characteristic; a literal; or an expression that equates to an integer value. It must have a value of between 1 and the size of the LDM array. It may be used to limit the number of elements in the LDM array that are used in the calculation of the sum. For example, if the LDM array has a size of 12 and the <bound> is set to 10, then the Sum function will only add the values of the first 10 elements.

Return

Numeric

The sum of the elements in the array of an LDM.

Remarks

Currently dynamic arrays are only supported by scripts directly processed by the Enrichment Agent and the Decision Agent. For further details about the use and restrictions of dynamic arrays, see Using dynamic arrays in a script.

The result can be stored in a numeric characteristic; passed as an argument into another function; or used as part of an expression.

The <bound> parameter specifies the upper element limit in an array. This is useful for arrays that contain sequential information such as the balance information for each month of a year, where it may be required to only find the sum for a shorter period than a year.

The summation of all the values for the whole array can be obtained by using the SIZE function to set the <bound> to the size of the array. For further information, see Size.

The function should not be used on uninitialised arrays otherwise an error will be produced.

The function cannot be used with Date or String arrays.

Example for usage of SUM( < array >, < bound > )

 

The following example uses an array called Example.Integerarray which has 3 elements containing the values 2, 10 and 15 respectively. The SUM function is used to return the summation of the values for all elements by using the SIZE function to set the <bound> value. The result is 27 and is stored in the Integer characteristic called Example.Totalvalue.

'Example.Totalvalue' = SUM('Example.Integerarray', SIZE('Example.Integerarray'))

Example for usage of SUM( < ldm array >, < characteristic >, < bound > )

 

The following example uses an LDM array called Applicant which contains an applicant's income information. The SUM function sums all the applicants' income using a fixed bound. The result is stored in Application LDS.Sum Applicants Income.

'Application LDS.Sum Applicants Income' = SUM ( 'Application LDS.Applicant'[1].'Income', 6 )

  The characteristic being assessed, 'Application LDS.Applicant'[1].'Income', refers to the first element in the LDM array. However, any of the elements in the LDM array can be used.

 

The following is an invalid example in which the income characteristics are not a direct child of the Applicant LDM.

'Application LDS with Two Level LDM.Sum Income' = SUM ('Application LDS with Two Level LDM.Applicant','Application LDS with Two Level LDM.Applicant'[1].'Applicant Information.Income', 6)
