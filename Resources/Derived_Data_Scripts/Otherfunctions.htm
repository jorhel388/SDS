Other functions

Other functions have been added to execute external calls, to execute external scripts, to generate unique IDs, to be able to persist multiple DA Call Results in a single instance, and to be able to obtain information about the operational environment.

In a system where multiple Decision Setters are used at different points within the decisioning process, if a consolidated overall decision is required, then the individual Decision Results Tables need to be merged together into a table producing the final top ranking decision. Within the Derived Data Script component there is a specific function called Merge Tables. This function has been created to enable the user to merge multiple Decision Result Tables to obtain the overall decision.

Function Script Syntax Usage

Exec*

EXEC( "<class.method>" )

Enables the user to call any Java code. The .jar file for the external code must be included on the Java Classpath used by the DA.

  If the external call is used in interactive/non-interactive testing, the .jar file must be copied to a sub-folder of the Studio's installation folder

Exec Script**

Execute script

EXEC_SCRIPT( "<script.filename>" )

Enables runtime capability of talking to external client-written scripts.

Generate UUID

UUID()

User is able to invoke the unique ID generator. The function does not accept any parameters.

Get Environment Variable

GETENV( "<variable_name>" )

Enables the solution designer to obtain information within the business process flow about the bank operator who operates on the Business Process Server (BPS) and use it for either logging/tracing purposes or for executing Boolean conditions. This function always yields a string, which can be either assigned to a Logical Data Source characteristic or used as one side of a comparison. See Environment variable parameters for a list of all possible parameters that can be passed to the function.

Insert

INSERT( "<lds>", '<data view embedded array>' )

Inserts Logical Data Source characteristic into the embedded array Logical Data Source characteristic.

Lookup Code

LOOKUPCODE (<code table>, <desc table>, <decision reason code>)

Returns the descriptions corresponding to the given reason codes; looks up each of the reason codes from the specified Decision Reason Code Table and writes the description to the specified description table.

Code table = String array that contains the Decision Reason Codes to be looked up in the table given by <decision reason code>.

Desc table = A string array that is used by the function to write the descriptions that correspond to the matching Decision Reason Codes.

Decision Reason Code = The reference of the Decision Reason Code Table component used for the look up.

  If the <desc table> uses a dynamic array, its size will be set during execution of the function and will overwrite any existing data in the array.

Merge Tables

MERGETABLES ( <table1>, <table2>, <decision set>, <output table>, <decision category>, <decision text>, <reason code table> )

Mergetables, merges the contents of two Decision Setter Tables, using the priority order defined in the Decision Set of a Decision Setter to produce a consolidated overall decision, refer to the Merge Decision Tables topic for more information.

  If the <output table> and/or the <reason code table> uses a dynamic array, its size will be set during execution of the function and will overwrite any existing data in the array.
  When an empty or null string is found in either <table1> or <table 2> this marks the end of the array and no further entries are processed from this table.

Reset***

RESET( "<lds>" or <char>)

The user has the choice of setting the value of an individual characteristic to Null using <char> or setting the values contained in a logical data source <lds> to Null before running the next DA Call, so that it will contain only the new value(s) to be inserted into the DA Result table.

e.g.

IF 'characteristic' <>"22" THEN

RESET ('basic.value')

ENDIF
  *The EXEC function requires the size of dynamic arrays to be defined within the script prior to it being referenced. If this is not possible the user should consider using the User Defined Function Java option instead.
  **The Exec_Script function supports JavaScript and GroovyScript, see Exec_Script example.
  ***The Reset function which previously reset an LDS and its characteristics to Null has been overloaded to provide a new implementation which will accept an individual characteristic. This function is intended for use only within the Strategy Management and Originations context and its runtime environment. The use of this function in a non-Strategy Management/non-Originations runtime environment can result in runtime exception errors.
