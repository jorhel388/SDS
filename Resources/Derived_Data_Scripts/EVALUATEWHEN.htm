EVALUATE WHEN

Evaluate is a shorthand way of writing nested IF statements. It allows the comparison of one or more expressions with an initial expression. The first comparison that evaluates to true will result in a statement being performed.

 

To set an Income Bracket description based on the values held in an Income characteristic you may write:

EVALUATE 'Generic App.Income'

WHEN > 3000 DO 'Generic App.Income Bracket' = "High"

WHEN > 1500 DO 'Generic App.Income Bracket' = "Middle"

OTHER 'Generic App.Income Bracket' = "Low"

END_EVALUATE

- If the value in Income is greater than 3000 set the Income Bracket to a value of "High"

- If the value in Income is greater than 1500 set the Income Bracket to a value of "Middle"

- Otherwise set the Income Bracket to a value of "Low"

The Evaluate syntax is:

EVALUATE <expr>

WHEN <comp> <expr> DO <stmt> (WHEN....DO... is repeated as often as required)

OTHER <stmt>

END_EVALUATE

In the above example:

  • 'Generic App.Income' replaces the initial <expr> in the supplied template
  • > replaces the <comp> in the supplied template
  • 3000 replaces the <expr> in the WHEN..DO... <expr> in the supplied template
  • 'Generic App.Income Bracket' = "High" replaces the <stmt> in the supplied template
  • The second WHEN...DO.. line is added to the initial template
  • 'Generic App.Income Bracket' = "Low" replaces the <stmt> after the OTHER in the supplied template

Generally:

  • An initial expression is entered. This expression can be a characteristic or a calculation but must result in a value
  • Then a series of WHEN statements are written to make a comparison against the initial expression. The expression being compared can be a characteristic or a calculation but must have the same data type as the initial expression
  • The first WHEN comparison that produces a true result will cause the DO statement that follows it to be executed
  • If none of the WHEN comparisons produce a true result then the OTHER statement is processed
  • The OTHER statement is not optional, if it is not included the script will not compile properly
    •  

    The expressions used in the WHEN.. DO.. lines could overlap and so the order in which they are written is important as the statement on the first true condition will be performed.

    For example in above you would not write >1500 before >3000 as if it is >3000 it will also be >1500 and the statement relating to 1500 will be processed even if the value is, for example 4000.
