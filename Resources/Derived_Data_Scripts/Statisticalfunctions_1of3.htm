Statistical functions - 1 of 3

In all of the following:

  • array is a single row table characteristic containing numeric values
  • bound is a limitation on the number of entries in the array on which the function will be based. For example a bound value of 10 will return the result based on the first 10 values. If no bound is entered then the function will be performed on all values in the array.

The below series of drop downs provide detailed information on each array function.

For information on the Palette availability tables, see Palette availability.

Mean (Returns the average value for an array)

Mean

Palette availability

The MEAN function returns the mean or average value contained in a numeric array.

Syntax

MEAN( <array>, <bound> )

or

MEAN( <ldm array>, <characteristic>, <bound> )

 

For usage of Mean( <array>, <bound> )

Parameter or Return Data Type Description

<array>

Numeric array

A reference to a fixed-size or dynamic array.

<bound>

Numeric (Integer)

A reference to a characteristic; a literal; or an expression that equates to an integer value. It must have a value of between 1 and the size of the array. It may be used to limit the number of elements in the array that are used to calculate the mean value. For example, if the array has a size of 12 and the <bound> is set to 10, then the MEAN function will only use the first 10 elements.

Return

Numeric

The mean value for the array.

For usage of MEAN( <ldm array>, <characteristic>, <bound> )

  This usage is not supported in the Behavioural History Update Script, Behavioural Script or User Defined Behavioural Script components
 

This usage requires access to hierarchical group characteristics, which are only supported by scripts directly processed by the Enrichment Agent and the Decision Agent. Usage in an unsupported context will result in a deployment failure.
Parameter or Return Data Type Description

<ldm array>

Array of an LDM

A reference to a fixed-size or dynamic array of a Logical Data Model.
<characteristic> Numeric or String A reference to a <characteristic> which must be held within the <ldm array>, not in a subordinate Logical Data Model. This is the <characteristic> that the MEAN will be executed against.

<bound>

Numeric (Integer)

A reference to a characteristic; a literal; or an expression that equates to an integer value. It must have a value of between 1 and the size of the array. It may be used to limit the number of elements in the array that are tested for the maximum value. For example, if the array has a size of 12 and <bound> is set to 10, then the MEAN function will only test the first 10 elements.

Return

Numeric

The mean value of the elements in the LDM array.

Remarks

Currently dynamic arrays are only supported by scripts directly processed by the Enrichment Agent and the Decision Agent. For further details about the use and restrictions of dynamic arrays, see the Arrays topic in the Arrays topic in the Experian Domain Scripting Language (EDSL) User Guide. Dynamic arrays are not supported by the Scoring Function and Transformation Function components.

The result can be stored in a numeric characteristic; passed as an argument into another function; or used as part of an expression.

The <bound> parameter specifies the upper element limit in an array. This is useful for arrays that contain sequential information such as the balance information for each month of a year, where it may be required to only find the mean value for a shorter period than a year.

The mean value for the whole array can be obtained by using the Size function to set the <bound> value to the size of the array. For further information, see the Size topic in the Experian Domain Scripting Language (EDSL) User Guide.

The function should not be used on uninitialised arrays otherwise an error will be produced.

Rounding is automatically applied to the nearest multiple if required. If the mean is midway between an upper and lower multiple, the mean is rounded up to the upper multiple. For example, a mean value of 10.5 would be rounded up to 11.

The function cannot be used with Date or String arrays.

It is recommended that the MEAN function is used instead of the deprecated AVGLASTN function used by CMDS.

If the MEAN function is used in a Behavioural History Update Script, Behavioural Script or a User Defined Behavioural Function, the Customer Management runtime traps any on size error or divide by zero error and defers the record (known as a Behavioural Variable Deferral or BVD). An on size error occurs if the absolute value of the result of an arithmetic evaluation, after decimal point alignment, exceeds the largest value that can be contained in the result field.

Examples for MEAN ( <array>, <bound> )

 

The following example uses an array called Example.Integerarray which has 3 elements containing the values 5, 40 and 15 respectively. The MEANfunction is used to return the maximum value for all elements by using the Size function to set the <bound> parameter. The result is 20 and is stored in the Integer characteristic called Example.Meanvalue.

'Example.Meanvalue' = MEAN('Example.Integerarray', SIZE('Example.Integerarray'))

Examples for MEAN( <ldm array>, <characteristic>, <bound> )

 

The following example uses an LDM array called Applicant which contains an applicant's income information. The MEAN function calculates the mean income over all applicants using a <bound> defined based on the size of the LDM array. The result is stored in Application LDS.Mean Income.

'Application LDS.Ave Income' = MEAN('Application LDS.Applicant', 'Application LDS.Applicant'[1].'Income',SIZE('Application LDS.Applicant') )

  The characteristic being assessed, 'Application LDS.Applicant'[1].'Income', refers to the first element in the LDM array. However, any of the elements in the LDM array can be used.

 

The following is an invalid example in which the income characteristics are not a direct child of the Applicant LDM.

'Application LDS with Two Level LDM.Ave Income' = MEAN ('Application LDS with Two Level LDM.Applicant','Application LDS with Two Level LDM.Applicant'[1].'Applicant Information.Income', 6)
Median (Returns the middle value in the array)

Median

The MEDIAN function returns the median or middle value of the values held in a numeric array.

Palette availability

Syntax

MEDIAN( <array>, <bound> )

 

 

 

 

 

 

Parameter or Return Data Type Description

<array>

Numeric array

A reference to a fixed-size or dynamic array.

<bound>

Numeric (Integer)

A reference to a characteristic; a literal; or an expression that equates to an integer value. It must have a value of between 1 and the size of the array. It may be used to limit the number of elements in the array that are used to calculate the median value. For example, if the array has a size of 12 and the <bound> is set to 10, then the MEDIAN function will only use the first 10 elements.

Return

Numeric

The median value for the array.

Remarks

Currently dynamic arrays are only supported by scripts directly processed by the Enrichment Agent and the Decision Agent. For further details about the use and restrictions of dynamic arrays, see the Arrays topic in the Experian Domain Scripting Language (EDSL) User Guide. Dynamic arrays are not supported by the Scoring Function and Transformation Function components.

The result can be stored in a numeric characteristic; passed as an argument into another function; or used as part of an expression.

The <bound> parameter specifies the upper element limit in an array. This is useful for arrays that contain sequential information such as the balance information for each month of a year, where it may be required to only find the median value for a shorter period than a year.

The median value for the whole array can be obtained by using the SIZE function to set the <bound> value to the size of the array. For further information, see the Size topic in the Experian Domain Scripting Language (EDSL) User Guide.

If an even number of elements is used the median value is rounded up, i.e. the two middle numbers are added together, divided by 2, and rounded up.

The function should not be used on uninitialised arrays otherwise an error will be produced.

The function cannot be used with Date or String arrays.

Examples

The following example uses an array called Example.Integerarr which is assumed to have a size of 11 and contains the following values: 3, 7, 5, 21, 23, 39, 23, 40, 23, 14 and 12. The MEDIAN function is used to return the median value for all elements by using the Size function to set the <bound> value. The result is 21 and is stored in the Integer characteristic called Example.Medianvalue.

'Example.Medianvalue' = MEDIAN('Example.Integerarr', SIZE('Example.Integerarray'))

The following example uses an array called Example.Integerarr which is assumed to have a size of 12 and contains the following values: 3, 7, 5, 13, 20, 23, 39, 23, 40, 23, 14 and 12. The MEDIAN function is used to return the median value for all elements by using the Size function to set the <bound> value. The result is 17 and is stored in the Integer characteristic called Example.Medianvalue.

'Example.Medianvalue' = MEDIAN('Example.Integerarr', SIZE('Example.Integerarray'))

Mode (Returns the most common value in the array)

Mode

Palette availability

The MODE function returns the first most common value in a numeric array. Parameters are also available for capturing the number of modes and their values.

Syntax

MODE( <array>, <bound>, <modality>,
<modalValues> )

 

Parameter or Return Data Type Description

<array>

Numeric array

A reference to a fixed-size or dynamic array.

<bound>

Numeric (Integer)

A reference to a characteristic; a literal; or an expression that equates to an integer value. It must have a value of between 1 and the size of the array. It may be used to limit the number of elements in the array that are used to find the mode(s). For example, if the array has a size of 12 and the <bound> is set to 10, then the MODE function will only use the first 10 elements.

<modality>

Numeric (Integer)

A reference to an Integer characteristic. This is used by the MODE function to store the number of modes found in the array.

<modalValues>

Numeric array

A reference to the fixed-size or dynamic array. This is used by the MODE function to store the value of modes found in the array.

Return

Numeric

The first mode found in the array, i.e. the one with the lowest value.

Remarks

Currently dynamic arrays are only supported by scripts directly processed by the Enrichment Agent and the Decision Agent. For further details about the use and restrictions of dynamic arrays, For further details about the use and restrictions of dynamic arrays, see the Arrays topic in the Experian Domain Scripting Language (EDSL) User Guide. Dynamic arrays are not supported by the Scoring Function and Transformation Function components.

The result can be stored in a numeric characteristic; passed as an argument into another function; or used as part of an expression.

The <bound> parameter specifies the upper element limit in an array.

The mode values for the whole array can be obtained by using the SIZE function to set the <bound> value to the size of the array. For further information, see the Size topic in the Experian Domain Scripting Language (EDSL) User Guide.

The function should not be used on uninitialised arrays otherwise an error will be produced.

The function cannot be used with Date or String arrays.

As MODE has a number of optional parameters (i.e., bound, modality, and modalValues) the following example will explain this function more clearly:

Where there is more than one most common value in the array, the first value (in ascending order) will be returned. A modality characteristic can optionally be entered to show how many most common values were found. A modalValues array characteristic can be entered to show what those most common values are.

 

If you write

'Most Common Value' = MODE ('Array 1', 100, 'How Many Values', 'Values' )

The script will evaluate the most common value in the first 100 values for 'Array 1'. In 'Array 1' there are two most common values; 215 and 400.

The values returned would therefore be:

'Most Common Value' = 215

'How Many Values' = 2

'Values' = 215, 400

Example

The following example uses an array called Example.Integerarr which is assumed to have a size of 12 and contains the following values: 3, 7, 5, 13, 20, 23, 39, 39, 40, 23, 14 and 12. It can be seen from these values, that there are two modes 23 and 39, i.e. it is bimodal.

The MODE function is used to return the modes for all elements by using the SIZE function to set the <bound> value.

The return value is 23 and is stored in the Integer characteristic called Example.FirstMode. The Integer characteristic Example.NumModes is used by the function to store the number of modes found, i.e. 2.

The Integer array Example.ModeValues is used by the function to store the value of each mode: i.e. 23 and 39.

'Example.FirstMode' = MODE('Example.Integerarr', SIZE('Example.Integerarray'), 'Example.NumModes', 'Example.ModeValues')

Std (Returns the standard deviation of the values held in the array)

Std

Palette availability

The STD function returns the standard deviation for the values in a specified numeric array.

Syntax

STD( <array>, <bound> )

 

 

 

Parameter or Return Data Type Description

<array>

Numeric array

A reference to a fixed-size or dynamic array.

<bound>

Numeric (Integer)

A reference to a characteristic; a literal; or an expression that equates to an integer value. It must have a value of between 1 and the size of the array. It may be used to limit the number of elements in the array that are used to calculate the standard deviation. For example, if the array has a size of 12 and the <bound> is set to 10, then the STD function will only use the first 10 elements.

Return

Numeric

The standard deviation for the array.

Remarks

Currently dynamic arrays are only supported by scripts directly processed by the Enrichment Agent and the Decision Agent. For further details about the use and restrictions of dynamic arrays, see the Arrays topic in the Experian Domain Scripting Language (EDSL) User Guide. Dynamic arrays are not supported by the Scoring Function and Transformation Function components.

The result can be stored in a numeric characteristic; passed as an argument into another function; or used as part of an expression.

For the Behavioural History Update Script, Behavioural Script, User Defined Behavioural Script components, the STD function is limited by months since open. History record elements are initialised to zeroes. This means the STD function can include all History elements up to the number of months since open even when the History hasn't been stored yet.

The <bound> parameter specifies the upper element limit in an array. This is useful for arrays that contain sequential information such as the balance information for each month of a year, where it may be required to only find the standard deviation for a shorter period than a year.

The standard deviation for the whole array can be obtained by using the SIZE function to set the <bound> value to the size of the array. For further information, see the Size topic in the Experian Domain Scripting Language (EDSL) User Guide.

The function should not be used on uninitialised arrays otherwise an error will be produced.

The properties of the characteristic used to store the return value must also be set to values that are appropriate to the expected returned data.

If the STD function is used in a Behavioural History Update Script, Behavioural Script or a User Defined Behavioural Function, the Customer Management runtime traps any on size error or divide by zero error and defers the record (known as a Behavioural Variable Deferral or BVD). An on size error occurs if the absolute value of the result of an arithmetic evaluation, after decimal point alignment, exceeds the largest value that can be contained in the result field.

Example

The following example uses an array called Example.Integerarrwhich is assumed to have a size of 12 and contains the following values: 12, 7, 5, 13, 20, 23, 39, 23, 40, 23, 14 and 12. The STD function is used to return the standard deviation for all elements by using the SIZE function to set the <bound> value. The result is 11.234 and is stored in the Float characteristic called Example.Std. This characteristic has a length of 6 and a scale of 3.

'Example.Std' = STD('Example.Integerarr', SIZE('Example.Integerarray'))
