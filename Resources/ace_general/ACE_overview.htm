ACE Framework overview

The Analytic Component Extensions (ACE) framework has been created to enable decision process extension capability for integrating third party technologies such as Machine Learning in PowerCurve.

This is achieved via the creation of plugins which allows the use of models built upon different Machine Learning platforms, supporting different deployment methods.

Plugins

Plugins are extensions of studio and server functionality, created externally to the design studios. Specifically, plugins introduce new components which can be used in Decision Process Flows.

  For example, when a plugin is installed in a studio, it can be used to support the import of models.

Each plugin installed in a studio will introduce its own components:

  1. Definition component
  2. Executor component
Definition component overview

Within the studio, the Definition component defines and represents a specific model or collection of models, and other supporting files, created in the associated analytic platform/deployment format, for example, PMML. This includes information such as:

  • one or more model files, for example, a model and script.
  • metadata about the model, for example, external version and model type.

To create a Definition component, users specify one or more model files, such as a model and script, which can be imported into the repository.

The Definition component displays metadata about the model. This information could include external version, model type, summary information, variables and data types.

Definition components can be assigned to Executor components for use in Decision Process Flows.

Executor component overview

The Executor component executes a model. It represents an instance of a model for use within a Decision Process Flow.

Users assign a Definition component to the Executor component. This allows variables referenced in the Definition component to be mapped within the Executor. The Executor can then be used within a Decision Process Flow to apply the model and generate outputs such as scores, predictions, estimations or classifications for use downstream in the decision strategy.

Executor components:

  • use the content of the Definition component, as described above.
  • display variables referenced in the Model Definition, including inputs, outputs and interim results.
  • map model inputs and outputs to corresponding logical characteristics on the logical data model.
  • are used as required in the Decision Process Flow.
