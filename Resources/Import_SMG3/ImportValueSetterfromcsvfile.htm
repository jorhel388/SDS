Import Value Setter from .csv file

The Value Setter Import functionality allows users to create a Value Setter from an imported .csv file. The import process creates an embedded segmentation tree.

Import
  You can only import data into a folder if it is one of the allowed component types for that folder. For example, if you want to import Logical Data Models, then Logical Data Models must be among the component types allowed for that folder. See Manage Allowed Component Types for more information on this subject.

To import a value setter

  1. From the Explorer window, right click on a folder and select Import.
    The Import wizard is opened. The Select import source screen is displayed.
  2. Locate and select the .csv file to import.
  3. From the Files of type field, select Value Setter Format (*.csv).
  4. Click Next to display the Value Setter Configuration screen. This screen will be used to map the characteristics to the import file data:

  5. Use the Characteristics filters, if necessary, to identify and select a logical characteristic.

Characteristics filters

The following filters can be used to help the user to find and select characteristics from the set of logical characteristics in the Value Setter Configuration screen of the Wizard.

Filter for Data Types – Allows the user to limit the display of logical data characteristics to one or more types.

Select Characteristic – Type a word or part of a word next to the Search icon and the Select Characteristic dialog will focus in on a particular characteristic or set of characteristics.

Using the * wildcard will search all the available logical data sources to display any characteristic name and Logical Data Source name that contains the text. Matching is not case sensitive, so you could use * to match Applicant.Scores.Risk Score with Scor*risk for example.

  1. Click Automap. The Automap Characteristics dialog displays.

  2. Select which of the suggested mappings to add and which to discard.

  3. Click Accept. The Automap Characteristics dialog will close and the characteristics will be displayed in the Characteristic line of the import wizard.

  4. Map any additional characteristics that have not been picked up by the Automap Characteristics dialog to the data file by dragging and dropping characteristics from the Logical Characteristics chooser to the Characteristic line of the import wizard.

  1. If you are re-importing a Value Setter, you are given the option of overwriting the existing Value Setter or creating a new one:

    If you choose to create a new one, you will need to enter a new component name.

  1. Select the output columns to use in the Value Setter by selecting the appropriate checkbox. The selected columns will be highlighted in purple.

    The number of potential Class Set Splits is displayed below the Preview Window:

    As you select Output columns, this number will change. You can change the order of the columns to minimize the number of outcomes by clicking on a column header and dragging the column to the right or left.

      To achieve maximum efficiency you should ensure that the minimum number of outcomes is created from the input file. The number of outcomes is based on the order in which the class sets are used within the segmentation. The minimum number of outcomes is attained by having the Class Sets with the smallest number of values in the left column and those with the largest number of values in the right column.
  1. Click Next to display the Value Setter Others Segmentation Configuration screen.
  2. Select one of the options to set the value for 'Others'.
  1. Do Nothing - Sets the outcome segmentation value to Do Nothing (default).
  2. Undefined - Sets the outcome segmentation value to <<Undefined>>.
  3. User Defined - Allows you to manually enter the outcome for the 'Others' segmentation values. If no value is defined, the 'Others' value will be empty.
    1. When this option is selected, four more options appear - String, Integer, Float and Decimal. Enter data into at least one field.
    4.   Data entered into one of the User Defined fields is not validated.
      The date data type is not supported in the User Defined field.
      If no values are defined, by default the User Defined field will be empty.
  After import is complete, existing validation will be triggered for length of an empty value. Users should define the 'Others' value in the Value Setter.
  1. Click Next to display the Confirm choices screen. Review the name and location of the imported file.
  2. Click Next to display the Import job summary screen.
  3. Click Finish to import the Value Setter.

The import monitor is displayed on the bottom right of the screen:

To cancel the import process, click on the cancel button , and click Yes at the prompt.

When the import is finished, the Import complete message is displayed.

The imported Value Setter is listed under the folder in the Explorer window, with the same name as the input file name. The embedded segmentation tree will have the same name, with the prefix TREE_ attached to it.

Invalid input handling

Invalid input from the .csv file is handled in various ways by the import procedure. The following are typical invalid input scenarios:

1. Single or multiple input values are empty

 

In this example, the first row represents the table header, second row is record no1, third row is record no 2, etc. Here, record 1 in the second column is an empty string.

Col1,Col2,Col3
100,,a
200,SP,b
300,CK,c

  • The empty string value for the outcome name will be empty. This is because if the empty string is set as a 'null' value, and the input file had another input value defined as 'null', both outcomes will be grouped together and treated as a single outcome; but in fact they are referring to different outcomes.
  • Empty string values for the output characteristic values will be defined as 'Do Nothing'.

2. Space at the front or back of the input value

 

In this example, record 1 col2 value 'SK ' has a space as the last character; record 2 col2 value ' SP' has a space as the first character.

Col1,Col2,Col3
100,SK ,a
200, SP,b
300,CK,c

  • Field length validation will trim the space at the front and back. For example, " SK" is length of 3 (including space at the front), but the valid minimum length for a characteristic to map is a string characteristic with minimum length of 2.
  • If the value is for a class set interval, the value will be imported without space at the front and back. System will import successfully.
  • If the value is for an output characteristic -- for string/integer data type -- the value will be input without space.

    Class set intervals and output characteristic values will be input without space because Strategy Design Studio class set intervals and value setter's output characteristics do not accept space at the front and back of the input value.

3. Space in the middle of a number

 

In this example, record 1 col1 value '20 0' has a space in the middle of the number.

Col1,Col2,Col3
100,SK,a
20 0,SP,b
300,CK,c

  • Treat this input value "20 0" as string input value.

4. Unused value setter outcome (occurs when same segmentation outcome group with different output characteristic assignment)

 

In this example, assume Col3 will be uses as the output characteristic; for the sample input, note that records 2 and 3 have the same segmented outcome but with a different output characteristic assignment.

Col1,Col2,Col3
100,SK,a
200,SP,b
200,SP,c

  • System is able to import with an unused outcome. Note: When multiple similar segmented outcomes exist, the system always uses the first output characteristic as the used outcome. In the above example, the system will use 'b' as the used outcome for records 2 and 3. 'c' will be imported as an unused outcome in order to retain all the information from the import file.

5. Same segmentation outcome group, and same output characteristic assignment

  In this example, assume Col3 will be use as the output characteristic; for the sample input, note that records 2 and 3 have the same segmented outcome and the same output characteristic assignment
  • System will treat records 2 and 3 as a single record. In this case, only one value setter outcome will be generated.

6. Blank CSV file

  • System will not allow user proceed on to the next import step. An error message will be displayed.

7. Missing column header

 

In this example, there is no column name defined for second column.

Col1,,Col3
100,SK,a
200,SP,b
200,SP,b

  • System will not allow user proceed on to the next import step. An error message will be displayed.
