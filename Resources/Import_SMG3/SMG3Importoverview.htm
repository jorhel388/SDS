SMG3 Import

PowerCurve Strategy Design Studio supports the transition of Strategy Management Generation 3 (SMG3) users to the new version of Strategy Design Studio in two ways:

  • Users can import components from Strategy Design Studio v.1 for use in Strategy Design Studio v.2.x.
  • As in SMG3 users can create a value setter from an imported .csv file. (Value setters were known in SMG3 as action setters.)
 

Prior to importing an SMG3 solution into Strategy Design Studio, it is recommended that the SMG3 Duplicate Names Detector Tool is used to generate a CSV file that identifies any duplicate component names in their SMG3 xml solution. Using the generated CSV file, the user will need to use the SMG3 software to fix any duplicate component names found in it. Once corrected, the updated solution can be imported into PowerCurve Strategy Design Studio.

If a CSV file is not generated by the Tool, the user can import the SMG3 solution into PowerCurve as there are no duplicate component names in the solution being migrated.

The SMG3 - Duplicate Names Detector Tool can be accessed from the GPS Download Portal.
Component import overview

The components libraries are exported from Strategy Design Studio v.1 as a .xml file. The .xml file contains the latest version of all the components in the v.1 system.

 

SMG3 Import has only been certified for .xml files exported from Strategy Design Studio v.1.4 SP1.
 

Test Group Sets that are used within Segmentation Trees will not be imported, they will need to be created in another component tree once the import has been successful.

Objects in Strategy Design Studio v.1 are imported as components in Strategy Design Studio v.2.x by the SMG3 import process. See here for the one-to-one correspondence between components in Strategy Design Studio v.1 and those created in Strategy Design Studio v.2.x.

The import process requires the user to import components in a specific order, from the simpler components such as data models through to the more complex components such as matrices and policy rules, since the more complex components reference the simpler components. In this way the links between the various components are maintained.

Components should be imported in the following order:

  • Data Universe. Global and Business Area specific.
  • Index Tables
  • Class Sets
  • Matrices
  • Sub-populations
  • User Functions
  • Derived Data Scripts
  • Adverse Reason Codes
  • Scorecards
  • Decision Categories
  • Decision Reason Codes
  • Policy Rules
  • Policy Rule Sets
  • Segmentation Trees
  • Action Setters
  • Strategy Tables
  • Business Objective Flow

To facilitate the import process, two sets of templates are provided with the Strategy Design Studio v.2.x Content Gallery. One set of templates enables the user to recreate the folder structure found in Strategy Design Studio v.1, so components can be imported in a one-to-one correlation. These are identified by the "G3 Solution" in the name. In this case, the new Strategy Design Studio v.2.x project will mirror the original v.1 structure. Please see the Import SMG3 components using SDS v.1 solution structure help topic for more information. The second set of templates enables the user to create a structure that follows the v.2.x design philosophy, where components are grouped together logically. Please see the Import SMG3 components using SDS v2.x solution structure help topic for more information. All templates include all publishing rules and allowed component type settings for all folders.

  To consume solution templates the user is required to have Architect permissions, as they will be creating folders when applying templates.

The SMG3 Import process follows a similar path in either case: Components are imported into each folder in turn from the Strategy Design Studio v.1 .xml file; only allowed component types are imported into each folder.

Value Setter import overview

The Value Setter Import functionality allows users to create a value setter from an imported .csv file. The import process automatically creates an embedded segmentation tree and creates one class set per import column.

Any number of columns may be included in the import, and the order of the columns may be moved around during the import process if it is not possible to configure the .csv file in the desired order. The ability to re-order the columns allows the user to create the most efficient segmentation tree.

.csv import rules

The following rules apply to importing a .csv file as a value setter in Strategy Design Studio v.2.x:

  • Within the import, the column headers (effectively) become the class sets used to segment the data, with the range of values in each column representing the class set values. An "Others" category is automatically included with each.
  • Any number of input columns may be included, with the column on the left representing the first segmentation, the next column to the right the second, and so on. Maximum efficiency for the Segmentation Tree is achieved by creating the minimum number of outcomes.
  • At least one column must be designated as an output characteristic and all outputs must be located to the right of any inputs. All columns must be mapped to a characteristic.
  • If a column consists of numeric only input, the user may map it to a numeric characteristic or a string characteristic.
  • For a numeric column type mapping, the minimum requirement is that the logical data source characteristic’s length must be equal or greater than the target column’s length, and the characteristic’s scale length must be equal or greater than the target column’s scale.
  • In practice, it will be easier to use the import facility if the columns of the .csv file are constructed in the order that the data is to be segmented. If this is not possible then the columns may be moved during the import process itself.
