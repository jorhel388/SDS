Annotation Model editor

The Annotation Model editor enables the user to map Logical Data Source characteristics to Annotation Templates that, depending on the Annotation Template mapped, at deployment will enrich the characteristics' meaning and facilitate their use in the solution.

  If the user does not have a solution or capability that contains annotation sets, then no Annotation Sets will be available in the Resources window for use in the Annotation Model.

The Annotation Model editor consists of:

Annotation Set - group of Annotation Templates that have been assigned for use in the Annotation Model. Expanding the System Annotation Sets tree in the Palette window will show a list of the available Annotation Sets.

Logical Characteristics - list all the available Logical Data Source characteristics that can be mapped to an Annotation Template. The Logical characteristics tree/table displays all the Logical Data Sources that are published to the node in the system composition where the Annotation Model component has been created. Use the filters to identify the Logical Data Source characteristics to map to the Annotation Template.

Select Logical Data Sources – select to open the Logical Data Source Select dialog from where the user can limit the number of Logical Data Sources displayed. The Select Logical Data Sources icon will indicate when the number of Logical Data Sources displayed has been reduced.

Show Table View – toggle display of logical characteristics between tree or table view. The table view shows the full characteristic name, including path name:

Annotation Templates - once an Annotation Set has been assigned to the Annotation Model, all the Annotation Templates that have been created in the set will be listed and available for selection.

Annotations - once an Annotation Template has been mapped to a Logical Data Source characteristic it will be listed in the Annotations area of the Annotations Model editor. The default value that was assigned to this template will be listed in the Value field. The user can amend this default value by entering a new value in this cell, however this new value still needs to comply with the regular expression pattern defined for this Annotation Template in the Annotation Set.

Filters

Two sets of filters can be used to help the user find and select characteristics from the set of logical characteristics

Filter for Data Types – Allows the user to limit the display of characteristics to one or more types. The Filter for Data Types icon will indicate when the range of characteristic types displayed has been narrowed down.

Filter by Characteristic Name – Type a word or part of a word next to the Search icon and the Select Characteristic dialog will only display those characteristics whose names match the entered text. Name filtering includes the full logical name of the characteristics; for example, the characteristic Applicant.VIP will show up if the user enters 'A' or 'a' because it's present in 'Applicant'.

A wildcard (*) can be used to match any characteristics or sequence of characteristics, usually with other characters. For example, ‘Scor*risk’ will match ‘Applicant.Scores.Risk’ or ‘Applicant.Scores.Risk2’

Map button - select to map the characteristic(s) to the annotation template. The new Annotation(s) will be listed in Annotations.

 

Not all Annotation Sets are assigned with a default value. The value is disabled for Annotation Sets which are created for displaying data, such as the Audit Trail and PCI Sensitive Annotation Sets. When these sets are used, the defined value in the Annotation Model will be ignored because the Annotation Set is used to define the captured value to be displayed or how to display the data.
