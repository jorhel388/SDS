Functional Roles

Functional roles are created to control a user's permissions to perform specific actions related to component types within an allowed part of the repository.

Functional role options are List, Read, Create, Update, Delete, Exclude and Custom.

Role option Description

List

Users can see the names of the component in the repository as a list.

User can see the names of the component as a list in the Explorer view.

Read

Users can access the contents of the component in the repository.

Users can open an appropriate editor for the component and edit and save the contents in their user area.

Users can not commit their changes to the shared Repository or lock the version in the Repository

Users can print the component.

Users can test, validate, search and use where used.

Users can carry out most actions on components, they just can't apply any changes back to, or change the state of the component in the Shared Repository.

Create

Users can create new instances of the corresponding component in the user area and save components.

User can import components.

Update

Users can update changes to the corresponding component that exists already in the repository.

Users can save the changes and check them into the shared repository.

User can Lock components.

Users cannot create a new instance of the component.

Users can select to Hide a component.

Users can select to Show a previously hidden component.

Delete

Users can delete components from the repository.

Exclude

User will be prohibited from the component or folder.

Exclude takes precedence over any other permission assigned to the component or folder.

Custom

Users will be able to carry out the capability listed in the dialog (Depending on the component selected).

Once a functional role has been set up, it must be assigned to a security profile.

The functional roles of Architect and Solution Administrator are predefined and can be merged with other functional roles in a security profile. The Architect functional role should be assigned to users who need access to add or modify folders. The functional role of Solution Administrator is reserved for unlocking components locked by other users.

  Only users with the Security Administrator Profile will have access to the edit functions in the Security Explorer window.

A sysadmin user or any user that has had the Security Administrator profile assigned to it can set up functional roles, assign functional roles to security profiles, view functional roles and their permissions, edit functional roles and their permissions and delete functional roles from within the Functional Roles folder.

The following actions require specific functional role permissions:

Action Required functional role permission

Copy

Read

Validate

Read

Print

Read

Paste

Read

Export

Read

Import into a folder

Create

Lock

Update

Create a solution template

Read in the Solution Repository and Create in the Content Repository

Consume a component template

Read in the Content Repository and Create in the Solution Repository
