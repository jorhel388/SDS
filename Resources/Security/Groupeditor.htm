Groups editor

The Groups editor allows the system administrator (sysadmin) or a user assigned the Security Administrator Profile to view and manage group accounts. The editor is opened from the Groups folder in the Security Explorer window. To open the editor, right click on a group account and select Open.

The Groups editor consists of the following tabs:

General

The General tab displays the group information and allows the user to manage the group account description, and unit fields.

The General tab consists of the following:

  • Group Name - displays the group account name (read only).
  • Description - allows descriptions or additional information relating to the group account to be added.
  • Unit - displays the unit assigned to the group account (for example, Italy) or an empty value, if the group has not been assigned to a unit.
    •  

    The Unit drop down list is only available to the system administrator (sysadmin) or a user with the Security Administrator Profile that has not been assigned to a unit.

    A user with the Security Administrator Profile that has been assigned to a unit will only see a read only value.
     

    A group account that has been created by a user with the Security Administrator Profile and assigned to a unit will automatically inherit the unit that has been assigned to the user.
Advanced

The Advanced tab displays the security profiles and user accounts that are assigned to the group account. It also allows the user to manage the accounts (add or remove).

  The Palette window displays the available accounts that can be dragged and dropped into the required field.

The Advanced tab consists of the following:

  • Security Profiles - displays the security profile accounts that have been assigned to the group account
    •  

    When assigning a security profile to a group, the system will evaluate if both the security profile and group accounts have the same unit. If there is a unit mismatch, an error will be displayed when saving (Ctrl+S).
  • Users - displays the user accounts that have been assigned to the group account.
    •  

    When assigning a user to a group, the system will evaluate if both the user and group accounts have the same unit. If there is a unit mismatch, an error will be displayed when saving (Ctrl+S).
External Matching

The External Matching tab allows the matching of external groups (for instance using the unique group SID from an Active Directory) to an internal group account, facilitating the single sign-on and LDAP authentication functions.

The External Matching tab consists of the following:

Applied External Groups:

  • - opens the Add New LDAP Mapping dialog
  • - opens the Add New NTLM Mapping dialog
  • - opens the selected external group in its dedicated dialog (Edit LDAP Mapping or Edit NTLM Mapping dialog)
  • Information area - displays the applied external group and its description in brackets, if any. For example, (ABC).

For information on how to manage an applied external group, refer to the Add or edit an External Group topic.

 

If a user logs in externally, using the NTLM method or using the LDAP authentication functions, the permissions that they will have will be the combination of the internal groups and profiles assigned directly to their internal user profile and the permissions of the internal groups that are mapped to their external group's IDs (called SID).

 

Direct LDAP mapping between an external and internal user is not permitted. LDAP mapping can only be done between an external and internal group.
 

An external LDAP user will log in successfully if the internal groups mapped to their LDAP groups have the same unit. An authorization error will be displayed if there is any mismatch in the units assigned to their internal groups. For details on the authorization error, refer to the studio log file.
 

When a user with external LDAP credentials logs into the studio for the first time, a new internal user account will be created automatically.

The internal user account will be displayed in the Users folder (for example, <LDAP server name> /<User Name>). The internal user account will inherit the unit assigned to the internal group that has been mapped to the LDAP group to which the LDAP user belongs.

The unit assigned to the user is displayed in the User editor as read only. Since the unit assigned to the user has been inherited from the internal group, any saved changes (for example, reassigned to another unit or removed the assigned unit) made to the unit in the Group editor will be automatically inherited by the user account. The change will take effect the next time the LDAP user logs in.
 

NTLM mapping is permitted between an external and internal user as well as between an external and internal group.
 

An external NTLM user will log in successfully if the internal user and/or groups mapped to their NTML user and/or groups have the same unit. An authorization error will be displayed if there is any mismatch in the units assigned to their internal user and/or internal groups. For details on the authorization error, refer to the studio log file.
 
 

NTLM - stands for NT LAN Manager. The NTLM authentication mode allows for authenticating users by using their Windows user accounts, without the need to specify a username and password. NTLM mode is used to facilitate the Single-Sign-On experience in the Decision Analytics Server environment.

 

LDAP - stands for Lightweight Directory Access Protocol, which is a protocol for communicating with directory servers such as Active Directory or OpenLDAP. LDAP authentication mode allows for authenticating with the external user directory instead of the built-in security repository.

 

SID - stands for Security ID. This is globally-unique identifier specific for Microsoft Active Directory. Each object residing in Active Directory is assigned with such an ID.
