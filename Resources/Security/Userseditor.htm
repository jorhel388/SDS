Users editor

The Users editor allows the system administrator (sysadmin) or a user assigned the Security Administrator Profile to view and manage user accounts. The editor is opened from the Users folder in the Security Explorer window. To open the editor, right click on a user account and select Open.

The Users editor consists of the following tabs:

General

The General tab displays the user information and allows the user to manage the user account, full name and unit fields.

The General tab consists of the following:

  • User Name - displays the user account identifier (read only). The user name is used at the login screen.
  • Full Name - allows the user to enter the full user name or additional information relating to the user account. This field is only for information and is not used in any authorization process.
  • Unit - displays the unit assigned to the user account (for example, France) or an empty value if the user has not been assigned to a unit.
    •  

    The Unit drop down list is only available to the system administrator (sysadmin) or a user with the Security Administrator Profile that has not been assigned to a unit.

    A user with the Security Administrator Profile that has been assigned to a unit will only see a read only value.
     

    A user account that has been created by a user with the Security Administrator Profile and assigned to a unit will automatically inherit the unit that has been assigned to the user.
Advanced

The Advanced tab allows the user to manage user properties.

  The Palette window displays the available accounts that can be dragged and dropped into the required field.

The Advanced tab consists of the following:

  • User Email Address - can be used to update the user's email address.
  • User Information - can be used for additional user information.
  • Group - displays groups that have been assigned to the user
    •  

    When assigning a group to a user, the system will evaluate if the group and user accounts share the same unit. If there is a mismatch, an error will be displayed when saving (Ctrl+S).
  • Security Profiles - displays security profiles that have been assigned to the user
    •  

    When assigning a security profile to a user, the system will evaluate if the security profile and user accounts share the same unit. If there is a mismatch, an error will be displayed when saving (Ctrl+S).
Policy

The Policy tab allows the user to manage the password expiration periods, account expiration date and account status.

The Policy tab consists of the following areas:

  • Password Change Frequency
    • Password Never Expire - when checked, no password expiry date will be assigned to the password.
    • Password Change Period (in days) - allows the user to set the password expiry period in terms of days (99 is the maximum number of days allowed). The default setting is 28 days and can be customised in the Global Security Settings folder.
    • Password Due to Expire on - displays the password expiry date (read only). If the icon is present, the password has already expired.
    • Date of Last Password Change - displays the date when the password was last changed (read only).
  • Account Expiration
    • Account Never Expires - when checked, the account will never expire.
    • Account Expiry Date - allows the user to set an account expiry date.
  • Account Status
    • Account Locked - when checked, the account will be locked (the default setting is unlocked). If the account is locked, information on why the account is locked will be displayed, for example if the account has been locked by the system administrator or if the user has unsuccessfully logged in too many times.
External Matching

The External Matching tab allows the user to add or edit existing external matches, enabling the single sign-on function.

The External Matching tab consists of the following:

Applied External Users:

  • - opens the Add New NTLM Mapping dialog
  • - opens the selected external user in the Edit NTLM Mapping dialog
  • Information area - displays the applied external users ID and its description in brackets, if any. For example, (ABC).

For information on how to manage an applied external user, refer to the Add or edit an External User topic.

Last Used External Groups - this area contains two table columns, Last Used External Group IDs and Corresponding Internal Groups Unique Names. When a user logs in using the single sign-on method or LDAP method, groups that have been assigned to the external user profile are checked. If one or more of these groups has a SID which is mapped to an internal group, then the permissions assigned to this internal group will be applied to the user. The table lists only those external SIDs which have been mapped to an internal group for this particular user.

  If a user logs in externally, using the single sign-on or LDAP method, the permissions that they will have will be the combination of the internal groups and profiles assigned directly to their internal user profile, and the permissions of the internal groups that are mapped to their external groups SIDs.
 

If a user logs in externally, using the NTLM method or using the LDAP authentication functions, the permissions that they will have will be the combination of the internal groups and profiles assigned directly to their internal user profile and the permissions of the internal groups that are mapped to their external group's IDs (called SID).

 

If the user logs in internally (using the login dialog), the permissions that they will have will be only from the internal groups and profiles assigned directly to their internal user profile.
 

NTLM mapping is permitted between an external and internal user as well as between an external and internal group.
 

An external NTLM user will log in successfully if the internal user and/or groups mapped to their NTML user and/or groups have the same unit. An authorization error will be displayed if there is any mismatch in the units assigned to their internal user and/or internal groups. For details on the authorization error, refer to the studio log file.
 

NTLM - stands for NT LAN Manager. The NTLM authentication mode allows for authenticating users by using their Windows user accounts, without the need to specify a username and password. NTLM mode is used to facilitate the Single-Sign-On experience in the Decision Analytics Server environment.
 

LDAP - stands for Lightweight Directory Access Protocol, which is a protocol for communicating with directory servers such as Active Directory or OpenLDAP. LDAP authentication mode allows for authenticating with the external user directory instead of the built-in security repository.
 

SID - stands for Security ID. This is globally-unique identifier specific for Microsoft Active Directory. Each object residing in Active Directory is assigned with such an ID.
