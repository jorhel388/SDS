Audit Trails editor

The Audit Trails editor allows the user to monitor the following event types:

  • Login Success – the user has logged into the system successfully.
  • Login Failure – the user has failed to log in due to wrong credentials, for example, username or password.
  • Logout Success – the user session has been closed successfully.
  • Logout Failure – the user session has failed to close due to, for example, the session was not present, it may have expired or could have been terminated by a security administrator.
  • Session killed by admin – the user session has been closed by a security administrator.
  • Password change - a change of the password forced by a password expiration, user's own initiative or security administrator initiative.
  • Session expired – the server has terminated the session because it has expired. The default session time out is 8 hours. It can be configured in the hazelcast.xml file. For more information, refer to the topic Distributed Cache in the Decision Analytics Servers Advanced Technical Guide.

  • Security Setup Change – describes all the changes in the user-group association (relation between the user and the group entities), roles or policy.

  • User permissions invalidated – user permissions have been invalidated due to a change in the user security setup.
  • User permissions recomputed – invalid permissions are being re-calculated. The action takes place on demand, for example, when the permissions are requested for the first time after invalidation.
  • Purge Event – a security administrator has deleted the audit trail or an inactive user has been deleted from the studio.
    •  

    A number of properties have been introduced that control whether inactive accounts are automatically cleaned up after a specific period of activity. In the Design Studio, by default this feature is disabled.

    For more information on configuring these properties refer to the Decision Analytics Servers Configuration Guide.

      Purge Events cannot be deleted from the Audit Trail.
  • Request Password Reset – the procedure for resetting the sysadmin password has been triggered.

    All of the above can be filtered for a date and time period and viewed in the Audit Trails editor. A user can also specify advanced filtering options to an audit trail from within the editor.

     

    Only users with the Security Administrator Profile will have access to the edit functions in the Security Explorer window.

    A user without the Security Administrator Profile assigned can access the Audit Trails editor but they can only view audit trails of their own activities. This user is also limited to only apply a filter period or reset the filter for their audit trail.

The Audit Trails area can be found in the Security Control Centre folder from the Security Explorer window.

The Audit Trails editor consists of the following areas:

Advanced filtering options - where the user can specify and apply a filter to the audit trail. For more information, refer to the topic Apply Advanced filtering options to the Audit Trails Table.

Filter Period - where the user can specify and apply a filter period or reset the filter for the audit trail. For more information, refer to the topic Apply a Filter Period to the Audit Trails Table.

Audit trails table columns - where the user can view the filtered data. Audit data can be exported using the Export Data functionality (available only to users with the Security Administrator profile). For information on how to export audit data, refer to the Managing audit trails data section in the Security Administrator Getting Started Guide.

 

JSF stands for Job Server Framework, an alias of the Job Server. The audit trail shows the sub-system to which the event relates, so if the Design Studio column displays JSF this means the Job Server.

Page selection, Refresh Data area, Export Data and Delete Data area - where the user can:

  • choose a page to display and the amount of items per page in the Audit Trails Table
  • choose to refresh the data in the Audit Trails Table (the Audit Trails Table displays a static view; click on the Refresh Data button to gain a real time view)
  • choose to export the data from the Audit Trails table in preparation for housekeeping or to be able to manipulate it in another package
  • choose to delete the data from the Audit Trails table for housekeeping purposes

    •   The Export Data and Delete Data buttons are only available to users who have accessed this editor using the Security Administrator Profile.
