Functional Roles editor

The Functional Roles editor allows the system administrator (sysadmin) or a user assigned the Security Administrator Profile to view and manage functional role accounts. The editor is opened from the Functional Roles folder in the Security Explorer window. To open the editor, right click on a functional role account and select Open.

The functional role of the Architect and Solution Administrator are predefined and can be merged with other functional roles in a security profile. For further information on the permissions assigned to these roles, refer to the Functional Roles Permissions topic.

The Functional Roles editor consists of the following fields and tabs.

Fields:

  • Role Name - displays the functional role account name (read only)
  • Description - can be used for additional functional role information
  • Unit - displays the unit assigned to the functional role account (for example, France) or an empty value if the functional role has not been assigned to a unit
    •  

    The Unit drop down list is only available to the system administrator (sysadmin) or a user with the Security Administrator Profile that has not been assigned to a unit.

    A user with the Security Administrator Profile that has been assigned to a unit will only see a read only value.
     

    A functional role that has been created by a user with the Security Administrator Profile and assigned to a unit will automatically inherit the unit that has been assigned to the user.
  • Repository Type (read only) - displays the repository type that is applicable to the functional role
  • Category - allows the user to filter the view in both the Preview and Component Permissions tabs using the drop down list. The category list is related to the selected repository type.

Preview tab (read only) - consists of table columns that display the component types and permissions granted to each component (permissions can be edited in the Component Permissions tab).

Component type - displays the component types assigned to the selected category (set in the Category field)

Permissions Assigned:

  • - this functional role has permission to access the displayed component type
  • - this functional role does not have access to the displayed component type

Permissions - displays permissions granted to the functional role per component type

Component Permissions tab - consists of table columns that display the component types and their permissions that are assigned to the functional role. Permissions can be enabled () or disabled (). Refer to the Assign Component Permissions topic for more information.

  • Component type - displays the component types available in the selected category (set in the Category field)
  • List - enable or disable the functional role from seeing component names as a list in the repository and Explorer view
  • Read - enable or disable the functional role from accessing component contents in the repository, opening the dedicated component editor or printing the component
  • Create - enable or disable the functional role from creating new instances of the corresponding component in the user area, save and import components
  • Update - enable or disable the functional role from updating changes made to the corresponding component that exists in the repository, saving changes, lock and check components into the shared repository. Also if enabled, the role cannot create a new instance of the component
  • Delete - enable or disable the functional role from deleting instances of the corresponding component from the repository
  • Exclude - exclude or include the functional role from the corresponding component in its entirety. Exclude takes precedence over any other permission assigned to the component or folder.
  • Custom - exclude or include the functional role from carrying out the capability permission listed in the selected <component name> dialog.

Once a functional role has been set up, it must be assigned to a security profile.
