Swagger Client Library (SCL) and Server Connection Profile Key Configuration

The Swagger Client Library (SCL) configuration properties allows the set up of specific REST Call connection, authentication and authorisation settings.

The Studio scl.cfg files are located in the following paths:

  • For Interactive Tester
    • When testing a Business Process Flow component containing a REST Call, locate the file in <Job Server installation path>/conf/scl.cfg
    • When testing a Decision Process Flow component containing a REST Call, locate the file in <Studio installation path>/conf/scl.cfg
    • When testing ACE plugins containing a REST Call, locate the file in <Studio installation path>/conf/scl.cfg
    • When testing a REST call component, locate the file in <Studio installation path>/conf/scl.cfg
  • For Test Project
    • Locate the file in <Job Server installation path>/conf/scl.cfg
 

For Server Connection Profile, the <ClientKey> does not need to be specified as shown in the example below.

The similar configurations in the scl.cfg file are shown below.

scl.host.<ClientKey>= http://api.testserver.com

scl.authentication.type.<ClientKey>= FLEXI_AUTH

scl.authorization-server.token-endpoint.url.<ClientKey>=http://api.testserver.com/token

scl.auth.request.body.Authorization.<ClientKey>=abc

19 scl.auth.response.
cache.timeout-path.<ClientKey>		   FLEXI_AUTH

This key determines the token cache extraction from response body (from token endpoint call), if the response body contains the token timeout value.

 
  • A hard limit of 1 hour has been set for the cache time out. Any value set above the hard limit will reset back to 1 hour.
  • Some token servers does not return cache time out value.
  • The configuration only supports unit second. Some token servers does not return the value in second.
  • If both cache.timeout and cache.timeout-path are defined, the cache timeout-path will take precedence.

CSRF configurations
No. Property Mandatory? Description Valid values for Server Connection Profile (regular expression, not case sensitive)
1 scl.csrf.token.source.<ClientKey> No

This defines how to extract the CSRF token. The valid values are:

  • CUSTOM-HEADER - The value of the csrf.token.key property is used as CSRF token value. This value is used when the type of CSRF protection is custom header.
  • HEADER - An HTTP request is made to a CSRF token URL. The CSRF token is extracted from an header of the returned response.
  • COOKIE - An HTTP request is made to a CSRF token URL. The CSRF token is extracted from a cookie set by the returned response.
  • BODY - An HTTP request is made to a CSRF token URL. The CSRF token is extracted from the body of the returned response. The body should be in JSON format.
 
2 scl.csrf.token.key.<ClientKey> No

This defines the name of the placeholder to extract the CSRF token from. The content of this property depends on the value of scl.csrf.token.source property.

If the value of scl.csrf.token.source is:

  • CUSTOM-HEADER - this property contains the value of the CSRF token.
  • HEADER - this property contains the name of the header holding the CSRF token.
  • COOKIE - this property contains the name of the cookie holding the CSRF token.
  • BODY - this property contains the JSON pointer to the CSRF token. The JSON pointer syntax is defined in RFC6901.

Supported Authentications

The following sample configurations show the required properties for the different types of authentication.

Basic Authentication

scl.password.<ClientKey>=MyPassword

Bearer Authentication

scl.authentication.overwrite-swagger-definition.<ClientKey>=true

scl.authentication.type.<ClientKey>=APIKEY

scl.authentication.overwrite-swagger-definition.<ClientKey>=false
