Common REST API characteristics

This topic provides information relating to the Logical Data Model common REST API characteristics. These characteristics:

  • are part of the Logical Data Model created by the Swagger wizard within the Swagger component
  • must be present in the Logical Date Source used in the REST Call component
  • will store some system information following a REST call.

  • Original Code
  • Return Code
  • Description
  • Truncation Warning Count
  • Array Truncation Warning Count

The characteristic structure does not depend on the called service but will be present in all REST Calls.

The common REST API characteristics can be used in the Decision Process Flow within a solution to define the post-call action depending on the values received in these fields.

Original Code

The Original Code is the code send by the service. It should only be used for troubleshooting purposes and can also be seen in the logs at runtime. 

Return Code

The Return Code is the most important characteristic and it is used to define how to process the application further depending on the outcome, for example:

  • to proceed with the application if the call is successful
  • to reiterate the call in case of a communication error
  • to simply end the application

The Return code will contain a response from the calling service with a numeric value (for example, 200, 202, 300, 400, 404, 500) or it will return the text EXCEPTION to indicate communication errors, certificate related issues, etc. In both cases, the details will be provided in the Description characteristic.

 

The valid values of the Return Code characteristic and their corresponding description are created by the Swagger wizard, based on the information in the Swagger file with an additional entry named EXCEPTION.

 

 

The Value and Name of the valid values must be unique.

If not, the Logical Data Model (LDM) will fail the validation process despite the LDM and Logical Data Source (LDS) components being generated successfully.

Return codes are separated into several categories. The first digit of the code defines the class of response, while the last two digits do not have a categorisation role. Below are examples of the common categories:

  • 2XX Successful - the request was successfully received, understood and accepted
  • 4XX Client Error - the request contains bad syntax or cannot be fulfilled (for example, missing input, invalid input)

The Return Code can provide useful information for troubleshooting, refer to the table in the Troubleshooting section below for more information.

Description

The Description characteristic provides the details related to the corresponding Return Code.

 

The Description characteristic will be populated during runtime using either:

  • the description defined in the service provider specification (Swagger file)
  • the runtime error descriptions
Truncation Warning Count

The Truncation Warning Count characteristic counts the number of occurrences where the length of data being passed to a characteristic exceeds its length as defined in the Data Model.

A number that is larger than zero (0) indicates length validation issues and will require an investigation. Details of the truncation issues can be found in the IDE log (menu View > IDE log) or in the trace file. A Truncation Warning Count equal to zero or null indicates that there is no truncation warning.

For example, if you receive data of 30 characters for a characteristic that has been defined with a length of 10, this will trigger a +1 in the Truncation Warning Count.

Array Truncation Warning Count

The Array Truncation Warning Count characteristic counts the number of occurrences where the array index being passed to a characteristic or a Logical Data Model exceeds the array size as defined in the Data Model.

A number that is larger than zero (0) indicates array size validation issues and will require an investigation. Details of the array truncation issues can be found in IDE log (menu View > IDE log) or in the trace file. An Array Truncation Warning Count equal to zero or null indicates that there is no array truncation warning.

For example, if you receive data of 10 items for an array that has been defined with a size of 5, this will trigger a +1 in the Array Truncation Warning Count.

Troubleshooting

The table below show examples of category for troubleshooting.

Return Code Provider Description and Reasons Recommendations

2XX

Called Service

Used for a successful call.

 N/A
3XX Called Service Used for URL redirection and is not commonly used by REST service providers.

This code should not be used by the service provider. Contact your service provider for guidance.
4XX Called Service

Used for issues related to the Client Error.

Regarding the context and the Description characteristic of the code, you have several possible actions, as shown in the examples below:

  • If the code corresponds to a Missing Input or an Invalid Input - try to redesign the process and add validation before performing the call.
  • If the code corresponds to an Entry or Record not found - try to handle the Return Code in the flow of your solution.
  • For other codes, check your Description characteristic and, if necessary, contact your service provider for guidance.
