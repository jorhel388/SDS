Swagger Update wizard

The Swagger Update wizard allows users to update the Logical Data Model structure of services with changes defined in the attached Swagger definition file supplied by their Third-Party provider. These changes may include for example, service components which have an updated Data Model.

 

To update the Logical Data Model Swagger definition users must have the Solution Administrator or Architect Functional role in their security profile.
 

The Logical Data Model structure cannot be updated if the Logical Data Model editor is opened.

The Swagger Update wizard consists of the following screens.

Logical Data Model Content

The Logical Data Model Content screen displays the changes detected in the attached Swagger definition compared to the current LDM structure being used in the solution.

This screen consists of table columns, a Change information area, and a toolbar:

Table columns - displays the selected Logical Data Model structure including referenced characteristic names and their properties.

 

The Change column displays the changes detected in the attached Swagger definition compared to the current LDM structure being used in the solution. These changes may include for example updates in the Data Model, such as newly added characteristics or modification of existing characteristic definitions.
 

Only string lengths and array sizes not defined in the REST API (Swagger file) can be edited.

Change information area - displays the change description for the selected characteristic, for example, Increased Array Size (previous value: {0}, new value: {1})

 

Most types of changes in the Data Model are supported using the Swagger Update wizard. These include:

  • New Swagger Data Model properties - the Swagger Update wizard maps these to newly added LDM characteristics.

  • Updated Swagger Data Model properties with lengths, scale, and/or array sizes increased/decreased - the Swagger Update wizard maps these to existing modified LDM characteristics.

  • Updated Swagger Data Model properties with array size (maxItems) changed from defined to undefined, or vice versa which then corresponds to the LDM static and dynamic array sizes (but only if the previous characteristic definition is not a dynamic array) - the Swagger Update wizard maps these to existing modified LDM characteristics.

  • Updated Swagger Data Model properties with data type changed (for example, from String to Integer type), but only if the property names match exactly - the Swagger Update wizard maps these to existing modified LDM characteristics.
 

Some changes in the Swagger properties are reflected differently in the Logical Data Model. These include:

  • Updated Swagger Data Model properties with array sizes changed from static array to dynamic array, or vice versa, but the previous LDM characteristic definition is already a dynamic array (likely set prior by the user) - the Swagger Update wizard maps these to existing LDM characteristics.

  • Renamed Swagger Data Model properties (for example, MailBox property renamed to PostBox) - the Swagger Update wizard will map it to a newly added PostBox LDM characteristic, while Mailbox characteristic is kept as-is.

  • Deleted Swagger Data Model properties (for example, the StampDuty property is removed from the new Swagger definition) - the Swagger Update wizard will NOT delete the StampDuty LDM characteristic, instead it will remain as-is.

  • Swagger Data Model properties with an updated enum list - enum definitions for Valid Values are not supported in both the Swagger wizard and the Swagger Update wizard.
Toolbar

- opens the Find: area below the table columns.

  • Find area

- expands all nodes.

- collapses all nodes.

- opens the Edit Property Values dialog for the selected rows or nodes. The user can edit lengths and/or array sizes for the selected characteristics in a single action.

- opens the Filter context menu.

Filter context menu
 

Depending on the content of the Logical Data Model, certain filter option(s) may not be visible in the context menu.

The filter context menu can be used to:

  • display only the information that can be edited, for example, string lengths and or array sizes.

  • display the selected Logical Data Model group, for example, INPUT, OUTPUT, and/or MAIN.

Filter Text: - filters the characteristic name displayed in the Name column. On the right of the toolbar, the Clear Filter Text action can be used to clear the text.

 

The filter text is not case sensitive.
Summary

The Summary screen displays a summary of the changes that will be applied to the target Logical Data Model structure in the solution, based on the attached Swagger definition.

Changes are highlighted in the following background colours:

Background Colour Description
Yellow Characteristics are mapped to Swagger properties with an undefined length or array size. The system default value is 1, or a previously specified value, but it can also be manually modified by the user.
Orange Existing characteristics with modified properties.
Green New characteristics that will be added

For information on using this wizard to update a Logical Data Model structure, refer to Use the Swagger Update wizard to update the LDM structure to match the Swagger definition.
