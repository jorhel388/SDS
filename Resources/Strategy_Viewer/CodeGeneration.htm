Code Generation

Strategy Viewer can be used to generate the code to create an external interface from any strategy with a physical definition. Byte array Physical Data Models (PDM) can be used to generate either COBOL or C; Java Object PDMs will generate JavaBeans, XML or JSON.

To create a Java Bean interface

  1. From the Strategy Viewer window, right click on an open Java Object PDM strategy file and select Code Generation.
  2. The first screen of the Code Generation wizard, Select Code Generation Type, is displayed.
  3. Select Java Bean Interface V1 Generator from the drop down menu.
  4. Click Next to display Enter required information, the second screen of the wizard.
  5. Type in a Package name. The name supplied will be the name of the physical definition (followed by .java).
  6. Select a data source from the Data sources window.
  7. Browse to the directory where you want to save the generated files, and click Finish to generate the code.

The code generator will create the three Java files - <name>.java, <data source>.java, and OCONTROL.java in the selected directory.

To create a Java Bean interface (Legacy)

  The Java Bean interface V2 should only be used with a system imported from SMg3 into PowerCurve. The Java Bean interface V2 does not support Logical Data Models that contain dynamic arrays. The Java Bean Interface V2 does not support Logical Data Models that are arrays.
  1. From the Strategy Viewer window, right click on an open Java Object PDM strategy file and select Code Generation.
  2. The first screen of the Code Generation wizard, Select Code Generation Type, is displayed.
  3. Select Java Bean Interface V2 Generator from the drop down menu.
  4. Click Next to display the second screen of the wizard, Enter required information.
  5. Type in a Package name. The name supplied will be the name of the physical definition (followed by .java).
  6. Select a data source from the Data sources window.
  7. Browse to the directory in which the generated files should be saved, and click Finish to generate the code.

The code generator will create the three Java files - <name>.java, <data source>.java, and OCONTROL.java in the selected directory.

To create a simple JSON file (used to create a JSON file where no data type is required and the default date format needs to be used)

  The format for the default date characteristic is yyyymmdd
 

It is recommended that JSON V2 is used if in your strategy file you require script that converts string to date, since JSON V2 accepts date characteristics that are formatted as string.
  1. From the Strategy Viewer window, right click on an open Java Object PDM strategy file and select Code Generation.
  2. The first screen of the Code Generation wizard, Select Code Generation Type, is displayed.
  3. Select JSON Schema V2 Generator from the dropdown menu.
  4. Click Next to display Enter required information, the second screen of the wizard.
  5. Browse to the directory where you want to save the generated files, and click Finish to generate the code.

The code generator will create the JSON file - <name>.json in the selected directory.

 

Contains the characteristic value passed to the Decision Agent. The values that are supported:

  • Numeric for Number. For example: "integer_characteristic": 4825
  • Text for a String with quotes. For example: "string_characteristic": "some value"
  • Text for a Date with quotes. The JSON date format, "yyyyMMdd" . JSON V2 only accepted this format.
  • For example: "date_characteristic": "20191101"
 

When a characteristic is defined as a date data type, then the JSON V2 will allow it to be passed as a string using the default date format.

When the default date format is not used, then a script conversion is required to convert the date.
For example For DATEPADD () and DATEPDIFF () user needs to use the TODATE () to convert the default format so that the DATEPADD () and DATEPDIFF () can be used correctly.

To create an XML file (Legacy)

  The XML Schema V1 Generator should only be used with a system imported from SMg3 into PowerCurve. The XML Schema V1 Generator does not support Logical Data Models that contain dynamic arrays.
 

The XML Schema V1 Generator will order external name characteristics based on the ordering defined in the Java Object PDM, which is generated based on the ordering in the Logical Data Source. In order to sort external name characteristics in alphabetical order, deploy the Decision Process Flow in Originations mode. During XML Schema V1 Generation, the generated .xsd files will be sorted alphabetically by their external names.
  1. From the Strategy Viewer window, right click on an open Java Object PDM strategy file and select Code Generation.
  2. The first screen of the Code Generation wizard, Select Code Generation Type, is displayed.
  3. Select XML Schema V1 Generator from the drop down menu.
  4. Click Next to display Enter required information, the second screen of the wizard.
  5. Browse to the directory where you want to save the generated files, and click Finish to generate the code.

The code generator will create the XML file - <name>.xsd - in the selected directory.
