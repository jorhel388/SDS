Decision Setter editor

The decision setter editor enables the user to define the decision making process for a record.

The decision setter editor consists of two areas:

  • Decision Set and Default Decision selection area
  • Policy Ruleset selection area

Decision Set and Default Decision selection area

Default radio button - select to use the default category and reason code as the default decision. The decision that will be unconditionally applied to the record before any rules are evaluated. This is the default selection for this editor.

Fallback radio button - select to use the default category and reason code as the fallback decision. The decision that will be used as a fallback after the rules have been evaluated in the event that none of the rules are triggered.

No Default radio button - select to not use the default decision. When this radio button is selected, only the policy ruleset that has been assigned to the decision setter will be executed. A policy rule set must be assigned to the decision setter when the No Default radio button is selected for the Decision Setter to be valid. The decision sets and default categories drop down box and reason codes will all be greyed out when this radio button is selected.

Decision Sets - a drop-down list of available decision sets. The decision setter uses the information held in the chosen decision set to populate the Default Categories drop-down list. The ranked list of decision categories contained in the decision set are used to process any policy rules used in the decision set in order to return an overall decision.

  Only decision sets that have been published to, or created in the folder where the decision setter has been accessed will be listed as available for selection from within the Decision Setter.

Default Categories - a drop-down list of available categories. With the Default radio button selected, the category selected in this drop down list will be used with a reason code to form the default decision and unconditionally applied to the record before any rules are evaluated. When the Fallback radio button is selected, the category and reason code will be used as a fallback after the rules have been evaluated in the event that none of the rules are triggered. Selecting a default category with a reason code forms the default decision.

 

If a Default Category within a Decision Setter is changed after validation, it must be manually reselected via the Default Categories drop down in order for the change to be applied.

Decision Categories are created in Decision Sets, see Decision Sets overview for more information.

Reason Codes - a browse button accesses the Code Finder dialog which enables the user to search for an appropriate code from the available Decision Reason Code tables. The code selected is combined with the default category to form the default decision for the decision setter.

Policy Ruleset selection area

Policy Ruleset field - drag a policy rule set into this field to use it in the current decision setter, or right click and select Insert Embedded to create a policy rule set specifically for this decision setter. The decision setter uses the policy rule set to ensure that all the required policy rules are processed for each record. A decision setter does not have to have a policy rule set assigned to it to be valid.

For more information on Policy Rule sets see Policy Rule Set Overview
