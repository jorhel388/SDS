Policy Rules

Policy Rules are based on business conditions. They are defined using script and based on logical statements where the outcome is either true, or false. A record will therefore either meet a policy rule condition, or not.

Overview

A Policy Rule is created in a similar way to a Boolean Expression, using operators, functions and characteristics. Similarly to Boolean Expressions segmentation functions can be used in Policy Rules. For more information on using Segmentation functions see Adding Segmentation Functions to script.

  Index Tables are not supported in Policy Rules.

The default mode for a Policy Rule is for it to be triggered to output its associated Reason Code if the condition evaluates to be true. If required, this can be altered to "false". This would return a Reason Code for any record that did not meet the condition, rather than all those that did.

When a record is passed through the Policy Rule Set at each Decision Category point in the sequence one or more Policy Rules are applied. If one or more of the conditions contained in the Policy Rules are true for the record, the text and code describing each condition will be returned; the record will then be directed to the next relevant Decision Category point in the Policy Rule Set.

A Policy Rule consists of:

Description - the name given to the Policy Rule when it is created. This name is used to identify the Policy Rule when it is used in the Decision Setter

Reason Code - the information that is returned when a record meets a criteria

Mode - dictates whether the Policy Rule Reason Code will be returned if the condition is met ("true") or is not met ("false")

Condition - a logical (true/false) condition like a Boolean Expression, that is either met or not met by a record.

Edit a Policy Rule

Policy Rules consists of a rule/condition created in a similar way to a Boolean Expression, a Reason Code that will be returned when a record meets the criteria of the rule and a mode that dictates whether the Reason Code will be returned if the condition is met ("true") or is not met ("false"), the default being true.

Create a Policy Rule

A Policy Rule can be created from the Explorer window.

  You will only be able to add a component type that has been allowed for the selected folder. If it is not allowed it will not be listed and therefore cannot be selected.

To create a policy rule

  1. From the Explorer window right click at the required folder level and select Add component.
  2. Select Policy Rule.
  3. In the Create component dialog enter the name of the Policy Rule.
  4. Select the Open new components in component editor check box.
  5. Click on the OK button.
    The Policy Rule Editor will open allowing you to define the Policy Rule.
    The Policy Rule name will be listed in the Explorer window under the selected folder level. The component is identified by the icon.

If you do not wish the editor to open, keep the check box de-selected. From the Explorer window right click ans select the Policy Rule you require and select Open.

To edit a Policy Rule

Select the Policy Rule mode

When a record is passed through the Policy Rule Set at each Decision Category point in the sequence one or more Policy Rules are applied. The mode for a Policy Rule determines whether the Reason Code is returned if the condition is (true) or if the record did not meet the condition (false). The default mode for a policy rule is "true".

To select the Policy Rule mode

  1. With the Policy Rule editor open select the True radio button to ensure that the Reason Code is returned when the condition is satisfied.
  2. Select the False radio button to ensure that the Reason Code is returned only when the condition is not met by the record.

You can continue editing the Policy Rule.

Select a Reason Code

Reason Codes are held in Decision Reason Code Table. The browsing area of the Code Finder dialog lists the available Decision Reason Code Tables from which you can choose a Reason Code. In the Decision Setter editor the code selected will be applied to a record when the Default Decision is assigned at runtime.

To select a Reason Code

  1. With either the Decision Setter editor or the Policy Rule editor open click on the Browse button.

    The system will open the Code Finder dialog.

  2. Locate the Decision Reason Code Table you require.
  3. Click on the Expand + button to list all the codes contained in the Decision Reason Code Table. Moving the mouse cursor over the individual reason codes will cause the system to display the description that has been used to describe this code.
  4. Select the Reason Code you require.
  5. Click on the OK button.

The Code Finder dialog will close and the code will be applied to either the default or fallback decision or the Policy Rule.

Define a Policy Rule condition

A Policy Rule is defined by a script, created in a similar way to a Boolean Expression, using operators, functions and characteristics.

To define a Policy Rule condition

  1. With the Policy Rule editor open, add script freehand or use the required resources from the Palette and Resources window to create your Policy Rule condition. See the following for more details:
    Add an operator or function to a script
    Add a characteristic to a script
    Add a class set to a script
    Add a matrix to a script
  2. Click on the Compile icon in the tool bar to check the script syntax.

The system will provide you with information regarding the validity of the script. Details of any errors will be displayed to provide you with information so that you can correct them.

  You cannot test a Policy Rule using Tester unless the script is valid and the Policy Rule contains a Reason Code.
Test a Policy Rule

Once the user has successfully created a policy rule, the user will be able to test it using the Batch or Interactive Tester.

The user can test a policy rule either by manually typing in data for the input characteristics referenced in the policy rule or by performing a test against a known data source.

To perform an interactive test

To test a policy rule manually by entering data into the relevant fields for the input characteristics, use the Interactive Tester.

To perform a batch test

To test a policy rule using data from a .csv file, from the Explorer window, right click on the component and select New Test Project to use the Batch Tester.

The Policy Rule will be ready for use within the Decision Setter.
