Policy Rule Set Editor

The policy rule set editor is used to define the policy rule set used in the decision setter.

The policy rule set editor consists of four areas:

  • Policy Rule Set toolbar
  • Decision Set selection area
  • Decision category flow definition area
  • Policy Rules area

Decision Set selection area

Decision Sets - a drop-down list of available decision sets. The decision setter uses the information held in the chosen decision set to populate the Default Categories drop-down list. The ranked list of decision categories contained in the decision set are used to process any policy rules used in the decision set in order to return an overall decision.

  Only decision sets that have been published to, or created in the folder where the decision setter has been accessed will be listed as available for selection from within the Decision Setter.

Default Categories - a drop-down list of available categories. With the Default radio button selected the category selected in this drop-down list will be used with a reason code to form the default decision and will be unconditionally applied to the record before any rules are evaluated. When the Fallback radio button is selected the category and reason code will be used as a fallback after the rules have been evaluated in the event that none of the rules are triggered. Selecting a default category with a reason code forms the default decision and is a mandatory selection within the decision setter, it ensures that a decision of some sort is always returned.

 

If a Default Category within a Policy Rule Set or Decision Setter is changed after validation, it must be manually reselected via the Default Categories drop down in order for the change to be applied.

Decision Categories are created in Decision Sets, see Decision Sets overview for more information.

Reason Codes - a browse button accesses the Code Finder dialog which enables the user to search for an appropriate code from the available Decision Reason Code tables. The code selected is combined with the default category to form the default decision for the decision setter.

Default radio button - select to use the default category and reason code as the default decision. The decision that will be unconditionally applied to the record before any rules are evaluated.

Fallback radio button - select to use the default category and reason code as the fallback decision. The decision that will be used as a fallback after the rules have been evaluated in the event that none of the rules are triggered.

Decision Category Flow definition area

The decision category flow definition area of the Policy Rule Set editor is used to define the decision category flow that ensures that all the required policy rules are processed for each record.

The decision category flow within the policy rule set is made up of the following:

Start node - the point in the sequence where processing starts. A processing sequence must always have a start node.

Category node - a point in the sequence where decision categories are applied. Policy Rules are applied to categories in the sequence.

The category node has four display modes that help the user know the current definition state of the category node, these are:

- Undefined - Only policy rule(s) applied - Only decision category applied - Category fully defined

Rules Fired node - a point in the sequence where Yes or No pathways can be used. When a record is processed through policy rules that have been applied to a decision category, the rules fired node is used to direct the record to the next relevant decision category depending on which outcome (True or False) has been triggered.

End Node - the point in the sequence where processing ends. A processing sequence must have an end node.

Policy Rules area

The policy rules area of the Policy Rule Set editor is the table where the user can view a list of the policy rules that are currently in use in the Policy Rule Set, their priority order, reason code that will be applied if the rule is triggered and outcome mode (true or false). Once a policy rule has been applied to a category it will be listed next to the name of the decision category it has been applied to. If no decision category has been applied to the category, then the name displayed in the table will be the name of the category node itself. The policy rules will be listed initially in the order that they have been applied to the category. This order, the priority order, can be altered from within the table.

 

In the Policy Rules area, to open a Policy Rule, the user can either double click on the row or right click on the row then select Open from the context menu.

To delete a Policy Rule, right click on the row then select Delete from the context menu.

 

The user is able to delete more than one policy rule at a time by selecting multiple rows by either pressing Ctrl or Shift + click to select multiple rows and then right clicking in the table to open the context menu, then selecting Delete. The user is not able to open more than one policy rule at a time using this method.
