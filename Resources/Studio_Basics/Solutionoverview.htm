Solution overview

A solution is a level by which the contents of domains can be further divided. Some examples could include solutions that:

  • are composed from purely decisioning capability and content, or purely operational capability and content, or from a combination of both
  • are organised differently based on business objectives and solution scope
  • cover multiple work streams such as origination, customer management and reporting
  • are multi-country solutions designed with the capability to isolate country specifics
  • manage multiple credit products and associated components with the potential for cross product activities such as cross-selling

The publishing mechanism that allows sharing of components operates within the solution boundary; for example, definitions of data models and layouts can be located in a folder and published for use within other parts of the solution, but not within other solutions.

A solution is represented with the icon and can be cloned, viewed, added, deleted, renamed and loaded in the Explorer window.

The user can import a previously exported component, folder or solution along with any dependent components and folder structures.

The user can export a component, folder or solution along with any dependant components and folder structures.

Add an empty solution

The user can add an empty solution or a pre-configured solution.

To add an empty solution

  1. In the Explorer window, right click on the domain within which you want to add the new solution.
  2. Select New.
  3. In the New dialog, select Empty solution and click on the OK button.
  4. Select Add solution.
  5. In the Add solution dialog, type the name of the new solution.
  6. Click OK.

The solution will be added to the domain.

Add a pre-configured solution

The user can add an empty solution or a pre-configured solution to a domain.

To add a pre-configured solution

  You must have Architect access rights in order to overwrite an existing signature in a solution.
  You must have a target solution loaded prior to commencing.
  1. In the Explorer window, right click on the required domain.
  2. Select New.
  3. In the New dialog, select Pre-configured solution and click OK. The Import wizard will be initiated.
  4. In the first screen, Select import source is displayed with the Product Library folder selected:
    1. Double click on the Solution Repository Import Library folder and select the xml file to import (or navigate to the xml file of your choice).
    1. From the Files of type field, ensure that Experian Proprietary Format is selected:
    1. Click Next.
  1. In the second screen of the Import wizard, View import file:
    1. Review the components and folder structure to be imported.
    2. Click Next.
  2. In the third screen of the Import wizard, Existing components, it displays a list of components among those you are attempting to import that are already in the target solution.
    1. If you want to import the existing components, you must import them into your user area by checking the Import tickbox:

      If you do not specify that the existing components are to be imported into your user area, they will not be imported.

    2. If all the components already exist in the target solution, you will be unable to continue the import process until you have selected the tickbox; the following message will be displayed:

    3. Click Next.

  3. In the fourth screen of the Import wizard, Confirm choices:
    1. Review the name and the location of the imported file.
    2. Optionally, select the Import checkbox if you wish to retain the source signature from the solution when importing into the solution repository.
    3. Unless all components are to be imported into the user domain, the Comments field is mandatory; type a relevant comment. The comment is for users who want to know why a component was imported and it appears in the History of a component in the shared domain, in the Comments column.
    4. The Label field is an optional field.
    1. Click Next.
  1. In the fifth screen of the wizard, Import job summary:
    1. The process will now be sent for remote execution. You can specify that the Job Submission Console will launch automatically when you exit the wizard by clicking in the Launch Job Submission Console tickbox.
    1. Click Finish.

The newly imported solution will be listed within the selected domain.

Clone a solution

Users can clone an existing solution in the same repository within a domain of their choice.

To clone a solution

 

Before cloning a solution, ensure any changes you want to be cloned are checked in.
 

You must have Architect permission to clone a solution.
 

If the Clone process fails, the unsuccessful cloned solution will be removed.
  1. In the Explorer window, right click on the solution you wish to clone.
  2. Select Clone.
    3. The Clone solution dialog appears. The source solution root domain name is selected by default to be the target location and appears in the dropdown menu.
  3. Optionally, select the target domain of your choice using the dropdown menu.
  4. Click Clone.
    5. The Remote Job Notification dialog appears.
  5. Click OK.

The cloned solution will be added to the domain.

The component history of the cloned solution and source solution can be viewed via the History window.

 

If the source solution is deleted, the cloned solution will lose reference to its source content. A message ‘Clone source solution no longer exists’, will be displayed to notify users of the absence of the source solution via the History window and Properties panel (Origin solution path).
Unlock a locked solution for editing

When a user with architect access is creating folders or editing the publishing rules within a solution, a lock token is put on the solution.

If another user with the same access tries to create folders or edit the publishing rules within the locked solution, a warning dialog will be initiated. This is expected behaviour.

However, if the server shuts down abnormally whilst the lock token is in place, or if a user with architect access has left a session open in editing mode in error, other users with architect access will continue to face the Warning dialog. If this is the case, the solution may be unlocked for editing. Only a user with Solution Administrator access will be able to unlock a locked solution.

  This is a maintenance operation only and not a usual business action. This should be used in extreme cases only.

To unlock a solution for editing

  1. In the Explorer window, right click on the locked solution.
  2. Select Unlock.

You may now create folders or edit the publishing rules within the solution.

Remove a solution

The user can remove a solution from a domain.

  The removal of a solution will mean deletion of its content.
 

A user must have the Architect role to remove a solution.

To remove a solution

  1. In the Explorer window, right click on the solution that you wish to remove.
  2. Select Remove.
    The Confirm solution deletion dialog will be displayed.
  3. Select the Confirm deletion of solution checkbox.
  4. Click Delete.

The solution will be permanently removed from the domain.

Add a signature to a solution

A Solution Signature is a unique identity given to a solution and is used at runtime as an ‘internal’ password to ensure that the process flow being executed is for the correct client solution. The solution signature is also used to gain access to view deployed strategy contents within the Deployed Strategy Viewer.

The user is prompted to enter the solution signature during the execution of already deployed jobs. This additional security feature ensures that the person deploying a strategy is authorised by the solution architect to carry out this kind of action.

At solution design stage, there is no need to enter the signature to carry out designing actions.

To add a solution signature

  1. In the Explorer window, right click on the loaded solution to which you want to add the signature.
  2. Select Add solution signature.
  3. In the Add Signature dialog, type the signature into the Signature field.
    4.   The solution signature is case sensitive and is limited to 8 characters in length.
  4. Click OK.

The signature will be applied to the solution.

  A signature can only be assigned to a client system user by a user who has Architect access rights.
 

The signature of your solution is not retained during import when importing into an empty domain. If this is the case, it is recommended that the signature is noted prior to export.
DA Null Handling solution property

The DA Null Handling solution property allows users to define how nulls are handled in the Decision Agent (DA) runtime execution. The property only applies to Java Object Physical Data Sources.

  The DA Null Handling property can only be modified (set or updated) by users with Architect access rights. The property is visible to all other users but in read-only mode.

The DA Null Handling property can be set in the Properties window.

There are two settings available to users:

  • Error on Null - the processing of an unhandled Null value in a Physical Data Source will terminate the execution with an error. This is the default value which maintains the existing behaviour and will be displayed when no value has been set. For example, in existing solutions and when importing existing XML files.

  • Use Default Values -:

    • When null values in a Physical Data Source are accessed during execution, they will be replaced with the default values.

    • Testing for nulls in scripts (ISNULL) will still return true for nulls.

    • The actual value returned will be the default values in-built to the Decision Agent or as specified in the Custom Default Value component (when present).

To set (or update) the Null Handing property

  1. Select Window > Properties from the main menu bar to open the Properties window.

  2. In the Explorer window, open (or select) the solution property you want to update.

  3. Click on the dropdown in the DA Null Handling properties row and select the required value.

The value will be set in the solution for all users. There is no additional save mechanism. Any deployments currently in progress will not be affected by this change.

Rename a solution

The user can rename a solution.

To rename a solution

  1. In the Explorer window, right click on the solution you wish to rename.
  2. Select Rename.
  3. In the Rename dialog, type the new name in the New name field.
  4. Click OK.

The system will check to ensure that this name is unique in the domain and rename the solution.

Load a solution

Solutions are stored within a domain from where they can be loaded.

To load a solution

  1. You must first navigate to a domain.
  2. In the Explorer window, highlight the required domain and click on the icon.
  3. The solutions within the domain will now be displayed.
  4. Right click on the required solution and select Load solution.
  You can also double click on the Solution to connect.

You can now click on the icon to open the Solution.

  Clicking on the icon to the left of the solution icon in the Explorer window will expand the solution.
Close a solution

The user can close a solution.

To close a solution

  1. In the Explorer window, right click on the solution you want to close.
  2. Select Close solution.

The solution will be closed.
