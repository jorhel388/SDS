Characteristic Mappings panel

The Characteristic Mapping panel allows the user to view details of the source Data Model components including details of any target mappings that have been made, as part of the Merge process.

  In this topic Logical Data Sources, Logical Data Model characteristics and Logical Data Source characteristics will be referred to as ‘Data Model components’.

From this panel the user can also view the mapping information and perform an Automap, Unmap, Ready and Apply.

  To change the row order displayed in the Characteristic Panel, click on the column header once for ascending order, twice for descending order and three times for the default order.

The Characteristic Mapping panel consists of columns, a toolbar and a contextual menu:

Source Columns

The Source columns display information about the source Data Model components and consists of:

Source – displays the source Data Model components and their structure in a hierarchical tree. Source components can be mapped at Logical Data Source level or Logical Data Model characteristic level or Logical Data Source characteristic level.

Next to each source Data Model component is a check box. This check box is used to indicate when the mapping is complete (Ready). The Apply button located in the toolbar is activated when a check box is selected. During the Merge process only source Data Model components with this ‘Ready’ status will be merged.

Type – displays the type of Logical Data Source characteristic (for example, String, Numeric, Date, etc), whether the source is a Logical Data Source itself or is a Logical Data Model in which case the name of the Logical Data Model will be displayed in the Type column.

Length – displays the number of digits or characters the field can hold and includes any decimal component

Scale– display the number of decimal places required (applies only to decimal and float data types)

Array Size – display the number of times a characteristic appears in an array (size of the array). If the characteristic is not an array, it is set to zero. An asterisk (*) is used to indicate a dynamic array (an array without a fixed size).

For information about a Logical Data Source, see the Logical Data Source overview topic.

Status Column

The Status column displays the source Data Model component mapping status:

 

Data View components are only available in an Originations or Connectivity and Enrichment Solution.
 

Conflict mapping statuses, when the conflict is either on the Name or Path property there is no functional impact. However, if the conflict is either on the Length or Scale property then a strong validation of the solution is required.

Unmapped – this component has not been mapped

Conflict (partial) – this component is mapped but conflicts exist within at least one of its properties (e.g. Name, Length, Scale and Path). Also at least one of its target Data Views has not been mapped (see the Data View Mapping panel topic for more information).

Conflict – this component is mapped but conflicts exist within at least one of its properties (for example, Name, Length, Scale and Path). The target Data Views mappings are complete.

Perfect (partial) - this component is mapped and no conflicts exist within its properties. Also at least one target Data View has not been mapped.

Perfect – this component has been successfully mapped and no conflicts exist. The Data Views have been mapped successfully. This Perfect status also applies to a target component marked as new (see the Manual Selection tab drop-down heading in the Target Selection panel topic for more information).

Missing Data View(s) – this component has been mapped but at least one Data View needs to be mapped but there is no target Data View available that is related to the target characteristic.

Ready – this mapped component is complete (the check box associated with it is selected) and ready for the Merge process. Ready status includes both Conflict and Perfect mappings.

During the Merge process only source Data Model components with a 'Ready' status will be merged.

Use the Show/Hide Status buttons to filter the Data Model components according to their mapping status. See the Characteristic Mapping panel Toolbar topic (below) for more information.

Target Columns

The Target columns display information about the target Data Model components and consists of:

Target Parent – displays the full name of the mapped target Data Model component. Hovering with the mouse over the component name will display the folder path.

Target – displays the full name of the mapped target Data Model component. A green cross indicates that a new target Data Model component will be created into the selected target Data Model component destination. Hovering with the mouse over the component name will display the target path.

Target Type – displays the type that can be defined for a Logical Data Source or a Logical Data Model characteristic

Target Length – displays the number of digits or characters the field can hold and includes any decimal component

Target Scale – displays the number of decimal places required (applies only to decimal and float data types)

Target Array Size – displays the number of times a characteristic appears in an array (size of the array). If the characteristic is not an array, it is set to zero. An asterisk (*) is used to indicate a dynamic array (an array without a fixed size).

  The target characteristic property columns are hidden by default. To show or hide the columns in the Characteristic Mapping panel either right click on a column header to access the contextual menu or click on the Select Visible Columns button.

For information about a Logical Data Source refer to the Logical Data Source overview topic.

Toolbar

The toolbar consists of two groups of buttons (Show/Hide Status on the left and actions on the right).

Show/Hide Status

The Show/Hide Status toggle buttons filters the Data Model components according to their mapping status:

  Data View components are only available in an Originations or Connectivity and Enrichment Solution.

Unmapped – show/hide all the unmapped components

Partial Mappings – show/hide all the mapped components that do not have a Data View mapped. This filter includes:

  • Conflict (partial) – this component is mapped but conflicts exist within at least one of its properties (e.g. Name, Length, Scale and Path). Also at least one of its target Data Views has not been mapped (see the Data View Mapping panel topic for more information).
  • Perfect (partial) - this component is mapped and no conflicts exist within its properties. Also at least one target Data View has not been mapped.
  • Missing Data View(s) - this component has been mapped but at least one Data View needs to be mapped however there is no target Data Views in the solution.

Conflict – show/hide all the components that are mapped but conflicts exist within at least one of its properties (for example, Name, Length, Scale and Path)

Perfect – show/hide all the components that have been successfully mapped and no conflicts exist. The Data Views have been mapped successfully. This Perfect status also applies to a target component marked as new (see the Manual Selection tab drop-down heading in the Target Selection panel topic for more information).

Ready – show/hide all the mapped components with the check box associated with it selected. Ready status includes both Conflict and Perfect components.

During the Merge process only source Data Model components with a 'Ready' status will be merged.

A target characteristic property is assigned with an individual Match score based on its comparison to the same property from the source characteristic property. The final Match score is the sum of all of the individual scores unless an ‘Exit threshold’ process is triggered. The average of the individual Match score will provide the final score for the matching candidates.

Action Buttons

Options - opens the customisable matching parameters used in the Merge editor

Import - allows the user to import a previously saved csv history file (containing the mapping configuration)

Export - allows the user to export all the mapped history configuration from the solution to a csv file

Automap - access the following automatic mapping options:

  • History - maps a target Data Model component(s) using a saved history mapping configuration to the selected source Data Model component(s)
    •   If, the history mapping configuration does not contain a target mapping for the selected source, or the target Data Model component does not exist in the solution then nothing will be mapped.
     

    When closing the Merge editor, the history mapping configuration will be saved in the solution and therefore, it can be accessed by all users, who are working on the same solution.
  • Perfect only - maps a target Data Model component(s) only when the match is a Perfect Match (score of 100%) to the selected source Data Model component. If there is no perfect score, nothing will be mapped.
  • Best Candidate - maps a target Data Model component starting with a Perfect match score (if any). If there is no Perfect match then the next candidate with the highest match score will be mapped. The History option is ignored because it is assigned with the top match score (above a Perfect match).
  • Source - uses the source items as the target
  To ignore the candidate characteristics that are below a defined score change the Trust score value in the Matching Options.

Unmap - removes the current Data Model component mapping

Ready - sets the Ready status for the mapped source Data Model component(s)

  When applying the Unmap or Ready action on a parent Logical Data Model the same action is also cascaded down to its child characteristics.
  The Automap, Unmap and Ready actions described above are also available using the contextual menu accessed by right clicking on a row and selecting the action of your choice.

When the mappings have been defined the Merge process will perform some or all of the following action(s):

  • Mapped source characteristics that exist in any component including those components that only use references to these characteristics (for example, Derived Data Script) will be replaced with the target characteristics.
  • The source characteristics marked as new will be created in their defined target destination (Logical Data Source or Logical Data Model characteristics).
  Derived Data Script will have their direct references to a Logical Data Source updated with the Merge process.

  The Merge process may affect components that do not support dynamic array characteristics. Therefore, it is not recommended to map static characteristic or static array characteristic to characteristics that contain dynamic arrays in their Path.
  When the Merge process is being used in a multi-user environment, all the Data Model dependencies (for example, Entity Models, Logical Data Sources, Logical Data Models, Data Views etc), should be locked during the process of merging (from configuration to Apply).

Apply - launches the Merge Editor Apply Wizard that allows the user to preview the changes before executing the Merge process

After the Merge process all components that previously used the source Data Model components including their Data Views (if any) will now use the newly merged target Data Model components and their target Data Views. This does not include those components that are not supported by the Merge process.

Contextual Menu

The Characteristic Mappings panel contextual menu can be accessed by right clicking on any row:

Toggle Ready - sets the Ready status for the mapped source Data Model component(s)

Automap - access the following automatic mapping options:

  • History - maps a target Data Model component(s) using a saved history mapping configuration to the selected source Data Model component(s)
    •   If, the history mapping configuration does not contain a target mapping for the selected source, or the target Data Model component does not exist in the solution then nothing will be mapped.
     

    When closing the Merge editor, the history mapping configuration will be saved in the solution and therefore, it can be accessed by all users, who are working on the same solution.
  • Perfect only - maps a target Data Model component(s) only when the match is a Perfect Match (score of 100%) to the selected source Data Model component. If there is no perfect score, nothing will be mapped.
  • Best Candidate - maps a target Data Model component starting with a Perfect match score (if any). If there is no Perfect match then the next candidate with the highest match score will be mapped. The History option is ignored because it is assigned with the top match score (above a Perfect match).
  • Source - uses the source items as the target
  To ignore the candidate characteristics that are below a defined score change the Trust score value in the Matching Options.

Paste DataViews - paste the recently copied target and source Data Views mappings into a selected source Data Model component(s) from the Characteristic Mapping panel. If a selected source Data Model component(s) does not have Data Views with the same name then nothing will be applied. See the Data View Mapping panel topic for more information.

Select all - selects all the visible rows

Expand selection - expands the content of a selected Data Model component(s)

Collapse selection - collapses the content of a selected Data Model component(s)

Where used - displays all components that have references to the selected Data Model component
