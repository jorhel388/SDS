Domain overview

A repository may contain one or more domains, each of which can contain one or more solutions. User details and access permissions operate at repository level, and a user's role-based permissions may therefore span domains, or be confined within a single domain, as required within the repository.

Many clients, particularly those with only a single solution, or a small number of solutions, will generally have a single domain within their repository. For enterprise-level clients, or for delivery centres working on multiple solutions for many clients, the domain provides a useful mechanism for grouping sets of solutions that logically belong together (and conversely to separate/isolate them from other solutions/groups of solutions).

A domain is displayed with the icon in the Explorer window.

From the repository (Content, Reporting or Solution), a user who has been assigned to an Architect functional role in their security profile account can:

Navigate to a domain

From a repository it is possible to navigate to a domain.

To navigate to a domain

  1. You must first Log into a Repository.
  2. In the Explorer window, highlight the required repository and click on the icon.
  3. The domains within the repository will now be displayed in the Explorer window.
  4. Highlight the required domain and click on the icon.

The domain is now loaded and the solutions within the domain will now be displayed. You can now load a solution.

  Clicking on the to the left of the domain icon in the Explorer window will expand the domain.
Add an empty domain

An empty domain can be added into a repository.

 

Only a user who has an Architect functional role assigned to their security profile account can manage domains (add, remove, rename or change the unit value assigned to it).

To add an empty domain

  1. From the Explorer window, right click on the required repository and select Connect
  2. Right click on the same repository and select New...
  3. In the New dialog, select the Empty domain option and click OK.
  4. In the Add domain dialog, enter the domain name in the Name field.
  5. Select the required unit using the Unit drop down list.
    6.  

    If there are no units saved in the Security repository, the drop down list will be empty.
     

    Depending on the user profile, specific units will be available to the user from the Unit drop down list. A user who has an Architect functional role assigned to their security profile account and is:

    • assigned to a unit can select either the unit account assigned to the user or no unit (empty value)
    • not assigned to a unit can select any unit account that is stored in the Units folder of the Security Explorer window.
     

    A user with the Security Administrator Profile that has been assigned to a unit can view the content of any domains that have not been assigned to a unit (have an empty value) in the Explorer column from the Security Profile editor.

  6. Click OK.

The new domain will be displayed in the selected repository. You may now add a solution (empty or pre-configured) to your domain.

Add a pre-configured domain

A pre-configured domain can be added into a repository.

 

Only a user who has an Architect functional role assigned to their security profile account can manage domains (add, remove, rename or change the unit value assigned to it).

 

If the user has been assigned to a unit, the imported pre-configured domain will automatically inherit the unit that has been assigned to the user.

If the user has not been assigned to a unit, no unit will be assigned to the imported pre-configured domain.
 

Any unit that has been assigned to a domain will not be saved in the export file.
 

To enable repository and domain level export, additional information has been added in the export process, storing the domain details within the XML file. Therefore, older exports without the correct domain details (prior to 2.2) will only be supported from a solution level import (and are therefore not supported at repository/domain level import as they can not validate the domain information).

If there is a file mismatch, the following error will be displayed:

It is recommended that any XML (pre v2.2) systems are imported into the new software via the solution node by an architect and then re-exported to capture this additional information within the export file. This will enable them to be imported at a repository or domain level.

To add a pre-configured domain

  1. From the Explorer window, right click on the required repository and select Connect
  2. Right click on the same repository and select New...
  3. In the New dialog, select the Pre-configured domain option and click OK.
  4. The Select import source step is the first screen of the Import wizard.
    1. Double click on the Solution Repository Import Library folder and select the .xml file to import.
    2. From the Files of type field, ensure the Experian Proprietary Format (*.xml) has been selected.
    3. Click Next.
  5. The View import file step is the second screen of the wizard. It allows users to view the full contents of the file that will imported.
    1. Click Next.
  6. The Review Components step is the third screen of the wizard.
    1. If there are no conflicting components in the solution repository, click Next.
    1. If there are any conflicting components in the solution repository, they will be displayed on the screen. To import the existing components, import them into your user area by selecting the Import checkbox.
       

      If you do not specify that the existing components are to be imported into your user area, they will not be imported, and the following error will displayed.
    1. Click Next.
  7. The Confirm choices step is the fourth screen of the wizard. It allows you to review the import information and to add a comment (mandatory).
    1. Unless all components are to be imported into the user domain, in the Comments field, type a relevant comment. The comment is for users who want to know why a component was imported and it appears in the history of a component in the shared domain, in the comments column.
    1. The Label field is optional (a label is a method of grouping objects together and the label represents a version of the objects as a collective group).
    1. Click Next.
  8. The Import Job summary step is the fifth and final screen of the wizard.
    1. The process will now be sent for remote execution. Specify that the Job Submission Console (displays the job status) will launch automatically when you exit the wizard by selecting the Launch Job Submission Console checkbox.
    1. Click Finish.

The new domain will be displayed in the selected repository. You may now add a solution (empty or pre-configured) to your domain.

Remove a domain

A domain located in a repository can be deleted.

To remove a domain

  1. In the Explorer window, right click on the domain that you want to remove and then select Remove.
    The Confirm domain deletion dialog will be displayed.
  2. Select the Confirm deletion of domain checkbox.
  3. Click Delete.

The selected domain has been removed from the Explorer window.

Rename a domain

A domain located in a repository can be renamed.

To rename a domain

  1. In the Explorer window, right click on the domain you want to rename and the select Rename...
  2. In the Rename dialog, type the new name and click OK.

The system will make sure that the name is unique within the repository and then apply the name to the selected domain.

Change the unit value assigned to a domain

The unit value assigned to a domain can be changed.

 

Only a user who has an Architect functional role assigned to their security profile account can manage domains (add, remove, rename or change the unit value assigned to it).

To change the unit assigned to a domain

  1. From the Explorer window, right click on the repository where the domain is located and select Connect
  2. Right click on the required domain and select Edit unit...
  3. In the Edit unit dialog, select the required unit value using the drop down list.
    4.  

    Depending on the user profile, specific units will be available to the user from the Unit drop down list. A user who has an Architect functional role assigned to their security profile account and is:

    • assigned to a unit can select either the unit account assigned to the user or no unit (empty value)
    • not assigned to a unit can select any unit account that is stored in the Units folder of the Security Explorer window.
     

    A user with the Security Administrator Profile that has been assigned to a unit can view the content of any domains that have not been assigned to a unit (have an empty value) in the Explorer column of the Security Profile editor.

  4. Click OK.
 

The current value assigned to a domain is displayed in the Unit field of the domain Properties window.

The domain has been assigned to the new unit value.

 

Any unit that has been assigned to a domain will not be saved in the export file. This is done to allow an easier re-usability of solutions.
