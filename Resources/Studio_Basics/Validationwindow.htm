Validation window

Validation is a service that carries out a check on the validity of a Solution, a Folder or a Component and its contents.

The validation service prevents the runtime object from being created from the business object if the business object is invalid. Component warnings and errors are displayed in the Validation window.

  Double clicking on a particular issue in the Validation Results window will open the invalid component.

Once validation is complete, the Validation window will list at the top of the window the number of validation issues discovered.

To revalidate the same selection, click the Re-validate button.

The Validation window also contains a table containing the following columns:

Level - displays the level of the validation issue.

  • Error - this is used when a flaw in the component would prevent a runtime object from being created or the runtime component would generate invalid or misleading results or when there are components that are in the Recycle Bin or when the components have been deleted. An example of misleading results would be duplicate outcome names in a class set. A user can double click on an error in the Validation window and the component will open in the main editor.
  • Warning - this is used when there is a possible flaw in the component that will not affect the behaviour at runtime. For example a user has specified decimal places in a class set based on an Integer characteristic.
    Using the Hide warning option, warning messages can be hidden from view.

    When a specific message type has been hidden, the Validation window will list at the top of the window the number of warning messages that have been hidden for this user.

    •   The type of Warning messages hidden in the Validation window is determined by user preferences.
  • Information - this is used when there is nothing "wrong" with the existing designed solution. The Information level means that the user does not need to fix a problem to make the solution work, it is more that leaving the issue would possibly cause an unpleasant outcome. For example, it is recommended that there is only one Enrichment Raw Data population Search component in a Business Process Flow to avoid duplication or unnecessary data storage in the Raw Data Service. If more than one occurs in the Business Process Flow the Information level will be displayed in the Validation Results window.

Component - displays the name of the component with the validation issue.

Type - displays the type of component with the validation issue.

Area - displays the area that the component is held in:

  • Indicates that the component is held in a user domain.
  • Indicates that the component is held in a shared domain.
  • Indicates that the component is held in the active editor (or was validated from the active editor).
  • Indicates that the component is embedded. A user can double click on an embedded component in the Validation window and the embedded component will open in the main editor.

Revision - displays the version number of the component. For embedded components, this will be n/a.

Description - displays a description of the warning or the error.

The Validation window can be customised; the user can change the row order, change the column order and remove or add columns from view.

The Validation window also has the following:

Change Visible Columns - the user can click on the icon to remove or add columns in the Validation window. The Level column is mandatory. The Component, Type and Description columns are optional.

Validation process status bar - displays the status of the Validation process. Multiple validation tasks can be performed simultaneously if required. Running validation tasks can be viewed and cancelled.

The Validation window is not displayed by default and is initiated when the user carries out validation; see Validation overview for more information.

When the Validation window is initiated it is housed in the Output area of the User Interface. By default, the Output area is displayed at the bottom right hand side of the interface.
