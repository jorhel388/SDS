Export wizard

The Export wizard allows a user to export a component, folder, solution or template. The exported item will be saved in an export.xml file. Any component and/or folder dependencies along with its structure will also be saved in the .xml file.

 

When exporting a template all its revisions will also be saved in the export.xml file.
 

To export a solution containing a solution property value, such as the DA Null Handling, users must have the Architect functional role as part of their security profile.

An exported item can be imported into a solution (for a component, folder or solution) or Content Repository (for a template) using the Import wizard. For more information about the export or import functionality, refer to the Export/Import overview topic.

 

Before exporting a component, folder, solution or template the user must have at least read access to the item. Also, the export process will be blocked if a folder or component contains any unreadable dependencies.
 

When exporting a solution, any template tracking information will also be saved in the export.xml file.

The tracking information links the template to the repository that was used to create it. When the template has been consumed in a solution, its tracking information can be viewed in the Consumed Templates window.

 

The signature of your solution is retained during import, when importing into an empty domain.

In the Explorer window, right click on the loaded solution and select Add solution signature. The signature that has been assigned to the solution will be displayed in the Add Signature dialog.

For information on how to use the Export wizard, refer to the Export a component, folder, solution or template topic.

The Export wizard consists of the following screens:

Select Context

The Select Context screen is the first screen of the wizard. It allows the user to specify the source workspace to be used in the export. Any version labels can also be added to the export file.

  The following options from the Select Context screen do not apply to a template and are disabled.

This screen consists of:

Include User Area:

  • checked (default setting) - the export.xml file will include the component(s) and its dependencies from the user area
  • unchecked - the export.xml file will include the component(s) and its dependencies from the shared area

Include following version labels:

  • checked - allows the user to add any labels displayed in the version label area (for example, Application CB/Application No125) to the export file using the Arrow button
  • unchecked (default setting) - the version label area is deactivated
View items

The View items screen is the second screen of the wizard. It displays the content of the repository structure that will be exported.

The export file will be in Experian Proprietary Format (*.xml). There are two options to save the export file name (short or long):

  • export.xml - this is the short file name

  • % artefact-name%_% job-start-time%_export - this is the long file name (<solution-name>_start-date-of-the-job_start-time-of-the-job_export.xml)

    •  

    Using the long export file name can affect internal systems consuming the exported file or post-processing within a Batch Process Flow.
 

The short export file name is selected by default. However, the user can switch between using the long export file name or revert to the short file name via the drop down menu. The selected option will persist and be used as the default setting for the next time the user opens the Export wizard.
Confirm selections

The Confirm selections screen is the third screen of the wizard. It displays information about the items that will be exported.

This screen consists of table columns:

Type - displays the component category type

Name - displays the component name

Label - displays any version labels added by the user from the Select Context screen

Revision - displays the revision(s) of the component to be exported

Export Job summary

The Export Job summary screen is the final screen of the wizard.

When the user click Finish, the Export job will be sent to the Job Submission Console for execution.
