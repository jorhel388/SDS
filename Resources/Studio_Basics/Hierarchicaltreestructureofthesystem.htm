Hierarchical tree structure

The Explorer window is housed in the Explorer area of the user interface. By default, on opening the software, the Explorer window will be displayed. If it is not open it can be opened from the Main menu bar. Once opened, it will display on the left hand side of the interface.

The Explorer window consists of a toolbar, the hierarchical tree structure area and the Explorer view bar.

The hierarchical tree structure area displays the following:

Repositories - used to hold and display a secure and persisted copy of the client’s system(s), which can be accessed and updated by the users of the studio applications. These users may be collaborating on changes to shared systems or may be working alongside each other in separate areas of a system (or on separate systems); the repository provides an archive and audit trail of changes made by these users during the lifetime of the systems. There are three types of repository, by default:

  • Content Repository
  • Reporting Repository
  • Solution Repository

Domains - may contain one or more domains, each of which can contain one or more solutions. User details and access permissions operate at repository level, and a user’s role-based permissions may therefore span domains within the repository, or be confined within a single domain, as required. Many clients, particularly those with only a single solution, or a small number of solutions, will generally have a single domain within their repository. For enterprise-level clients, or for Delivery Centres working on multiple solutions for many clients, the domain provides a useful mechanism for grouping sets of solutions that logically belong together (and conversely to separate/isolate them from other solutions/groups of solutions).

Solutions - is a level by which the contents of domains can be further divided. Solutions are held within a domain and the content of a solution can be viewed in the Explorer window.

Folders - used to provide an organisational structure for the components contained in a solution. Dependant on permissions, a user can view the contents of a folder, add a folder or delete a folder. Folders can contain many different types of components, however for ease of location it is recommended that they are used to group components of a similar type; for example, Segmentation devices, Decision components and Decision Process Flows etc Manage allowed component types - allows the user to determine which components should be held in which folders. Folders are stored in the Explorer window.

Components - is an entity within a solution that carries out a particular business function. Examples include Decision Process Flows, Scorecards, Logical Data Source etc. Each type of component has its own icon. Components are stored in folders within the Explorer window.

The text colours displayed in the hierarchical tree structure area of the Explorer window varies depending on where the item is located, refer to Explorer window topic for more information.
