Sanction or Reject a deployed label

When a label has been deployed initially, it is identified in the Label Management editor with the status of Pending . At this point, it is ready to be Sanctioned or Rejected.

  Deployed call interface and decision reason code table components do not need to be sanctioned; they are sanctioned automatically upon deployment.
 

 In order to be able to Sanction or Reject a label the user must have Sanction privileges assigned.

For more information see the topic Assign Custom Capability Permissions.

To Sanction a Pending label

  1. From the Label Management editor, right click on the pending label and select Sanction from the menu.
  2. The Sanction Deployment editor is displayed.
  3. Supply any notes to be included with the action, and check the tickbox to select the label to sanction.
  4. Click Sanction to deploy the label. The Status of the label deployment is changed to Sanctioned .

The Job Reference number is listed in the Label Deployment Output window. The progress of the deployment job can be viewed in the Job Submission Console.

The deployment job creates a deployment bundle .ser file, by default in the Job Server\Work folder, under a subfolder identified by the job reference number. You can also save the file directly from Job Submission Console to a location of your choice (see Display and save output files).

The deployment file will be marked as sanctioned and can be passed on for implementation in the acceptance/production environments.

To Reject a Pending label

  1. From the Label Management editor, right click on the pending label and select Reject from the menu.
  2. The Reject Deployment editor is displayed.
  3. Supply any notes to be included with the action, and check the tickbox to select the label to reject.
  4. Click Reject to reject the pending deployment. The Status of the label deployment is changed to Rejected .

By default, the live environment will only accept Sanctioned deployments.
