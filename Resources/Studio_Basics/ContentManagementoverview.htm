Content Management

Content Management enables the user to create templates (generic reusable content) which can be distributed to other users and can be used for other projects.

Overview

Template creation - a template is a reusable set of a component(s) and folder(s) that can be reused in a solution to speed up the solution build process. It can be created from one of - a component, folder or solution using the Save as template process.

A template will keep the internal relationships between components as well as the associated publishing rules and the allowed component types in the folders. It will contain all the information needed to recreate the folder structure. A folder or solution template does not need to contain components.

Template storage - a template is stored in the Content Repository and is indicated by a small overlay icon, added on top of the item being saved as a template. For example, when saving a Decision Process Flow as a template, the standard icon is , while the template icon looks like this .

In the Content Repository a template can be copied, renamed, marked as a favourite, locked/unlocked, exported/imported or moved to the Recycle Bin.

Template history details - every time a template has been updated, a new version of the template is saved in the history. Each saved version of the template is given a revision number. A template's history details can be viewed from the History window.

Template consumption - a template can be consumed either from the local Content Repository or from a remote repository using the Add from template process.

Once a template has been consumed, any saved template tracking information can be viewed using the Consumed Templates window. The tracking information links the template to the repository which was used to create it. From the Consumed Templates window the user can trigger actions, such as:

  • the Search for an update action - to search for a new version of the consumed component template(s)
  • the deletion of a configuration - opens the Confirm configuration deletion dialog, which allows the user to permanently delete the selected root template configuration
  • the Add latest template revision wizard - to consume the latest component template revision
  Special access permissions are required to create and consume templates.
  Components and folders within a template are identified with path names and unique component identifiers.
Save a component, folder or solution as a template

The Save <component, folder or solution> as template wizard is used to create or update an existing template. A template can be created from three different kinds of items - a component, folder or solution.

A template can be consumed either from the local Content Repository or from a remote repository using the Add from template process. For more information about templates, refer to the Content Management overview topic.

Templates and data models

When creating a template from a component, such as a scorecard, that is linked to a particular data model, that data model will be treated as a dependency of the scorecard. When the scorecard template is applied, the data model will be applied as well. The user must link to that exact data model, or the scorecard will not work; it is not simply the structure and attributes of the data model that are important, but the underlying identifications of the characteristics themselves.

If the exact data set already exists in the solution into which the template is being applied, the user can link to it.

  Note that all dependent logical data sources are stored in a template, not just the characteristics used by the components.
 

Before creating a template, ensure:

  • you have a security profile that includes a functional role assigned with the 'Content' and 'Solution' repository types, read access to the component and an architect (or design) licence
  • the Content Repository contains a loaded Content Solution
  • a target folder exists in the Content Solution that has the same allowed component type(s) as the selected component which will be used to create the template. In the case of a folder or solution template the user can configure 'Solution' as one of the allowed component types.
 

When creating a template from a folder, any component dependencies must be within the selected folder (or within its sub-folders), otherwise folder template creation will not be allowed. A message will be displayed if components from other folders are required.
Creating a component, folder or solution template

To create a template using the Save <component, folder or solution> as template wizard

  1. In the Explorer window, load a solution from the Content Repository.
  2. In the Solution Repository, right click on the component, folder or solution from which you want to create the template and select Save as template...
  3. The Select target screen is the first screen of the Save <component, folder or solution> as template wizard.
    4.  

    Any validation issues are displayed in the information area below the Name field. The Next button will only be activated once any issues have been resolved.
    1. In the Content Repository view, select the target folder in which to store the new template.
    2. Type the template name in the Name field.
    3. Click Next.
  4. The Configure options screen is the second screen of the wizard.
    1. Optionally, type the URL into the External Link (URL): field.
    1. Type the template description into the Template Description: field.
      2.   If the selected component only contains Logical Data Sources, Logical Data Models or Entity Models, the Retain unused characteristic(s) checkbox will be greyed out and set to checked.
     
    1. Optionally, to save all characteristics (used and unused in a Logical Data Source or a Logical Data Model) in the template, select the Retain unused characteristic(s) checkbox.
      2.  

      If the Save <component, folder or solution> as template wizard detects a component(s) in the selection that has not been checked in to the repository, the Enable template consumption tracking option will be deactivated.

      To enable the tracking option, ensure all changes are checked in prior to using the wizard. When the component(s) has been checked in, the tracking option will be activated by default.

      When the template has been consumed into a solution, its tracking information is used to evaluate the state of the template(s) and informs the user about any changes made to the template components.

    2. Optionally, if you do not want to save the tracking information, uncheck the Enable template consumption tracking checkbox. The tracking information links the template to the repository which was used to create it.
    3. Click Next.
  5. The Add notes step is the final screen of the wizard. It displays all components that are part of the template, including their Status, Version, Source Revision, etc.
    1. In the Notes column, click on a component cell. The Notes Editor is displayed.
    2. Type in a note. When the template has been consumed into a solution, the notes can be viewed using the Consumed Templates window.
    3. Click OK to save and then close the Notes Editor.
    4. Click Finish.
  1. Click OK to launch the Job Submission Console from the Remote Job Notification dialog.

Once the job has been successfully completed, the new template is displayed in the Explorer window, under the Content Repository.

Updating an existing component, folder or solution template

To update an existing template using the Save <component, folder or solution> as template wizard

  1. In the Explorer window, load a solution from the Content Repository.
  2. In the Solution Repository, right click on the component, folder or solution that you want to update and select Save as template...
  3. The Select target screen is the first screen of the Save <component, folder or solution> as template wizard.
    4.  

    Any validation issues that are found will be displayed in the information area below the Name field. The Next button will only be activated once any issues have been resolved.
    1. In the Content Repository view, navigate to and select the template that you want to update.
      2.  

      Any templates that have been moved into the Recycle Bin are indicated in red.
    1. Click Next.
  1. The Configure options screen is the second screen of the wizard.
    2.   The option fields will be populated with the values from the previous version of the template.
    1. Optionally, edit the URL in the External Link (URL): field.
    2. Optionally, edit the description in the Template Description: field.
      3.   If the selected component only contains Logical Data Models or Entity Models, the Retain unused characteristic(s) checkbox will be greyed out and set to checked.
    3. Optionally, to save all characteristics (used and unused in a Logical Data Source or a Logical Data Model), in the template, select the Retain unused characteristic(s) checkbox.
      4.  

      If the Save <component, folder or solution> as template wizard detects a component(s) in the selection that has not been checked in to the repository, the Enable template consumption tracking option will be deactivated.

      To enable the tracking option, ensure all changes are checked in prior to using the wizard. When the component(s) has been checked in, the tracking option will be activated by default.

      When the template has been consumed in a solution, its tracking information is used to evaluate the state of the template(s) and informs the user about any changes made to the template components.
    4. Optionally, if you do not want to save the tracking information, uncheck the Enable template consumption tracking checkbox and then check the agreement checkbox that is displayed.
    5. Click Next.
  1. The Add notes step is the final screen of the wizard. It displays all components that are part of the template that will be updated in the Save as template process, including their Status, Version, Source Revision, etc.
    2.   It is recommended to add notes to components that have been modified in the solution. Modified components are indicated with a Deleted or Updated status.
    1. In the Notes column, click on the cell of a modified component. The Notes Editor is displayed.
    1. Type in a note that describes the changes.
    2. Click OK to save and close the Notes Editor.
    3. Click Finish.
  1. Click OK to launch the Job Submission Console from the Remote Job Notification dialog.

Once the job has been successfully completed, the updated template is displayed in the Explorer window, under the Content Repository.

Add a template component from the local repository

The Add from local template wizard can be used to:

  • consume a component template into a local solution from the local Content Repository
  • update an existing solution using a new version of the consumed component template from the same repository

A template is used to create generic content that can be reused in a solution, speeding up the solution build process. Once a template has been consumed, any template tracking information (information that links the template to the repository which was used to create it) can be viewed using the Consumed Templates window.

For more information about templates, refer to the Content Management overview topic.

 

Before consuming a template, ensure:

  • you have a security profile that includes the Architect functional role
  • the target location (folder or solution) has the correct allowed component type(s) and the Recycle Bin is empty (to avoid any potential conflicts).
 

During the Add from template process, all component references will be properly retained depending on the conflict resolutions. However, this cannot be guaranteed for characteristic references, since characteristic references are not resolved by name in the Class Set, but by the ID of the characteristic. In this case, some manual steps are needed to resolve these validation errors, although the Class Set references the correct Logical Data Source (from the local system).

 

A consumed template will keep the internal relationships between the components, the associated publishing rules and the allowed component types.

Consuming a component template into an empty solution

To consume a component template into an empty solution using the original template structure from a local repository

  1. In the Explorer window, load the solution with the component template that you want to consume from the local Content Repository. In this example, the template has tracking information.
  2. From the Solution Repository, right click on the folder or solution into which you want to consume the component template, select Add from template and then Local repository...
  3. The Select template step is the first screen of the Add from local template wizard.
    1. Select the component template you want to consume.
    2. Click Next.
  4. The Configure options step is the second screen of the wizard.

    1. Optionally, select the version of the template you wish to consume via the drop down menu. By default, the latest version of the template will be selected

    2. Optional, if there is a URL displayed in the External Link (URL): field, to view the web page in your default browser, click Open.
    3. Click Next.
  5. The Configure targets step is the final screen of the wizard.
    6.  

    The Configuration name area will not be displayed if there is no template tracking information in the selected template.
     

    To collapse a folder structure, right click on the solution or folder and then select Collapse all. To expand a collapsed structure, right click on the solution or folder and then select Expand all.
    1. In the Configuration name field, enter the name of your current configuration. This configuration will be saved in the solution once the template has been consumed. Any saved configuration(s) can be reused when updating the same template in the same solution.
    2. Select the Use Original Template Structure checkbox. The component template will be consumed using the original template structure into the target location. It will include all the allowed component types and publishing rules from the template.
      3.   To view the content of a note attached to a component, select the component row that is displaying the Bold Notes icon. The note will be displayed in the Notes area below the table columns. Alternatively, the content of the note can be viewed using the tooltip.
    3. Click Finish.
  6. Click OK to launch the Job Submission Console from the Remote Job Notification dialog.

Once the job has been successfully completed, the content of the component template will be displayed in the Explorer window, under the Solution Repository. Any folders created by Consume Template Job are saved in the shared domain.

Updating a solution using a new version of the component template

To update an existing solution using a new version of the component template from a local repository

  1. In the Explorer window, load the solution with an updated version of the component template from the local Content Repository. In this example, the updated template has tracking information.
  2. From the Solution Repository, right click on the folder or solution into which you want to update with the new version of the component template, select Add from template and then Local repository...
  3. The Select template step is the first screen of the Add from local template wizard.
    1. Select the new version of the component template you want to consume.
    2. Click Next.
  4. The Configure options step is the second screen of the wizard.
    1. From the Select <template name> version drop down list, select the new version of the template (for example, 1.1).
    2. In the Template configuration area, ensure the previous configuration name is selected from the Reuse existing configuration drop down list.
      3.  

      The following areas will be disabled in the next screen (Configure target) of the wizard:

      • Configuration name
      • Original Template Structure.
    3. Optional, if there is a URL displayed in the External Link (URL): field, to view the web page in your default browser click Open.
    4. Click Next.
  5. The Configure targets step is the final screen of the wizard:
    6.  

    The Finish button will be disabled until all conflicts have been resolved. To avoid unnecessary work, before resolving any conflicts, check the conflict information using the tooltip. In the case when a conflict cannot be resolved using any of the conflict precedence options, it is recommended to close the wizard and resolve the conflict in the solution and then try again.
      
    1. If there are no conflicts between the template and referenced components, the Valid icon will be displayed in the Valid column (for all the items). Click Finish and proceed to step 6.
    2. If there are any unresolved conflicts between the template and referenced component, the Error icon will be displayed in the Valid column. To resolve a conflict, choose one of the precedence options from the Conflict Precedence drop down list.
      3.  Some error conflicts can be resolved by renaming the component template, right click on the component name cell and then select Name (or with the component name cell selected press F2).
       

      To view the content of a note attached to a component, select the component row that is displaying the Bold Notes icon. The note will be displayed in the Notes area below the table columns. Alternatively, the content of the note can also be viewed using the tooltip.

    3. Optional, to resolve all the conflicts at once using the same action, choose one of the precedence options from the Conflicts: Precedence area and then click Apply.
    4. Optional, if the updated component template contains a new component, you can change its target location using the Map <component> to Existing Folder dialog.
    5. Click Finish.
  6. Click OK to launch the Job Submission Console from the Remote Job Notification dialog.

Once the job has been successfully completed, the content of the updated component template will be displayed in the Explorer window, under the Solution Repository. Any folders created by the Consume Template Job are saved in the shared domain.

Consuming a folder or solution template into a target location

To consume a folder or solution template from a remote repository into a folder or solution

  1. In the Explorer window, load the solution with the folder or solution template that you want to consume from the local Content Repository. In this example, the template has tracking information.
  2. In the Solution Repository, right click on the folder or solution into which you want to consume the template (folder or solution), select Add from template and then Local repository...
  3. The Select template step is the first screen of the Add from local template wizard.
    1. Select the template (folder or solution) you want to consume.
    2. Click Next.
  4. The Configure options step is the second screen of the wizard.

    1. Optionally, select the version of the template you wish to consume via the drop down menu. By default, the latest version of the template will be selected.

    2. Optionally, if there is a URL displayed in the External Link (URL): field, to view the web page in your default browser, click Open.
    3. Click Next.
  5. The Configure targets step is the final screen of the wizard.
    6.  

    When consuming a folder or solution the following options are disabled by default:

    • Conflicts: Precedence
    • Original Template Structure.
     

    To collapse a folder structure, right click on the solution or folder and select Collapse all. To expand a collapsed structure, right click on the solution or folder and select Expand all.
    1. In the Configuration name field, enter the name of your current configuration. This configuration name will be saved in the solution once the template has been consumed. Its purpose is to allow you to differentiate between different consumptions of the same template in the same solution. It is displayed in the Consumed template window, under the Template Structure column. For example, <template name> (<configuration name>).
      2.  

      To view the content of a note attached to a component, select the component row that is displaying the Bold Notes icon. The note will be displayed in the Notes area below the table columns. Alternatively, the content of the note can be viewed using the tooltip.
    2. Click Finish.
  6. Click OK to launch the Job Submission Console from the Remote Job Notification dialog.

Once the job has been successfully completed, the content of the template (folder or solution) will be displayed in the Explorer window, under the Solution Repository. Any folders created by the Consume Template Job are saved in the shared domain.

Consuming a component template into an empty solution

To consume a component template using the original template structure from a remote repository into an empty solution

  1. In the Solution Repository, right click on the folder or solution into which you want to consume the component template, select Add from template and then Remote repository...
  2. The Login step is the first screen of the Add from remote template wizard.
    1. In the Connection description area (optional), enter a description that can be used to identify the remote repository. The description field is limited to 32 characters.
    2. In the URL details area.
      1. Optionally, to use a different communication protocol type (instead of the default HTTPS) use the drop down list.
      2. Enter the host address (it can be a DNS or IP address) in the Host: field.
      3. Enter the port number in the Port: field.
      4. Click Ping. If the repository is available, a green icon will be displayed next to the Ping button.
    3. In the User credentials area.
      1. Enter the remote user name in the User name: field.
      2. Enter the remote password in the Password: field.
        3.  

        The remote user account will be locked after three failed login attempts (default security setting of the remote user on the remote repository).

      1. Click Login. If the login has been successful, a green icon will be displayed next to the Login button. Both the Connection history drop down list and Ellipsis button will also be displayed. If the login has failed, refer to the warning message for more information (in red text).
      4.  

      Once you have logged in, the connection parameters will be saved in the user directory, except for the password. Saved connections can be reused when updating templates from the same repository.
    4. Click Next.
  3. The Select template step is the second screen of the wizard.
    1. Select the component template you want to consume.
    2. Click Next.
  4. The Configure options step is the third screen of the wizard.

    1. Optionally, select the version of the template you wish to consume via the drop down menu. By default, the latest version of the template will be selected.

    2. Optionally, if there is a URL displayed in the External Link (URL): field, to view the web page in your default browser, click Open.
    3. Click Next.
  5. The Configure targets step is the final screen of the wizard.
    6.  

    The Configuration name area will not be displayed if there is no template tracking information in the selected template.
     

    To collapse a folder structure, right click on the solution or folder and then select Collapse all. To expand a collapsed structure, right click on the solution or folder and then select Expand all.
    1. In the Configuration name field, enter the name of your current configuration. This configuration will be saved in the solution once the template has been consumed. Any saved configuration(s) can be reused when updating the same template in the same solution.
    2. Select the Use Original Template Structure checkbox. The component template will be consumed using the original template structure into the target location. It will include all the allowed component types and publishing rules from the template.
      3.   To view the content of a note attached to a component, select the component row that is displaying the Bold Notes icon. The note will be displayed in the Notes area below the table columns. Alternatively, the content of the note can also be viewed using the tooltip.
    3. Click Finish.
  6. Click OK to launch the Job Submission Console from the Remote Job Notification dialog.

Once the job has been successfully completed, the content of the component template will be displayed in the Explorer window, under the Solution Repository. Any folders created by Consume Template Job are saved in the shared domain.

    • Original Template Structure.
     

    To collapse a folder structure, right click on the solution or folder and select Collapse all. To expand a collapsed structure, right click on the solution or folder and select Expand all.
    1. In the Configuration name field, enter the name of your current configuration. This configuration name will be saved in the solution once the template has been consumed. Its purpose is to allow you to differentiate between different consumptions of the same template in the same solution. It is displayed in the Consumed template window, under the Template Structure column. For example, <template name> (<configuration name>).
      2.  

      To view the content of a note attached to a component, select the component row that is displaying the Bold Notes icon. The note will be displayed in the Notes area below the table columns. Alternatively, the content of the note can also be viewed using the tooltip.
    2. Click Finish.
  6. Click OK to launch the Job Submission Console from the Remote Job Notification dialog.

Once the job has been successfully completed, the content of the template (folder or solution) will be displayed in the Explorer window, under the Solution Repository. Any folders created by Consume Template Job are saved in the shared domain.

Update the latest component template revision

This topic provide details on how to use the Add latest template revision wizard to update an existing component that is part of a consumed template, with the latest revision of the same component from the local or from a remote Content Repository.

 

Before consuming the latest component template, ensure:

  • you have a security profile that includes the Architect functional role
  • the target location (folder or solution) has the correct allowed component type(s) and the Recycle Bin is empty (to avoid any potential conflicts).
 

During the Add from template process, all component references will be properly retained depending on conflict resolutions. However, this cannot be guaranteed for characteristic references, since characteristic references are not resolved by name in the Class Set, but by the ID of the characteristic. In this case, some manual steps are needed to resolve these validation errors, although the Class Set references the correct Logical Data Source (from the local system).

 

A consumed template will keep the internal relationships between the components, the associated publishing rules and the allowed component types.

Consuming the latest revision of a component template

To consume the latest revision of a component template into an existing solution

  1. In the Consumed Templates window, right click on a component template row that has a new revision (indicated in the Status column - New <version number> available), and then select Add to latest revision...
  2. The Add latest template revision wizard opens.
    3.  

    The Finish button will be disabled until all error conflicts have been resolved. To avoid unnecessary work, before resolving any conflicts check the conflict information using the tooltip. In the case when a conflict cannot be resolved using any of the conflict precedence options, it is recommended to close the wizard and resolve the conflict in the solution and then try again.
    1. If there are no conflicts between the template and referenced components, the Valid icon will be displayed in the Valid column (for all the items). Click Finish and proceed to step 3.
    2. If there are any unresolved error conflicts between the template and referenced component, the Error icon will be displayed in the Valid column. To resolve a conflict, choose one of the precedence options from the Conflict Precedence drop down list.
      3.   Some error conflicts can be resolved by renaming the template component. Right click on the component name cell and then select Name (or with the component name cell selected press F2).
       

      To view the content of a note attached to a component, select the component row that is displaying the Bold Notes icon. The note will be displayed in the Notes area below the table columns. Alternatively, the content of the note can be viewed using the tooltip.
    3. Optionally, to resolve all the conflicts at once using the same action, choose one of the precedence options from the Conflicts: Precedence area and then click Apply.
    4. Optionally, if the updated component template contains a new component, you can change its target location using the Map <component> to Existing Folder dialog.
    5. Click Finish.
  3. Click OK to launch the Job Submission Console from the Remote Job Notification dialog.

Once the job has been successfully completed, the content of the updated component template will be displayed in the Explorer window, under the Solution Repository. Any folders created by the Consume Template Job are saved in the shared domain.

Create and load an empty content solution

A user with Architect permission can create and load an empty content solution within which to create templates. To do so, the user might need to first create a domain within a repository. A solution can then be added.

To create and load an empty content solution

  1. In the Explorer window, right click on the appropriate repository.
  2. Select Connect.
     You can also double click on the name of the Repository to connect to it.

    The name of the Repository is displayed in blue to show that you are connected to it.

  3. Right click on the required content repository.
  4. Select New.
  5. In the New dialog, select Empty domain and click on the OK button.

    The new domain will be listed within the selected repository.

  6. Right click on the domain.
  7. Select New.
  8. In the New dialog, select Empty solution and click on the OK button.
  9. Select Add solution.
  10. In the Add solution dialog, type the name of the new solution.
  11. Click on the OK button.

    The solution will be added to the domain.

  12. Right click on the solution and select Load solution.
     You can also double click on the name of the solution to connect to it.

    You can now click on the icon to open the Solution.

You are now ready to use the content solution to create solution and folder templates. See Create content folders for more information on how to further configure the repository.
