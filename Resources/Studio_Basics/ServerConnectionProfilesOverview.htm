Server Connection Profiles Overview

The Server Connection Profiles enables the user to configure the SCL configuration parameters that are used in a REST component. The benefits of this feature are summarised below:

  This feature is an alternative to the SCL properties file. The point is you can completely ignore the SCL file in the Studio, and still be able to trigger a REST call.
  • Provides the user with an interface in the Studio to easily configure the SCL configuration parameters. This eliminates the dependencies on an administrator to make the changes in the file system.
  • Provides the user with the flexibility to create a REST enabled solution with separate configuration per Swagger component. This is important as it reduces the effort needed for the solution to support the execution of the same flow in different environments, for example the development, user acceptance test (UAT) and production environments.
 

Testing by using the Interactive Tester for the REST Call component is only supported when the Interactive Tester is invoked directly from the REST Call component or from the Decision Process Flow (DPF), which contains the REST Call component. The feature is backward compatible, which means that a user can still use the existing scl.cfg file implementation without any conflicts.

For more information about the scl.cfg file, refer to the Configuring the REST Call outbound section in the Business Process Server Configuration Guide.

There are two types of connection profiles available in the Server Connection Profiles, namely the Global Connection Profile and an Individual Connection Profile. The Global Connection Profile is automatically created by the Studio. A user can create a customised individual connection profile within the Server Connection Profiles and manage the keys of the connection profile by using the editor.

Global Connection Profile

The Global Connection Profile is automatically created by the Studio. It cannot be deleted, created or renamed. By default, the keys are created with blank values, and the user is allowed to modify the values of certain keys.

To edit the value of a key in the Global Connection Profile

  1. Right click on the Global Connection Profile and select Open to open the editor.

  2. Click on the value column that corresponds to the key that you want to modify and type the required value.

Global Connection Profile keys

The Global Connection Profile contains a fixed set of keys that are shared with each individual connection profile. The keys in the Global Connection Profile cannot be deleted and the user cannot add any new key into this profile. For more information about the configurable keys, refer to the Swagger Client Library (SCL) and Server Connection Profile Key Configuration topic.

Individual Connection Profile

A user is able to add as many individual connection profile as necessary in the Server Connection Profiles. Each profile is a custom connection configuration that allows a user to define the required parameters for specifying server connection details, credentials and appropriate authentication methods.

Modifications to the existing connection profile are allowed and the options are described in the table below.

Actions Descriptions
Open Select this option to open the individual connection profile in the editor.
Rename Select this option to rename an existing individual connection profile.
Delete Select this option to delete an existing individual connection profile.

To add an individual connection profile

  1. Right click on the Server Connection Profiles and select Add connection profile.

  2. Type the name of the individual connection profile, for example 'Connection Profile 03'. Click OK.
    Select the Open new connection profile in editor check box to open the newly created connection profile in the editor.

  3. Once an individual connection profile is created, the Studio adds the mandatory key 'scl.host' with blank value in the editor. The 'scl.host' is a mandatory key and its value must be populated.

There are two methods to populate the keys and values of an individual connection profile:

  • Use the actions provided in the Studio to add the keys manually.
  • Copy and paste the keys and values from an existing individual connection profile.

To add the keys manually

  1. Right click at the first entry (scl.host) and select Add

  2. Type or copy the key and value into the corresponding column.

  3. To add more keys and values, right click at the corresponding column and select Add.

    4. Below are descriptions of more actions that you can select to populate or amend the entries in the individual connection profile.

    Action Descriptions
    Delete Select this option at an existing key to delete the key and value row.
    Insert Before Select this option at an existing key to insert a new key and value row above the selected key.
    Insert After Select this option at an existing key to insert a new key and value row below the selected key.

To copy and paste from an existing connection profile

  1. Select all the rows from an existing connection profile.

  2. Select all the rows in the new connection profile.

    3.   Make sure that the number of rows in the new connection profile is configured to be the same as the existing connection profile.

  3. Press Ctrl+V at the keyboard to paste the content from the existing connection profile to the new connection profile.

The Connection Profile editor supports copying and pasting content from an editor table to the clipboard. This means existing keys and values can be stored in an Excel sheet and later copied into a new connection profile. The steps to copy and paste from an Excel sheet is the same as described above.

Individual Connection Profile keys

The keys and values in an individual connection profile are validated by the system and only valid keys and values are accepted. An invalid key or value is marked with the invalid icon. For more information about the configurable individual connection profile keys, refer to the Swagger Client Library (SCL) and Server Connection Profile Key Configuration topic.

Sample types of validation

The Server Connection Profiles editor provides validation of the keys and values added by a user. There are four types of validation as described below.

1. Key cannot be null or empty string

Upon inserting a new row, the key and value are defaulted to a blank string. These needs to be configured according to the meta data table.

Validation message displayed at the editor when an erroneous entry is made:

Row {0}: {1} is mandatory - The value cannot be blank

2. Key must be present in the meta data

Only keys listed in the meta data table above are allowed.

Validation message displayed at the editor when an erroneous entry is made:

Row {0}: Key {1} is invalid

3. Value must be valid value

The value is validated against the valid values regular expression listed in the meta data table above.

Validation message displayed at the editor when an erroneous entry is made:

Row {0}: Value {1} is invalid

4. No duplicate keys allowed

Each connection profile cannot have duplicate key.

Validation message displayed at the editor when an erroneous entry is made:

{0} The value is duplicated

5. Missing required property setting

Certain property needs another required property to be present.

Key {0} need scl.authentication.type. Value {1} is invalid

Associating a connection profile with a Swagger component

A REST component can use the connection profile after it is associated with a Swagger component. This feature introduces a new property in the Swagger component in its properties panel called connection profile.

The connection profile property is optional. If the property is not defined, the REST component will take the parameters from the existing scl.cfg file. This is to support backward compatibility for the existing solution.

The list will display all available individual connection profiles. When the Studio executes the REST component, the individual connection profile will be combined with the global connection profile.
