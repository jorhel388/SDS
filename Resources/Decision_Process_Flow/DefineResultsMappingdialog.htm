Define Results Mapping dialog

To configure a process or junction node in either the Decision Process Flow or Decision Process Sequence, the user needs to use the Define Results Mapping dialog to define where the output from each process and/or junction will be mapped. The type of process or junction added affects the mappings required since at runtime each process will generate different values.

Once a process has been added to a process node, or when a segmentation rule has been added to a junction, the user needs to right click on the node and select Results Mapping. The Define Results Mapping dialog will open. This dialog is divided into two areas:

  • Top area which contains the Results Mapping and Logical Data Sources areas
  • Bottom area which contains the Mapped Characteristics

In the top area of the Define Results Mapping dialog, the user can choose to select either the Generic or Custom button:

  • When the button is visible, the user is able to map one of the data models suggested by the system to the logical data sources.
  • When the button is visible, the user is able to individually map specific characteristics to individual characteristics that have been defined in the logical data source.
    •   Irrespective of what method is chosen the system will not allow the user to map characteristics twice or select to map an individual characteristic that has already been mapped.
  Dynamic arrays are not supported when the Decision Process Flow has been set to Originations Mode within the Properties window of the Decision Process Flow, see the Set the deployment mode of the Decision Process Flow topic for more information.

For more information see Generic Results Mapping, Custom Results Mapping and Mapped Characteristics.
