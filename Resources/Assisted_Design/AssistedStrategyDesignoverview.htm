Assisted Strategy Design

Assisted Strategy Design provides a controlled environment for the design, review and improvement of decisioning strategy trees, i.e. of segmentation and assignments.

Overview

Each Assisted Design Project centres around an Analysis Data Set that contains all characteristics used in the existing strategy, as well as one or more Target Characteristics, any number of Predictor Characteristics and other characteristics required for use in Measures. The Analysis Data Set is an embedded or by reference Input Data Connection.

In addition to the primary Analysis Data Set, the user can define an optional comparison data set. This enables the use of one data set to develop the segmentation and outcome assignment, for example, and another to validate the design. These can be physically distinct data files, or different sub-sets of the same physical data set as specified by a data set filter.

  Null values are not supported in the Assisted Design Project.

Measures based on key performance indicators, related to the Target Characteristic, Predictor Characteristics and other characteristics in the Analysis Data Set or generated as a result of strategy execution, can be included in the Assisted Design Project to help the user validate the strategy as well as to direct strategy design/tree growing.

Additionally, the user can create Impact measures to perform impact analysis and to drive the automatic assignment of best outcomes to strategy tree nodes.

Project Characteristics enable the user to create measures quickly and easily at the point they are required during the Assisted Design process - from within the Assisted Design Project Tree editor, the Measures sub editor, or the Outcome Assignment Parameters sub editor.

The user can perform Intelligent Tree Growing to grow and manipulate tree segments, using "Next Best Split Analysis" to interactively grow one level at a time from a given node, or "Grow" to automatically grow multiple levels from a given node (both approaches use CHAID.)

The user can then manually make assignments to resultant tree nodes, or use Propose Best Outcomes to automatically select outcomes that best satisfy the user's business goals and constraints.

The user can fine tune and test the resulting segmentation and assigned strategies before promoting the tree to the System Composition, for use in a decision process flow or in a 3rd party decisioning environment.

Build an Assisted Design Project

The Assisted Design Project can be created from an existing tree, from a tree in a Decision Process Flow and from the Explorer window

Create an Assisted Design Project from an existing tree

A new Assisted Design Project component can be created from an existing tree in the Explorer window.

To create an Assisted Design Project from an existing tree

  1. From the Explorer window, right click on an existing tree and select New Assisted Design Project.
  2. In the Create component dialog enter the name of the Assisted Design Project.
  3. Select the Open new components in component editor check box.
  4. Click OK.

The Assisted Design Project Tree editor will open allowing you to build the Assisted Design Project. The Assisted Design Project component name will be listed in the Explorer under the selected folder level.

If you do not want the Assisted Design Project to open, de-select the Open new components option. From the Explorer window, right click on the Assisted Design Project component and select Open. The structure of the tree in the Assisted Design Project will be identical to that of the original tree. The user will still need to select an analysis data set, map the characteristics, and specify the tree growing parameters.

  Until it has been promoted for use in the public domain, the tree created within the Assisted Design Project can not be used by other trees or components.

Add data weight to the Analysis Data Set (Optional)

Assisted Strategy Design typically operates on sampled data. To enable the data sets to be weighted up for review and analysis, a weight attribute or scaling factor can be assigned to the Data Set Weighting field in the Analysis Data Set.

The weight attribute shows how many observations a single record represents. For example, if one record represents 100 people, the weight attribute for this record is 100. The weight attribute is typically used in stratified sampling when each record can represent a different number of observations.

The scaling factor is the ratio between the total population and the sample size. For example, if 50 records represent a population of 10,000, the scaling factor is 200.

The weight attribute or scaling factor can be assigned to both the Primary Data Set as well as to the Comparison Data Set. The measure definition will not be affected by the weight attribute or scaling factor. However, the results displayed after a Review and Analysis job will incorporate the weight/scale to represent the weighted population.

  The Intelligent Tree Growing and Proposed Best Outcomes algorithms do not use data weighting.

To add data weighting to the Analytical Data Set

To add a scaling factor:

  1. With the Analytical Data Set editor open, type a numeric value into the Data Set Weighting field of the Primary Data Set.
  2. If required, repeat for the Comparison Data Set.
    3.   The scaling factor must be a positive integer.

The scaling factor will be used to weight up the data used for review and analysis.

To add a weight attribute:

  1. With the Analytical Data Set editor open, click on the Browse button next to the Data Set Weighting field of the Primary Data Set. The Select Characteristic dialog is displayed.
  2. In the Search field , type the word or part of a word that makes up the name of the characteristic.
    The Select Characteristic dialog will focus in on a particular characteristic or set of characteristics that match this word.
    3.   If the Select Characteristic dialog is displaying the characteristics in a tree view, the logical data source will need to be fully expanded to see all the characteristics that match the word(s).
     
  3. Select the characteristic you require.
  4. Click on the OK button.
  5. The Select Characteristic dialog closes and the characteristic you have selected is added to the Data Set Weighting field.
  6. If required, repeat for the Comparison Data Set.
    7.  The weight attribute field on your data set must be mapped to a numeric Logical Data Source characteristic within the relevant Input Data Connection.

The weight attribute will be used to weight up the data used for review and analysis.

To clear the weight attribute, right click on it and select Clear.

Create an embedded measure

Measures can be referenced from within the Assisted Design Project. This means they can be changed from outside the project and may be shared by other projects. Alternatively, a measure can be created from within the Measure sub editor and will be embedded into the Assisted Design Project. This means the measure is only used by this project and can only be edited from within this project.

  You can also create embedded measures using Project Characteristics at the point they are required during the Assisted Design process from within the Assisted Design Project Tree editor, the Measures sub editor, or the Outcome Assignment Parameters sub editor. See Create measures using Project Characteristics for details.

Create measures using Project Characteristics

Project Characteristics are available in the Resources window to enable the user to create embedded measures at the point they are required during the Assisted Design process - from within the Assisted Design Project Tree editor, the Measures sub editor, or the Outcome Assignment Parameters sub editor.

Measures can be created from one characteristic at a time; or (within the Assisted Design Project Tree editor and the Measures sub editor) measures can be created from multiple characteristics of the same type.

To create measures using a single Project Characteristic

  1. With the Assisted Design Project Tree editor, the Measures sub editor, or the Outcome Assignment Parameters sub editor open, drag and drop a characteristic from the list of Project Characteristics in the Resources window into the appropriate spot in the editor.

    For the Assisted Design Project Tree editor and the Measures sub editor, you can drop characteristics anywhere in the editor. For the Outcome Assignment Parameters sub editor, you can only drop characteristics into the Goal Measure field or a Constraint Definitions Measure field. See the different editors for details.

  2. The Create Measures dialog is displayed, with the name of the selected characteristic displayed.
  3. Select at least one measure type for the selected characteristic; the measure type for string characteristics is limited to Count. For each measure type selected, a different embedded measure will be created.
  4. The full characteristic name is displayed in the Suffix field; you can overwrite this default name with a shorter, more manageable name that will be used when the measure is displayed in the various editors.
  5. For Count measures only, you can enter values in the Value area of the dialog. Each value added will create a different embedded measure, with the value incorporated as a filter. Right click in the Value area to add a new row and enter a value.
    6.   The value(s) you enter should match the discrete values expected for the characteristic.

  6. For example, G and P are used here for the characteristic "Card Type":

  7. Click OK to save and close the dialog.

Specify the parameters for Propose Best Outcomes

To specify the parameters

  1. From the Navigator window, right click on Outcome Assignment Parameters and select Open Editor.
    The Outcome Assignment Parameters sub editor will open.
  2. In the Goal Name field specify a label for the goal (e.g., Minimise Expected Bad Debt).

  3. Specify the goal direction, either Maximise or Minimise

  4. From the Goal Measure drop down select the measure on which to base the goal (e.g., 'Total Expected Bad Debt').

  5. To create a goal measure from a Project Characteristic, drag and drop a Project Characteristic from the Resources window into the Goal Measure field. The Create Measure dialog is displayed. The only measure types allowed are Count and Sum. Once the measure has been created, it will appear in the drop down menu. See Create measures using Project Characteristics for more information.

  6. In the Constraints Definition area, in the first cell, specify a label for the constraint in the Name column.
  7. Click in the Measures cell and from the drop down list of measures select the measure for the constraint.
  8. In the Direction cell, select the constraint direction, either At Least or At most.
  9. Assign an impact script to the Outcome Impact Scripts field by dragging and dropping a Derived Data Script in the Resources window into the Impact Script field, or by right clicking and selecting Add Embedded Impact Script.

The parameters for the Outcome Assignment will be assigned.

Import a Strategy Tree to replace the existing tree scenario

The user can import a strategy tree into the Assisted Design Project to replace the existing tree scenario. This is useful, for example, when the user has created an Assisted Design Project from a template, and then imports a specific existing tree from the solution to make it the subject of the Assisted Design Project. This is also useful when the user wants to refresh an existing Assisted Design Project with a new copy of the original tree, as in cases where the operational tree has been modified since the Assisted Design Project was created.

To import a strategy tree to replace the existing tree scenario

  1. From the Assisted Design Project Tree editor, click on the Import an existing tree button .
  2. The Please select a tree dialog is displayed:

  3. Select an available tree and click on the OK button.

The tree segmentation in the Assisted Design Project is replaced by the imported tree segmentation. The outcomes of the imported strategy tree are merged with the outcomes from the existing Assisted Design Project tree scenario.

If the outcome assignments from the Assisted Design Project tree scenario are incompatible with those of the imported tree (e.g., a different Treatment Table Design or a different component type), only the outcome names are used and the assigned components are reset to undefined.

Duplicate outcomes are removed to preserve a single copy of each outcome (i.e., if the outcome name, outcome assignment type and assigned component name are the same).

Export Scenario Test Results

In Assisted Design, the user can test the tree scenario for a selected node or outcome and export the results data to a CSV file using the Export Scenario Test Results option. Export Scenario Test Results uses the primary analysis data set, and any defined filter and all the defined mappings in the associated Input Data Connection to run the test.

Test results can be specified using a Results Data Definition, which allows the user to define the set of input and results characteristics they want to export. The user can optionally include the results for any assigned impact scripts. Export Scenario Test Results can be selected from one of the following:

  • Assisted Design Project toolbar icon
  • Tree Node
  • Outcome Name
    •  

    When the Export Scenario Test Results option is selected, the following files are created:

    • results.txt
    • output.csv

    The results.txt will always contain the full set of results rather than a "filtered" set determined by the level of the scenario, e.g. full tree or outcome. The output.csv will contain "filtered" results.

      If you define data weighting in the Analysis Data Set, it will not impact the test results.

Assisted Design Project tool bar icon

Selecting the Export Scenario Test Results icon will execute the test for the entire tree and create an output.csv file containing the records that have passed through the full tree.

Tree Node

Selecting Export Scenario Test Results from any node in the tree will create an output.csv file that only contains the number of records that have passed through to a specific node.

Outcome Name

  This option will only be available when the measures have been calculated for each outcome in the Outcomes area using the Show Measures button.

  5. Click on the OK button.
  6. The new tree will open, but will also be listed in the Explorer under the same folder as the Assisted Design Project.

The new tree can now be used within other components.

Support for multi-process trees within Assisted Strategy Design

It is possible to create and maintain Assisted Strategy Design projects based on multi-process trees (known as Decision Process Trees). This means that Business Objective flows and trees can be imported from SMG3 into Strategy Manager, and Assisted Strategy Design can be used to validate the accuracy of the conversion by calculation of key measures against trees. Assisted Strategy Design projects based on multi-process trees behave consistently with Assisted Strategy Design projects based on any other types of trees.

See the SMG3 File Import help for more information about the conversion of Business Objective Flows to Decision Process Flows.
