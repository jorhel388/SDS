Supplementary Features

This area of the help lists those supplementary features that are used throughout your solution.

Logical Data

Characteristics are used to describe and reference the data used in the software and are grouped by Logical Data Sources and/or Logical Data Models.

Logical Data Source overview

Logical Data Model overview

Semi Structured Data Definition

The Semi Structured Data Definition component uses a loaded JSON schema to generate Logical Data Models of all or a subset of the contents of the selected JSON file. These Logical Data Models can then be used within other Design Studio components as normal depending on publishing rules.

  Although available for selection in all PowerCurve products, the Semi Structured Data Definition component is only supported in PowerCurve Strategy Management and PowerCurve Originations.

Physical Data Models

Physical Data Models represent physical specifications of Logical Data Models for a particular interface type. The Decision Agent interfaces currently can use two types; these are Java Byte and Java Object. The type of interface which a Physical Data Model is intended to represent determines the precise set of physical properties of the data for that environment for that model.

Annotation Model

The Annotation Model enables users to map Annotation Templates from a specific Annotation Set to characteristics to create annotations. One System Annotation Set exists in Strategy Management:

  • Data Observation

Data Structure

The Data Structure area contains those components that are used to create the structure of the operational database from the Logical Data.

Scripting

A common scripting language within the Studio enables a business user to construct simple or complex derivations. Any data generation, calculation or redefinition can be done using the Derived Data Script component with conditional statements and looping capabilities.

User Defined Functions allow a user to create a reusable script or function and choose it from the Resources window when needed. They can be used within Derived Data Scripts or other User Defined Functions.

Segmentation

The Studio's segmentation devices are used to group people together.

There are four methods of segmenting your applicants/customers. A single characteristic can be:

  • used to create a boolean expression resulting in a 'true' or 'false' result - Boolean Expression
  • classed into intervals - Class Set
  • combined with another characteristic to enable outcomes to be assigned to individual cells - Matrix
  • finally all three of these methods in any permutation can be combined - Segmentation Tree

  • segmented to use a sample population to which a 'control' group is applied or an alternative treatment is applied -

    Test Group Set
